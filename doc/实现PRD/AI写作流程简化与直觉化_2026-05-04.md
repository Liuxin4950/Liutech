## 1. 需求摘要

- 用户目标：管理员发送消息后 AI 直接写入表单字段，不需要手动"应用"；不满意可回退。
- 必须实现：AI 直接写入字段、底部回退栏、DOMPurify 消毒、合并后端接口。
- 本次不做：合并前端 UI（Admin 和 Web 布局不同）、普通聊天改动、多轮上下文。
- 关键验收标准：AI 写入后表单直接生效，无草稿卡片无应用按钮；回退可恢复单字段。

## 4. 总体实现方案

```text
用户输入 → 前端发送到 /ai/agent/stream（带 draft 上下文）
  → 后端意图分类（管理员 + 有 draft → 自动识别为写作）
  → AgentOrchestrator 生成 HTML + 匹配分类标签
  → SSE 发送 field-update 事件（只包含被修改的字段）
  → 前端接收 field-update，直接写入表单
  → 前端保存旧值到回退栈
  → 底部悬浮栏显示可回退的字段列表
```

关键设计取舍：

- 方案 A：保留 `WritingDraftPayload` 但前端直接应用（不展示草稿卡片）。
- 方案 B：改为 `FieldUpdatePayload`，只传被修改的字段，前端按字段写入。
- 选择：方案 B。原因：更清晰地表达"AI 只改了哪些字段"，回退粒度更细。

## 5. 后端实现方案

### 5.1 API 设计

合并后只有一个写作入口：

| 方法 | 路径 | 权限 | 请求 | 响应 | 说明 |
| --- | --- | --- | --- | --- | --- |
| POST | /ai/agent/stream | JWT | AgentChatRequest | SSE stream | 统一入口，管理员写作和普通聊天 |
| POST | /ai/agent/chat | JWT | AgentChatRequest | AgentChatResponse | 统一同步入口 |

管理员写作时，前端在 `context` 中传 `{ page: "admin-post-editor", postId: ... }`，后端根据 context 判断是否为写作场景。

### 5.2 Controller 层

- 删除：`AdminAgentChatController.java`
- 修改：`AgentChatController.java` — 统一处理所有请求
- 权限：写作操作（WRITE_ARTICLE、CREATE_DRAFT、PUBLISH_POST、OFFLINE_POST）在 `executeTask` 内部已检查 `user.isAdmin()`，无需顶层守卫

### 5.3 Service 层

修改 `AgentOrchestrator.java`：

- 删除 `executeAdmin()`、`executeAdminStream()` 方法
- `executeStream()` 统一入口：如果 `context.page == "admin-post-editor"`，自动使用 WRITE_ARTICLE 意图
- `handleWritingAssist()` 改为构建 `FieldUpdatePayload`（只包含被修改的字段）而非 `WritingDraftPayload`
- `buildWritingDraft()` 保留核心逻辑（读分类、读标签、生成 HTML），但输出改为 `FieldUpdatePayload`

新增 `FieldUpdatePayload.java`：

```java
@Data @Builder
public class FieldUpdatePayload {
    private String title;           // null 表示不修改
    private String summary;         // null 表示不修改
    private String contentHtml;     // null 表示不修改
    private Long categoryId;        // null 表示不修改
    private String categoryName;
    private List<Long> tagIds;      // null 表示不修改
    private List<String> tagNames;
    private String suggestedCategoryName;
    private List<String> suggestedTagNames;
}
```

SSE 事件：将 `writing-draft` 改为 `field-update`，payload 为 `FieldUpdatePayload`。

### 5.4 Mapper / 数据访问

无变化。

### 5.5 鉴权与权限

- `/ai/agent/stream` 和 `/ai/agent/chat` 保持现有 JWT 认证。
- 写作相关意图（WRITE_ARTICLE、CREATE_DRAFT、PUBLISH_POST、OFFLINE_POST）在 `executeTask` 内部检查 `user.isAdmin()`。
- 普通用户发消息走意图分类器，不会触发写作流程。

## 6. 前端实现方案

### 6.1 页面与路由

- Admin：`PostsManagement.vue` 文章编辑弹窗，侧边栏改为直接写入模式。
- Web：`CreatePost.vue` 创建文章页，写作助手改为直接写入模式。
- 路由无变化。

### 6.2 组件与状态

**AdminAgentSidebar.vue 改造：**

- 移除：草稿卡片（`writingDraft`）、应用按钮（"应用全部"、"标题"、"摘要"等）、`applyWritingDraft` 方法。
- 新增：监听 `field-update` SSE 事件，接收 `FieldUpdatePayload`。
- 新增：收到 `field-update` 后，emit `field-update` 事件给父组件，附带 payload。
- 保留：执行过程可视化（plan steps、tool events）、快捷提示词、输入框。

**PostsManagement.vue 改造：**

- 移除：`handleAgentApplyDraft` 方法。
- 新增：`handleFieldUpdate(payload)` 方法 — 直接写入表单字段，同时保存旧值到回退栈。
- 新增：`undoStack` ref — 记录每次 AI 修改的字段和旧值：`{ field: string, oldValue: any }[]`。
- 新增：底部悬浮回退栏 — 显示可回退的字段列表，点击回退某个字段。
- DOMPurify：`contentHtml` 写入前消毒。

**AdminWritingAssistant.vue 改造：** 同 AdminAgentSidebar 的改造思路。

**CreatePost.vue 改造：** 同 PostsManagement 的改造思路。

### 6.3 API 调用

- Admin：`AgentService.stream()` 改为调用 `/ai/agent/stream`（移除 `/ai/admin/agent/stream`）。
- Web：`AdminAgentService.stream()` 同上。
- 请求体：`context: { page: "admin-post-editor", postId: ... }` 保持不变，后端通过 context 判断写作场景。

### 6.4 交互细节

- AI 写入字段后，字段区域短暂高亮 2 秒（绿色边框动画）。
- 底部悬浮栏：半透明背景，固定在页面底部，显示"回退：标题 | 摘要 | 正文 | 分类标签"等可点击项。
- 每个字段只能回退一次（回退后从悬浮栏移除）。
- 新的 AI 写入会清空之前的回退栈（每次 AI 操作是独立的快照）。

本次不涉及数据库结构变化，原因：只改变 AI 写作的交互方式，不改变数据存储。

## 8. 接口与数据流

| 数据 | 来源 | 处理层 | 存储/输出 | 备注 |
| --- | --- | --- | --- | --- |
| 用户消息 | 前端输入框 | Controller → Orchestrator | AgentTask DB | 不可信，需校验 |
| 当前文章快照 | 前端 form state | request.draft | 传入 prompt | 不可信，仅作上下文 |
| 分类列表 | 主后端 Admin API | AdminBlogClient | 匹配用 | 内部调用，可信 |
| 标签列表 | 主后端 Admin API | AdminBlogClient | 匹配用 | 内部调用，可信 |
| AI 生成 HTML | SiliconFlow API | chatForWriting | FieldUpdatePayload | 不可信，需 DOMPurify |
| 分类标签匹配 | Java 代码 | matchTaxonomy | FieldUpdatePayload | 确定性逻辑 |
| field-update 事件 | 后端 SSE | AgentStreamPublisher | 前端接收 | 通过 envelope 格式 |
| 表单字段更新 | 前端 | handleFieldUpdate | formModel/form ref | DOMPurify 后写入 |

## 9. 安全影响

- 认证与授权：沿用现有 JWT + ROLE_ADMIN 检查，无变化。
- XSS：AI 生成的 HTML 通过 DOMPurify 消毒后写入，与当前行为一致。
- 输入校验：`AgentChatRequest.message` 有 `@NotBlank` 和 `@Size(max=4000)` 校验。
- 敏感信息：AI prompt 中包含当前草稿内容，但不包含密码/token。

安全风险等级：低。与当前写作助手安全等级一致。

## 10. 性能影响

- AI 生成耗时：取决于模型响应速度，与当前一致。chatForWriting 使用流式调用，不会超时。
- 前端包体积：移除草稿卡片和应用按钮的代码，略微减小。
- 回退栈：内存中存储最近一次 AI 修改的旧值，开销可忽略。

性能风险等级：低。
