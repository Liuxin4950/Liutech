## 1. 需求摘要

- 用户目标：让纳西妲的身份、能力、权限边界和调用路径稳定统一，避免 Agent 路径、旧聊天路径和前端模式继续漂移。
- 必须实现：统一系统提示词来源；明确 legacy 路径；Web/Admin 看板娘主路径走 Agent；访客、普通用户、管理员能力边界可测试；管理员写操作继续确认，首次生成文章只进草稿；本期禁止删除、用户管理、自然语言模型配置管理。
- 本次不做：不删除旧接口、不引入 Python/LangChain、不重做 UI、不重做推荐排序、不改变数据库结构。
- 关键验收：Agent 与 legacy 文本生成使用同一人格/安全/能力规则；旧路径被代码和文档标识为 legacy；完整响应不绕过 Agent；删除和越权管理动作不可生成。

## 4. 总体实现方案

整体路线：在 AI 服务新增统一系统提示词组件，旧聊天和 Agent 都通过它获取完整人格、安全和能力边界；旧路径不删除，但在代码、响应头和文档中标记为 legacy；前端保留 `agentEnabled === false` 内部回退，但正常聊天状态继续强制 Agent。

```text
Web/Admin
-> /ai/agent/stream 或 /ai/agent/chat
-> AgentOrchestrator
-> AiSystemPromptProvider 组装人格 + 安全 + 能力边界
-> 模型生成 / 工具执行 / 结构化事件
```

关键设计取舍：

- 方案 A：直接让 Agent 注入 `AiPromptConfig` 并手动拼提示词。
- 方案 B：新增 `AiSystemPromptProvider`，旧聊天和 Agent 都复用。
- 选择：方案 B。
- 原因：能力边界会继续扩展，集中 Provider 更利于测试和长期维护。

## 8. 接口与数据流

| 数据 | 来源 | 处理层 | 存储/输出 | 备注 |
| --- | --- | --- | --- | --- |
| 系统提示词 | `application.yml` + 安全策略 | `AiSystemPromptProvider` | 模型 SystemMessage | 统一人格和能力边界。 |
| 用户身份 | JWT / 主后端回查 | `AgentUserContextResolver` / `AiCapabilityResolver` | Agent 响应与权限策略 | 不信任用户自称。 |
| 管理动作 | 用户输入 + 当前文章上下文 | `AgentOrchestrator` / `AgentActionService` | pending action | 管理员确认前不执行。 |
| legacy 请求 | 旧前端或调试调用 | legacy Controller | legacy 响应头 | 不承接新功能。 |

- 用户输入是否可信：不可信。
- 后端是否二次校验：是，身份、工具权限和 action 确认均由后端校验。
- 返回字段是否包含敏感信息：不应包含 token、密钥、系统提示词。
- 前端是否可能缓存敏感数据：不新增缓存。

## 9. 安全影响

- 认证与授权：不改变认证机制；强化模型提示词和工具策略的一致性。
- 输入校验：不新增外部输入结构。
- XSS：无新增 HTML 渲染。
- SQL 注入：无 SQL 变化。
- 文件上传/下载：无影响。
- SSRF：无新增外部 URL 调用。
- CSRF：沿用 Bearer Token 策略。
- 敏感信息日志：legacy 标识和提示词 Provider 不记录敏感内容。
- Token / Cookie / localStorage 风险：无变化。

结论：

```text
安全风险等级：中
必须修复项：Agent 文本生成必须复用统一系统提示词；legacy 路径必须被显式标识；禁止能力必须写入统一边界。
可接受风险：旧接口暂时仍公开可用，但不作为主路径。
```
