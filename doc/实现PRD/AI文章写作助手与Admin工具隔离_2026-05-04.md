## 1. 需求摘要

- 用户目标：让纳西妲成为管理员文章写作助手，从一句自然语言生成可应用到编辑器的结构化富文本文章草稿。
- 必须实现：管理员 AI 接口隔离、结构化写作草稿、HTML 输出规范、Web/Admin 双入口、分类标签快捷创建、SSE 进度统一、发布确认。
- 本次不做：删除文章、管理用户/角色、SQL/Shell、自动绕过编辑器发布、自动生成并上传封面图。
- 关键验收标准：管理员可一键应用 AI 生成的标题、摘要、HTML 正文、分类、标签；普通用户无法调用管理员写作接口。

## 4. 总体实现方案

整体路线：保留公共 `/ai/agent/**` 只读 Agent 能力；新增管理员专用 `/ai/admin/agent/**` 写作入口，复用 Agent 编排但强制 admin 上下文和写作模式。AI 生成结构化 `writing-draft` 事件，前端侧边栏接收后以“写作产物”展示，并提供一键应用到 TinyMCE 表单和分类标签字段。所有写操作继续走待确认或用户显式点击。

```text
管理员页面 -> 写作侧边栏 -> /ai/admin/agent/stream
-> AI 服务鉴权 ROLE_ADMIN
-> AgentOrchestrator 写作模式
-> 分类/标签读取与匹配工具
-> 模型生成结构化 HTML 草稿
-> writing-draft / agent-plan / tool-* SSE
-> 前端预览与一键应用
-> 用户保存草稿或确认发布
```

关键设计取舍：

- 方案 A：继续使用公共 `/ai/agent/stream`，只靠工具权限拦截。
- 方案 B：新增 `/ai/admin/agent/stream`，公共 Agent 保持只读，管理员写作单独鉴权。
- 选择：方案 B。
- 原因：权限边界更清晰，避免普通用户通过 prompt 或前端绕过误触管理员工具。

## 5. 后端实现方案

### 5.1 API 设计

| 方法 | 路径 | 权限 | 请求 | 响应 | 说明 |
| --- | --- | --- | --- | --- | --- |
| POST | `/ai/admin/agent/chat` | ROLE_ADMIN | `AgentChatRequest` | `AgentChatResponse` | 管理员非流式写作助手 |
| POST | `/ai/admin/agent/stream` | ROLE_ADMIN | `AgentChatRequest` | SSE | 管理员流式写作助手主入口 |
| POST | `/ai/admin/agent/actions/{actionId}/confirm` | ROLE_ADMIN | `AgentActionConfirmRequest` | `AgentActionResultResponse` | 管理员确认写操作，可兼容旧 confirm |

新增 SSE 事件：

| 事件 | Payload | 说明 |
| --- | --- | --- |
| `writing-draft` | `WritingDraftPayload` | 标题、摘要、HTML 正文、分类/标签建议、封面提示词、检查结果 |
| `writing-check` | `WritingCheckPayload` | 发布前检查结果，可合并到 `writing-draft` 的检查字段 |

### 5.2 Controller 层

- 新增文件：`LiuTech-AI/src/main/java/chat/liuxin/ai/agent/controller/AdminAgentChatController.java`
- 职责：暴露 `/ai/admin/agent/chat` 和 `/ai/admin/agent/stream`。
- 参数校验：沿用 `@Valid AgentChatRequest`。
- 错误响应：未登录/非管理员由 Spring Security 返回 401/403；执行错误通过 SSE `error` envelope 返回。

可选新增：

- `AdminAgentActionController`，或在现有 `AgentActionController` 增加 `/ai/admin/agent/actions/**` 映射。

### 5.3 Service 层

新增/修改文件：

- `AgentOrchestrator.java`
- `AgentPlanService.java`
- `AgentStreamPublisher.java`
- 新增 `WritingDraftPayload.java`
- 新增 `WritingDraftParser` 或 `WritingDraftService`
- 可选新增 `AdminTaxonomyTool.java`

核心业务流程：

1. 管理员写作请求进入 admin Agent 路径。
2. 后端确认 `AgentUserContext.isAdmin()`，非管理员直接拒绝。
3. 根据意图区分从零写作、润色、格式整理、SEO、续写、发布前检查等写作动作。
4. 读取当前草稿上下文，必要时读取当前文章详情。
5. 查询分类/标签列表，用于匹配已有项。
6. 构造严格提示词，要求模型只输出 JSON 或可解析结构，正文为 TinyMCE HTML。
7. 解析生成结果，生成 `WritingDraftPayload`。
8. SSE 发送 `writing-draft`，并补充 `data` 文本摘要。
9. 若请求是创建草稿或发布，仍生成 `confirmation-required`。

事务边界：AI 服务不直接管理主库事务；创建草稿、发布、分类/标签创建仍通过主后端接口完成。

幂等性：AI 生成和应用到前端不产生写入；确认动作沿用 actionId 和 pending action 状态防重复执行。

异常处理：模型输出无法解析时返回可读错误；分类/标签查询失败时降级为名称建议；HTML 不合规时标记 blocked。

### 5.4 Mapper / 数据访问

- 不新增 mapper。
- 继续使用 `ai_agent_task`、`ai_agent_action`、`ai_agent_tool_call` 记录任务、确认动作和工具调用。
- 无 SQL 变化。

### 5.5 鉴权与权限

- 管理员写作接口必须匹配 `/ai/admin/agent/**`，由 `SecurityConfig` 的 `/admin/**`、`/ai/admin/**` 规则保护。
- 公共 `/ai/agent/**` 保留匿名/普通只读能力，但写操作不应通过公共入口创建。
- `AiToolAccessPolicy` 保持服务端兜底，创建草稿、发布、下架、创建分类/标签必须要求 admin。
- 前端展示条件不能作为安全依据，仅作为体验优化。

## 8. 接口与数据流

| 数据 | 来源 | 处理层 | 存储/输出 | 备注 |
| --- | --- | --- | --- | --- |
| 写作需求 | 管理员输入 | AI 服务提示词包装 | 模型输入 | 不可信 |
| 当前草稿 | Web/Admin 表单 | AI 服务截断和包装 | 模型输入 | 不可信 HTML |
| 分类/标签列表 | 主后端接口 | AI 工具匹配 | `writing-draft` | 只暴露必要名称/ID |
| HTML 正文 | 模型输出 | 解析、校验、前端消毒 | TinyMCE 表单 | 不直接发布 |
| 待创建分类/标签 | 模型建议 | 前端确认 | 主后端写入 | 必须 admin |
| 发布动作 | 管理员确认 | AgentActionService | 主后端发布接口 | 保持二次确认 |

需要特别标注：

- 用户输入是否可信：不可信。
- 后端是否二次校验：是，权限和 action 确认必须服务端校验。
- 返回字段是否包含敏感信息：不应包含 token、系统提示词、内部工具规则。
- 前端是否可能缓存敏感数据：只保存在当前页面状态，不写 localStorage。

## 9. 安全影响

- 认证与授权：新增 admin endpoint，强制 ROLE_ADMIN。
- 输入校验：限制标题、摘要、正文长度，模型输出解析失败不应用。
- XSS：HTML 必须经过 DOMPurify；提示词禁止 script、iframe、事件属性。
- SQL 注入：不直接拼 SQL；分类标签通过主后端 service。
- 文件上传/下载：本次不自动上传封面图。
- SSRF：不让 AI 拉取任意 URL。
- CSRF：沿用 Bearer token；不引入 cookie credentials 写操作。
- 敏感信息日志：工具输入摘要不得记录 token 和完整正文。
- Token / localStorage 风险：前端只用现有 token 发请求，不注入模型。

结论：

```text
安全风险等级：高
必须修复项：管理员 AI 接口隔离、HTML 消毒、写操作确认、普通用户不可触达 admin 工具。
可接受风险：AI 内容质量需人工审查；模型输出解析失败可重试。
```

## 10. 性能影响

- 列表分页：分类/标签列表可限制数量或复用已有 1000 条加载策略。
- 数据库索引：无新增。
- N+1 查询：分类/标签一次性读取，避免每个标签单独查。
- 大对象传输：草稿正文限制截断长度，模型输出正文受现有 50000 字限制。
- 缓存策略：分类/标签可短期前端缓存，AI 工具可不新增缓存。
- 线程池 / 连接池：SSE 仍异步执行，沿用超时。
- 前端包体积：新增组件会增加少量体积，不引入大型库。
- 首屏加载：Web 创建页可懒加载写作助手。

结论：

```text
性能风险等级：中
预估瓶颈：长文生成 token 成本和 SSE 持续时间。
缓解方案：正文上下文截断、输出长度限制、明确失败和重试。
```
