# 项目问题排查修复架构记录

## 背景

本次排查发现多个隐藏问题集中在安全边界和部署配置漂移：密钥入库、管理员接口只认证不鉴权、付费资源静态直通、部署脚本证书挂载路径与 Nginx 配置不一致。

## 架构调整

### 配置与密钥

- 仓库只保留 `.env.example`，真实 `.env` 不再被 Git 跟踪。
- `DB_PASSWORD`、`JWT_SECRET`、`SPRING_AI_OPENAI_API_KEY` 不再在 Spring 配置、Compose 或部署脚本中提供真实默认值。
- Docker Compose 使用必填环境变量表达式要求关键配置显式注入。
- Windows 本地开发通过 `scripts/run-backend-dev.ps1`、`scripts/run-ai-dev.ps1` 加载根目录 `.env` 后启动服务。

### 权限边界

- 主后端与 AI 服务的 `/admin/**` 都要求 `ROLE_ADMIN`。
- Admin 前端路由层同步要求登录用户角色为 `admin`，避免普通用户进入管理 UI 壳层。

### 付费资源访问

- 文章详情接口对未购买的付费附件只返回展示所需的基础信息，不返回文件 URL、外部链接和购买后说明。
- `/uploads/resources/**` 不再作为公开静态资源访问入口。
- 资源下载统一走 `/resource/download/{resourceId}`，由业务服务做购买校验、路径解析和目录边界校验。

### 部署入口

- Admin 容器直连入口的 `/ai/` 代理与根 Nginx 保持一致，去掉转发到 AI 服务时的多余 `/ai` 前缀。
- 服务器部署脚本生成的 Compose 将证书目录挂载到 `/etc/nginx/ssl`，与 Nginx 配置中的证书读取路径一致。
- `/api/` 使用 Bearer Token，不依赖 cookie credentials；Nginx 不再为通配来源添加 credentials 响应头。

## 影响范围

- 本地直接运行后端服务时，需要先准备 `.env` 或通过环境变量传入配置。
- 已购买资源下载路径不变，仍通过 `/resource/download/{id}` 获取文件。
- 曾经依赖 `/uploads/resources/**` 直连资源文件的访问方式会被拒绝，应改用资源下载接口。

## 后续建议

- 拆分本地和生产 Nginx 配置，避免本地无证书时 HTTPS server 阻塞启动。
- 统一 Nginx 与 Spring CORS 策略。
- 对历史 Git 提交做密钥轮换和必要的历史清理评估。
