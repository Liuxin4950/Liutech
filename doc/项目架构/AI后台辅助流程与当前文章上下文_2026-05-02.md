## 1. 本次变更概览

- 变更目标：让 Agent 能围绕“当前文章”工作，并把执行过程展示给用户。
- 核心能力：写作辅助与创建草稿分流、当前文章详情读取、当前文章总结、相关文章推荐、前端 plan/tool 展示、确认后表单状态同步。
- 影响范围：AI 服务 Agent 编排和公开文章工具、Web 聊天消息渲染、Admin 文章编辑器 Agent 侧边栏。
- 不影响范围：数据库表结构、Nginx、Docker、模型配置、删除能力。

## 2. 影响的系统模块

| `Admin` | 是 | 文章编辑器 Agent 侧边栏展示工具过程并同步确认结果。 |

## 4. 核心类、组件与职责变化

- 接口入口：仍使用 `/ai/agent/stream` 和 `/ai/agent/chat`，无新增公开路径。
- 业务服务：`AgentOrchestrator` 将 `WRITE_ARTICLE` 与 `CREATE_DRAFT` 分离；`SUMMARIZE` 和相关推荐可读取当前文章。
- 数据访问：不新增 Mapper，工具调用通过 `BlogApiClient.getPostDetail` 访问主后端。
- 前端页面 / 客户端：Web `chat.ts` 消费 `agent-start`、`agent-plan`、`tool-start`、`tool-result`、`confirmation-required`。
- 可复用组件：Web `AiChatBody` 和 Admin `AdminAgentSidebar` 都渲染 plan/tool 过程。
- API 调用层：Admin `AgentService` 继续解析统一 SSE envelope。
- 状态管理 / 缓存：公开文章搜索/推荐缓存保持不变，当前详情读取不额外缓存。

## 5. 接口与调用链路变化

```text
当前文章总结：
Web PostDetail -> buildChatContext(postId) -> /ai/agent/stream
-> AgentOrchestrator(SUMMARIZE) -> PublicArticleTool.getArticleDetail
-> BlogApiClient /posts/{id} -> 模型总结 -> data + article-results -> Web 渲染

后台写作辅助：
Admin PostsManagement -> AdminAgentSidebar(draft snapshot) -> /ai/agent/stream
-> AgentOrchestrator(WRITE_ARTICLE) -> 生成写作辅助文本 -> Admin 展示/应用

后台发布：
AdminAgentSidebar -> AgentOrchestrator(PUBLISH_POST) -> confirmation-required
-> /ai/agent/actions/{id}/confirm -> AdminBlogClient /admin/posts/{id}/publish
-> Admin 表单状态同步
```

新增或调整的接口：

| 方法 | 路径 | 调用方 | 鉴权 | 说明 |
| --- | --- | --- | --- | --- |
| 无新增 | 复用 `/ai/agent/stream` | Web/Admin | 可匿名，写操作需管理员 | 新增事件消费与后端分流逻辑。 |
| 无新增 | 复用 `/posts/{id}` | AI 服务 | 公开接口 | 读取当前文章详情用于总结。 |
| 无新增 | 复用 `/admin/posts/{id}/publish` | AI 服务 | 管理员 token | 确认后发布文章。 |

## 6. 数据模型与状态流转变化

- 新增字段 / 表：无。
- 状态枚举：无新增；前端新增运行态 `running/success/failed` 仅用于工具展示。
- 数据创建路径：创建草稿仍由 `CREATE_DRAFT` pending action 完成。
- 数据更新路径：发布/下架仍由管理员确认 action 完成。
- 数据删除或失效路径：无删除能力。
- 兼容旧数据方式：原 SSE envelope 格式不变。

## 7. 权限与安全变化

- 登录态：写操作继续依赖 AI 服务解析真实 JWT 后的管理员上下文。
- 角色权限：写作辅助不执行写入；创建草稿、发布、下架仍需要管理员确认。
- 数据归属：pending action 只能由发起管理员确认。
- 输入校验：草稿快照沿用 `AdminArticleDraftRequest` 长度限制。
- 敏感信息：工具事件只展示输入摘要和结果摘要，不展示 token。
- 文件 / 富文本 / AI 输出：本次不新增 HTML 直出；Web 仍通过 Markdown 渲染链路处理文本。

## 8. 性能与缓存变化

- 查询路径：当前文章总结和相关推荐会增加一次 `/posts/{id}` 调用。
- 索引：无变化。
- 分页：无变化。
- 缓存：搜索/最新/热门缓存不变；详情读取暂不缓存，避免后台编辑态和前台详情不一致。
- 长连接 / 线程池：SSE 事件类型不变，事件数量略增。
- 前端加载：新增少量渲染状态，不引入新依赖。

## 9. 部署与配置变化

- 环境变量：无。
- Docker：无。
- Nginx：无。
- CI/CD：无。
- 数据库迁移：无。

## 10. 对总体架构的影响

- 模块边界：Agent 编排继续集中在 AI 服务，主后端仍只暴露业务 API。
- 数据流：当前文章 `postId` 从前端上下文进入 Agent，再由 AI 服务主动读取真实文章详情。
- 接口协议：结构化 SSE 契约保持不变，前端开始完整消费 plan/tool/confirmation。
- 权限模型：写操作确认模型不变，写作辅助被明确为只读生成能力。
- 部署拓扑：无变化。
