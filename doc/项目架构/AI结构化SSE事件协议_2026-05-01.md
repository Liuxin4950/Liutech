# AI结构化SSE事件协议 架构记录 - 2026-05-01

## 1. 架构结论

Web 前台看板娘聊天统一进入 Agent 能力入口：

- 实时响应：`/ai/agent/stream`
- 完整响应：`/ai/agent/chat`

`stream` / `normal` 只表示响应返回方式，不再表示智能能力开关。前端不再通过关键词判断是否启用 Agent。

## 2. 数据流

```text
Web AiChat
-> chat store 构建 Agent 请求
-> 实时响应走 /ai/agent/stream
-> 完整响应走 /ai/agent/chat
-> AgentOrchestrator 识别意图
-> 普通闲聊返回 data/message
-> 搜索推荐返回 article-results
-> 管理动作返回 confirmation-required
```

## 3. 协议约定

- Agent SSE 使用统一 envelope，`contractVersion=1`。
- `data` 只承载自然语言文本。
- `article-results` 只承载文章卡片数据。
- `confirmation-required` 只承载管理员待确认动作。
- `tool-start` / `tool-result` 表示工具执行过程。
- 前端只按事件类型渲染，不解析模型自然语言里的协议标记。

## 4. 兼容策略

- 旧 `/ai/chat` 和 `/ai/chat/stream` 作为遗留接口保留。
- Web 看板娘主聊天不再默认请求旧聊天接口。
- `agentEnabled === false` 可作为临时兼容开关，但 Web 主流程不使用它。

## 5. 安全边界

- 访客和普通用户可使用聊天、搜索、推荐、总结等只读能力。
- 管理员写作、创建草稿、发布、下架仍由后端权限和确认动作控制。
- 前端模式选择不参与授权，所有写入权限由 AI 服务和主后端二次校验。
