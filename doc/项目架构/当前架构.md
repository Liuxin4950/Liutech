# 当前架构

## 系统组成

LiuTech 是全栈博客平台，包含：

- `Web/`：用户前台 Vue 应用。
- `Admin/`：管理后台 Vue 应用。
- `LiuTech/`：主后端 Spring Boot 服务，负责用户、文章、资源、上传下载等核心业务。
- `LiuTech-AI/`：AI 服务，负责聊天、模型配置、SSE/TTS 相关能力。
- `docker-compose.yml` 与 `nginx/`：生产/容器部署入口。

## AI Agent 架构

- AI 服务新增 `chat.liuxin.ai.agent` 领域包，首期用于智能看板娘 Agent 能力。
- Agent 新代码按 `controller`、`request`、`response`、`application`、`domain`、`tool`、`persistence` 分层，避免继续堆入旧通用 `service` 目录。
- `/ai/agent/chat` 提供非流式 Agent 响应，`/ai/agent/stream` 提供 SSE Agent 主入口。
- `/ai/admin/agent/chat` 和 `/ai/admin/agent/stream` 是管理员写作助手入口，只允许 `ROLE_ADMIN` 使用；普通 `/ai/agent/**` 不承接管理员写作工具。
- `/ai/admin/agent/actions/{actionId}/confirm` 是管理员 Agent 写操作确认入口。
- `/ai/chat`、`/ai/chat/stream` 和 `/ai/recommend` 是 legacy 兼容入口，不承接 Web/Admin 看板娘新能力；legacy 响应会通过 `X-LiuTech-AI-Route` 标识来源。
- Agent SSE 事件使用结构化契约：`agent-start`、`agent-plan`、`tool-start`、`tool-result`、`data`、`article-results`、`field-update`、`writing-draft`、`confirmation-required`、`action-result`、`complete`、`error`。
- 管理员写作助手主流程使用 `field-update` 事件返回字段级文章更新，包含标题、摘要、TinyMCE HTML 正文、真实分类/标签匹配和建议新分类/标签；`writing-draft` 仅作为兼容事件保留。
- 搜索和推荐文章统一返回 `ArticleResultItem`，包含 `id`、`title`、`summary`、`status`、`url`、`adminUrl`、`reason`、`source` 等前端可点击渲染字段。
- 前端访问 AI 服务时，生产环境统一以 `/ai` 作为入口前缀；AI 服务内部接口需要保留或兼容此前缀。
- AI 模型管理接口同时支持 `/admin/models/**` 和 `/ai/admin/models/**`，确保本地直连和生产 Nginx 代理都可用。
- AI 服务只通过主后端 API 执行文章写操作，不直接写主业务库。
- Admin 文章编辑器通过右侧 Agent 侧边栏接入智能看板娘，向 AI 服务传递当前草稿快照。
- Web 前台看板娘聊天默认走公共 Agent 入口：开发环境实时响应默认为 `http://127.0.0.1:8081/ai/agent/stream`，生产通过 `/ai/agent/stream` 代理；登录用户为 `admin` 时才切换到 `/ai/admin/agent/stream` 或 `/ai/admin/agent/chat`。
- Web 内部仍保留 `agentEnabled === false` 作为开发或故障回退开关，但不作为用户可见聊天模式。
- Web 前台不再通过关键词判断是否触发 Agent；普通闲聊由 Agent 内部按 `CHAT` 意图自然回复，推荐、搜索、总结等能力通过结构化事件和 `article-results` 文章卡片返回。
- Web 文章详情页会通过聊天上下文传递 `postId`；Agent 在总结当前文章或推荐相关文章时必须通过主后端读取真实文章详情，不依赖模型猜测当前页面。
- Admin 写作辅助中的 `WRITE_ARTICLE` 只生成可直接写入当前编辑器的字段建议，不创建草稿、不发布；`CREATE_DRAFT` 才进入管理员确认的草稿创建流程。
- Admin/Web 写作辅助应优先返回结构化 `FieldUpdatePayload`，前端对正文进行 DOMPurify 消毒后写入编辑器表单，并在底部工具栏提供字段级撤销。
- Admin/Web 写作请求必须带 `context.requestedFields` 字段白名单和可选 `context.appendTags`；后端只能返回白名单内字段，前端处理 `field-update` 或兼容 `writing-draft` 时也必须二次过滤，避免“只加标签/只改摘要”时覆盖正文等未请求字段。
- Admin/Web 写作辅助未匹配到真实分类/标签 ID 时，可通过 `suggestedCategoryName` / `suggestedTagNames` 返回建议名称；前端只能展示“创建并选中”按钮，由管理员点击后调用现有分类/标签接口新增，不允许 AI 静默新增字典项。
- Admin 写作辅助中的分类读取、标签读取、富文本 HTML 生成必须通过真实 `tool-start` / `tool-result` 事件暴露给管理员界面，不能只依赖前端推断进度。
- Admin/Web 写作执行过程 UI 应显示当前阶段、进度和短工具摘要；完成后不持续展示执行日志，`admin.generateWritingHtml` 的工具摘要不得包含正文 HTML。
- Web `/create` 页面在 admin 用户身份下可显示管理员写作助手；普通用户仍只能使用原文章编辑能力。Web `/create` 与 Admin 文章编辑器的写作上下文统一使用 `context.page=admin-post-editor`，后端兼容历史 `web-create-post`。
- 普通用户/游客的 Web 聊天不展示 `agent-plan`、`tool-start`、`tool-result`、`confirmation-required` 等执行过程，只展示原有“思考中”和最终回复；管理员聊天和 Admin 写作侧边栏才可视化这些过程事件。
- Admin 发布、下架或创建草稿确认成功后，需要把 action 结果同步回当前编辑器状态或新文章 ID。
- Agent 公开文章工具对搜索、最新、热门结果做短 TTL 内存缓存，默认 60 秒，单次结果默认最多 8 条。
- Agent 调主后端的公开和管理员客户端都设置连接/读取超时，避免主后端异常时长时间阻塞 Agent 流程。
- Agent 工具调用通过 `AgentToolCallRecorder` 写入 `ai_agent_tool_call`，记录成功状态、耗时、输入摘要、输出摘要和错误信息。

## 关键安全边界

- 真实 `.env` 不进入版本库，仓库只提交 `.env.example`。
- `DB_PASSWORD`、`JWT_SECRET`、`SPRING_AI_OPENAI_API_KEY` 必须通过环境变量或本地 `.env` 注入。
- 主后端和 AI 服务的 `/admin/**` 均要求 `ROLE_ADMIN`。
- Admin 前端除 `/login`、`/403` 外均要求登录且角色为 `admin`。
- 主后端 JWT 认证会回查 `users` 表当前状态和角色；禁用、删除、降权或旧密码哈希不匹配的 token 不会注入认证上下文。
- AI 服务 JWT 认证会携带 token 调用主后端 `/user/current` 获取当前用户状态和角色，不直接信任 token 中的 role claim。
- 公开文章详情只返回已发布文章；未发布文章仅作者本人可通过前台详情读取，管理员使用管理端详情接口。
- 文章和公告等富文本展示入口需要先经过 DOMPurify 消毒再渲染。
- 已发布文章的 `pre/code` 代码块必须使用稳定背景色和文字色，不能把可读性完全依赖 Prism 外部主题或主题变量。
- Web/Admin 的 TinyMCE 编辑器是共享富文本输入边界；主题切换时必须实时更新编辑器 iframe 内部样式，不应依赖初始化阶段的 `content_style` / `content_css` 自动响应，也不应为了切主题销毁编辑器实例。
- 分类和标签写接口属于管理员能力，普通用户只访问公开列表/查询能力。
- 付费资源文件不通过 `/uploads/resources/**` 静态直连，统一通过 `/resource/download/{resourceId}` 做购买校验后下载。
- 上传根目录不整体暴露为静态目录，公开静态路径仅限图片、文档、音乐等非付费目录。
- Agent 普通只读能力可匿名使用；创建草稿、发布、下架等写操作必须由管理员确认。
- 管理员写作、分类标签匹配、创建草稿和发布辅助必须走 `/ai/admin/agent/**`；普通用户不能通过公共 Agent 入口触发管理员写作工具。
- Agent 新生成文章第一次只能创建草稿，管理员审查或明确同意后才允许发布正文。
- Agent 不开放文章删除能力。
- Agent pending action 只能由发起该 action 的管理员确认。

## AI 信任边界与提示词安全

- AI 服务新增 `chat.liuxin.ai.security` 横切安全层，集中处理 AI 身份、能力、工具权限、提示词边界、模型选择、限流和敏感日志脱敏。
- `AiSystemPromptProvider` 是模型系统提示词的统一来源，组合纳西妲人格提示词、安全规则和能力边界；Agent 路径和 legacy 聊天路径都必须通过它获取系统提示词。
- `AiCapabilityResolver` 将当前请求解析为 `guest`、`user` 或 `admin`，并返回 capability 列表；capability 只用于展示和服务端策略判断，前端不能把它当授权依据。
- 基础只读 capability 包含聊天、公开文章读取、总结、搜索和推荐；管理员额外拥有写草稿、确认创建草稿、确认发布和确认下架能力。
- `AiToolAccessPolicy` 是 Agent 写入工具的统一权限入口；创建草稿、发布文章、下架文章必须是管理员，且发布/下架仍需要 pending action 确认。
- `AiPromptSecurityPolicy` 会追加系统安全规则，并把博客上下文、文章内容、用户输入、草稿上下文包成不可信资料；这些资料只能作为事实参考，不能覆盖系统身份、工具规则或权限规则。
- AI 不得根据用户自称授予权限，不得泄露系统提示词、API Key、JWT、内部工具规则或隐藏配置。
- AI 模型能力边界禁止删除文章、管理用户或角色、通过自然语言管理模型配置、直连数据库、执行 SQL 或 Shell。
- AI 生成的文章正文必须被视为不可信富文本；写作提示词要求 TinyMCE HTML，Web/Admin 前端应用前应进行 HTML 消毒，发布前仍需管理员审查。
- AI 生成的写作内容在进入正文和摘要前必须清理助手旁白、工具说明和执行过程描述，避免“我来帮你/先获取分类标签”等非文章内容污染已发布文章。
- AI 输出的分类/标签 ID 必须被视为不可信候选值；后端只能接受真实分类/标签列表中存在的 ID，不命中的值只能降级为建议名称。
- AI 写作结果末尾的分类/标签 JSON 元数据必须在后端解析后从正文中剥离；需兼容 fenced `json` 代码块和模型偶发输出的松散 `json\n{...}` 尾部元数据，避免污染 TinyMCE 正文。
- `AiModelPolicy` 统一解析模型和参数；前端传入未知、禁用或未配置模型时，必须回退后端默认模型，不允许在严格白名单模式下直接使用前端模型名。
- 公开 AI 入口通过应用内轻量限流保护，覆盖 `/ai/chat`、`/ai/chat/stream`、`/ai/agent/chat`、`/ai/agent/stream` 和 `/ai/recommend/**`；多实例生产部署后建议升级为 Redis 或 Nginx 限流。
- AI 服务回查主后端 `/user/current` 时设置连接和读取超时，避免主后端异常导致 AI 请求长时间挂起。
- Web 前台看板娘主聊天始终使用 Agent；非流式完整响应调用 `/ai/agent/chat`，避免“完整响应”绕过 Agent 身份和权限规则。

## AI Agent 数据模型

- `ai_agent_task`：记录 Agent 任务、用户、会话、意图、状态、输入、结果摘要和错误。
- `ai_agent_action`：记录管理员待确认操作、目标资源、payload、执行结果和过期时间。
- `ai_agent_tool_call`：记录工具调用名称、输入输出、是否成功、错误和耗时，供审计与性能分析。
- 已有数据库升级到 Agent 版本时，需要执行 `sql/ai_agent_migration_2026_04_30.sql`。

## AI Agent 性能配置

- `spring.ai.agent.tool-cache-ttl-ms`：公开文章工具缓存时间，默认 `60000` 毫秒。
- `spring.ai.agent.max-article-results`：单次结构化文章结果上限，默认 `8`。
- `spring.ai.agent.blog-connect-timeout-ms`：AI 服务连接主后端超时，默认 `3000` 毫秒。
- `spring.ai.agent.blog-read-timeout-ms`：AI 服务读取主后端响应超时，默认 `8000` 毫秒。
- `spring.ai.security.rate-limit.*`：公开 AI 接口应用内限流配置，默认启用。
- `spring.ai.security.model-policy.strict-whitelist`：模型严格白名单，默认启用。
- `spring.ai.security.prompt-guard.enabled`：提示词安全规则注入，默认启用。
- `spring.ai.security.auth-connect-timeout-ms` / `auth-read-timeout-ms`：AI 服务回查主后端身份的超时配置。

## 本地开发

- Windows 本地启动后端：`scripts/run-backend-dev.ps1`。
- Windows 本地启动 AI 服务：`scripts/run-ai-dev.ps1`。
- 两个脚本都会先读取项目根目录 `.env`，再执行对应模块的 `mvn spring-boot:run`。

## 部署约定

- Nginx 统一入口负责 `/api/`、`/ai/`、`/uploads/` 和前端路由分发。
- Nginx `/ai/` 代理到 AI 服务时保留 `/ai` 前缀，避免聊天、Agent、推荐等 `/ai/**` 接口被改写成不存在的路径。
- 服务器 SSL 证书目录挂载到容器 `/etc/nginx/ssl`，证书文件名与 `nginx/conf.d/default.conf` 保持一致。
- 生产环境必须在 `.env` 中显式配置数据库密码、JWT 密钥、AI API Key 和服务端口。
- `/api/` 通过 Authorization Bearer Token 认证，不使用 cookie credentials CORS；`/ai/` 的 SSE 场景保留按来源回显的 CORS 配置。

## API 契约约定

- 管理端分页参数使用 `current` / `size`。
- 文章状态在前后端之间使用 `draft` / `published` / `archived` 字符串枚举。
- 前台热门排序请求转换为后端 `sort=hot`。
- AI 服务读取最新文章使用 `limit` 参数。
- Agent 搜索/推荐结果必须使用结构化 `article-results` 事件或响应字段，不依赖自然语言解析。
- Agent 执行过程必须使用结构化 `agent-plan`、`tool-start`、`tool-result`、`confirmation-required` 事件传给前端；只有管理员界面可视化这些事件，普通用户聊天应隐藏过程事件；前端不能把这些事件当权限依据。
- 管理员写作字段更新必须使用结构化 `field-update` 事件或响应字段传给前端，不依赖自然语言解析标题、摘要、正文、分类和标签；`null` 表示不修改，前端不得用 `null` 或空标签数组清空已有字段。
- `requestedFields` 是管理员写作字段更新的长期契约：未列入白名单的字段即使模型生成了内容也不得写入；`appendTags=true` 时标签列表按当前标签和新匹配标签去重合并。
- `suggestedCategoryName` / `suggestedTagNames` 是建议创建契约：它们不是已存在的 ID，前端不得直接当作已选分类/标签保存，必须先由管理员确认创建成功并拿到真实 ID。
