# 看板娘双引擎TTS与Live2D表情控制 架构记录 - 2026-05-08

## 1. 架构结论

看板娘语音推理统一收口到主后端：

```text
Web/Admin
-> LiuTech 主后端 /tts/**
-> GPT-SoVITS 本地服务 或 SiliconFlow 云端
-> 主后端缓存音频
-> Web 同源播放 /tts/audio/{id}
```

AI 服务不再直连 GPT-SoVITS 或 SiliconFlow，只调用主后端 `/tts/speech`。这样可以让本地笔记本继续作为主音色推理节点，也能在后台切换到 SiliconFlow 作为云端备用，同时避免前端暴露本地服务地址或云端密钥。

## 2. TTS Provider

当前支持两个 provider：

- `GPT_SOVITS`：主音色，使用后台配置的 `baseUrl` 和 `voiceModel`。
- `SILICONFLOW`：云端备用，使用后台配置的 `siliconFlowModel`、`siliconFlowVoiceUri`、`responseFormat`、`sampleRate`、`speed`。

SiliconFlow 默认模型为 `FunAudioLLM/CosyVoice2-0.5B`，适配用户已上传的 `naxida` 音色；`IndexTeam/IndexTTS-2` 和 `fnlp/MOSS-TTSD-v0.5` 作为后台可选预设。

TTS provider 配置保存在主库 `system_settings`：

- 新环境由 `sql/sql.sql` 初始化默认键。
- 当前权威 SQL 为 `sql/sql.sql`，同时初始化主后端库 `liutech`、AI 服务库 `liutech_ai` 和 TTS 配置键；已有环境上线前以该文件作为表结构基线补齐差异。
- `tts.siliconFlowVoiceUri` 可保存用户上传后的 `speech:...` URI；API Key 不入库。
- SiliconFlow TTS Key 读取顺序是 `SILICONFLOW_TTS_API_KEY`、`SILICONFLOW_API_KEY`、`SPRING_AI_OPENAI_API_KEY`。本地 Spring Boot 直跑时，后端还会读取项目根目录 `.env` 作为兜底。

## 3. 主后端接口

- `POST /tts/speech`
  - 入参：`{ "text": "..." }`
  - 出参：`{ audioUrl, provider, format }`
  - 行为：按当前 provider 调用真实 TTS 服务，缓存音频后返回同源 URL。
  - 认证：`X-TTS-Internal-Token` header 必填，token 未配置时拒绝所有请求（fail-closed）。
- `GET /tts/audio/{fileName}`
  - 返回缓存音频二进制，供浏览器播放。
- `GET /tts/status`
  - 返回公共 TTS 状态，`permitAll()`；不暴露 GPT-SoVITS 地址、音色模型、SiliconFlow voice URI 或 Key 来源。
- `GET /admin/tts/status`
  - 返回完整 TTS 诊断状态，仅管理员可访问。
- `GET /admin/tts/siliconflow/voices`
  - 拉取 SiliconFlow 已上传音色列表。
- `POST /admin/tts/siliconflow/voice`
  - multipart 上传参考音频，并保存返回的 `speech:...` URI。
- `POST /admin/tts/test-speech`
  - 使用当前配置生成测试音频。

`SILICONFLOW_API_KEY` 或 `siliconflow.api-key` 只在主后端环境读取，不入库、不返回前端。`TTS_PROXY_INTERNAL_TOKEN` 为必填配置，AI 服务调用 `/tts/speech` 时携带 `X-TTS-Internal-Token`。

## 4. AI 服务事件

Agent 流式聊天在自然语言回复完成后，按分段发送看板娘事件：

- `avatar-cue`：`{ seq, expression, motion, intensity, durationMs, text }`
- `audio`：`{ seq, conversationId, text, audioUrl }`
- `audio-skip`：TTS 关闭、离线或失败时的跳过事件。
- `audio-complete`：本轮音频队列结束。

事件顺序：先发所有 `avatar-cue` + `audio`（每段一个），再发 `audio-complete`，最后发 `complete`。

`avatar-cue` 与 TTS 开关解耦，所以纯文本聊天也能驱动表情变化。TTS 音频仍由既有播放队列驱动嘴型 RMS。

## 5. Live2D 前端协议

Web 前台维护两个独立队列，但通过 cue 绑定机制实现同步：

- 音频队列：负责顺序播放 `/tts/audio/**`，嘴型由音频 RMS 驱动。
- Avatar cue 队列：负责顺序执行表情/动作提示。

### 5.1 Cue-Audio 绑定机制

`enqueueTtsAudio` 时，从 `avatarCueBuffer` 取出对应 seq 的 cue，绑定到音频 item 上：

```typescript
const cue = avatarCueBuffer.value[item.seq]
if (cue) {
  enriched.cue = cue
  delete avatarCueBuffer.value[item.seq]
  avatarCueNextSeq.value = item.seq + 1  // 推进游标，避免后续 cue 孤立
}
```

`playNextTts` 每播一段音频前，应用绑定的 cue，实现表情与音频同步：

```typescript
if (next.cue) {
  live2dRef.value.applyAvatarCue?.({ ...next.cue, skipResetTimer: true })
}
```

TTS 播放期间，`applyNextAvatarCues` 不消费 cue 队列，避免表情和音频脱节。

### 5.2 表情生命周期

```text
用户发消息 → aiThinking=true → 思考表情（半眼+手势变化）
  ↓
后端 avatar-cue 到达 → 存入 buffer → 绑定到音频 item
  ↓
playNextTts 播放前 → 应用 cue 表情（skipResetTimer=true，不设自动重置）
  ↓
下一段音频 → 应用下一个 cue 表情（自动覆盖前一个）
  ↓
所有音频播完 → finally 块 → neutral 恢复默认
```

### 5.3 新消息打断

`sendStreamMessage` 时递增 `ttsStopSignal`，MainLayout 监听后调 `stopTtsPlayback()` 停止当前音频，避免旧音频和新回复重叠。

### 5.4 表情配置

- 表情最短切换间隔为 `1200ms`。
- 动作最短切换间隔为 `3000ms`。
- 当前纳西妲模型没有 motions，只执行 expression。
- `Live2d.vue` 的 `expressionMap` 将语义名映射到模型表情名。

## 7. Admin 配置边界

Admin AI 设置页是唯一用户可见的 TTS 配置入口：

- GPT-SoVITS 区：配置服务地址、读取模型、选择本地音色。
- SiliconFlow 区：选择云端模型、填写或选择 voice URI、上传参考音频、设置输出格式、采样率、语速并试听。

浏览器上传参考音频，服务器不直接读取用户本机 `F:\...` 路径。用户本机目录只作为人工选择文件的来源。

## 8. 性能与失败策略

- AI 服务全局 TTS 并发限制为 `5`（Semaphore），保护本地笔记本推理。
- 主后端将 TTS 结果写入临时缓存目录，前端只播放缓存 URL。
- TTS 失败不影响聊天文本；AI 服务发送 `audio-skip`，前端继续展示文本和执行 `avatar-cue`。
- SiliconFlow 使用 `stream:false`，让主后端保存完整二进制文件后再返回同源地址。
- GPT-SoVITS 请求日志使用 `debug` 级别，避免记录用户文本。
- SiliconFlow 错误信息截断到 200 字符，避免泄露上游响应。

## 9. 安全边界

- 前端不得直接调用 GPT-SoVITS 笔记本服务。
- 前端不得直接调用 SiliconFlow。
- SiliconFlow API Key 只允许从环境变量或本地 `.env` 读取，状态接口只暴露变量来源，不暴露密钥值。
- `/tts/speech` 要求 `X-TTS-Internal-Token`，token 未配置时 fail-closed 拒绝请求。
- `downloadAudio` 不自动跟随重定向；每次重定向都重新校验 scheme、host、port 必须与配置的 GPT-SoVITS baseUrl 一致，防止 SSRF。
- TTS cache 默认 24 小时/512MB 清理，通过 `TTS_CACHE_MAX_AGE_HOURS`、`TTS_CACHE_MAX_BYTES`、`TTS_CACHE_CLEANUP_INTERVAL_MS` 配置。
- AI 服务 TTS 并发默认 1，通过 `TTS_PROXY_CONCURRENCY` 配置。
- 上传第三方或角色相关音色需要确认授权；系统只提供技术上传能力，不默认判断授权合法性。
