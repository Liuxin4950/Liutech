## 1. 本次变更概览

- 变更目标：把纳西妲从聊天式辅助升级为管理员文章写作助手，并隔离管理员 AI 工具路径。
- 核心能力：管理员专用 `/ai/admin/agent/**`、结构化 `field-update` SSE 事件、Web/Admin 双写作入口。
- 影响范围：AI 服务 Agent 控制器、编排器、写作响应契约；Admin 文章弹窗；Web 创建文章页。
- 不影响范围：主后端数据库结构、Nginx、Docker、主后端接口定义。

## 2. 影响的系统模块

| 模块 | 是否影响 | 变化说明 |

## 4. 核心接口与事件

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/ai/admin/agent/chat` | ROLE_ADMIN | 管理员非流式写作助手。 |
| POST | `/ai/admin/agent/stream` | ROLE_ADMIN | 管理员流式写作助手。 |
| POST | `/ai/admin/agent/actions/{actionId}/confirm` | ROLE_ADMIN | 管理员确认 Agent 写操作。 |

Web 全局聊天入口约定：

```text
游客 / 普通用户 -> http://127.0.0.1:8081/ai/agent/stream（开发环境默认）或 /ai/agent/stream（生产代理）
管理员 -> http://127.0.0.1:8081/ai/admin/agent/stream（开发环境默认）或 /ai/admin/agent/stream（生产代理）
```

普通用户聊天不展示 `agent-plan`、`tool-start`、`tool-result`、`confirmation-required` 等执行过程；这些事件只在管理员消息中可视化。

管理员写作主路径 SSE 事件：

```text
field-update -> FieldUpdatePayload
```

`writing-draft -> WritingDraftPayload` 保留为兼容事件，前端不再以草稿卡片作为主流程。

写作流程需要真实暴露以下工具过程，供管理员界面展示进度和排查问题：

```text
admin.listCategories -> 读取分类列表
admin.listTags -> 读取标签列表
admin.generateWritingHtml -> 生成富文本 HTML
```

`FieldUpdatePayload` 主要字段：

```text
title
summary
contentHtml
categoryId / categoryName
tagIds / tagNames
suggestedCategoryName / suggestedTagNames
```

写作请求上下文约定：

```text
context.page = admin-post-editor
context.requestedFields = ["title" | "summary" | "content" | "category" | "tags" | "check"]
context.appendTags = true | false
```

`requestedFields` 是字段写入白名单。后端只能返回白名单内的字段，前端即使收到兼容的 `writing-draft` 事件，也必须再次按白名单过滤后再写入表单。`appendTags=true` 表示标签更新应在当前标签基础上追加合并，而不是替换整组标签。

## 5. 数据流

```text
Admin/Web 编辑器草稿
-> 管理员写作侧边栏
-> 推断 requestedFields / appendTags
-> /ai/admin/agent/stream
-> AgentOrchestrator
-> 按字段白名单限制本次可写字段
-> tool-start/admin.listCategories -> AdminBlogClient 读取分类
-> tool-start/admin.listTags -> AdminBlogClient 读取标签
-> tool-start/admin.generateWritingHtml -> 模型生成 TinyMCE HTML
-> 后端校验分类/标签 ID 必须来自真实列表
-> field-update SSE（真实 ID 直接写入，建议名称进入确认创建 UI）
-> 前端 DOMPurify 消毒正文并直接写入编辑器表单
-> 不存在的分类/标签由管理员点击“创建并选中”后调用现有接口
-> 用户可在底部工具栏撤销字段
-> 用户保存草稿或确认发布
```

## 6. 权限与安全边界

- `/ai/admin/agent/**` 只允许管理员访问。
- 公共 `/ai/agent/**` 继续保留聊天、搜索、推荐、总结等只读能力。
- AI 写作输出永远视为不可信内容，不能直接绕过编辑器发布。
- AI 字段更新必须受 `requestedFields` 白名单约束，未被用户请求的标题、摘要、正文、分类或标签不得被本次响应覆盖。
- AI 写作输出进入正文和摘要前必须清理助手旁白、工具说明和执行过程描述；摘要只能来自文章正文内容。
- AI 输出的分类/标签 ID 永远视为不可信候选值，只能在命中真实分类/标签列表后写入字段。
- 分类/标签不存在时只作为建议名称，创建必须由管理员点击确认。
- 建议分类/标签名称可通过 `field-update.suggestedCategoryName` / `suggestedTagNames` 传给前端；前端只展示“创建并选中”操作，不允许模型静默新增字典项。
- 发布、创建草稿等写操作继续使用 pending action 和管理员确认。
- Admin token 不进入模型提示词、日志和 SSE payload。

## 7. 富文本边界

- 模型提示词要求输出 TinyMCE 可编辑 HTML。
- 允许常见文章结构标签，如 `h2`、`h3`、`p`、`ul`、`ol`、`blockquote`、`pre/code`。
- 禁止 `script`、`iframe`、事件属性和 `javascript:` URL。
- Web/Admin 应用正文前使用 DOMPurify；后端基础过滤不能作为完整富文本安全边界。
- Web 文章详情代码块必须有不依赖 Prism 外部主题的稳定背景色和文字色，确保已发布文章可读。

## 8. 部署与配置

- 无新增环境变量。
- 无数据库迁移。
- Nginx 保持 `/ai/` 前缀代理即可。
- 生产环境仍需确保 JWT_SECRET 在主后端和 AI 服务一致。

## 9. 后续演进

- 抽象 Web/Admin 共用写作助手组件，减少双端重复。
- 增加章节级应用、写作模板和发布前评分。
- 为 `writing-draft` 增加更严格的 schema 校验。
