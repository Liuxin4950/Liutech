## 1. 本次变更概览

- 变更目标：让 AI 身份、权限、提示词边界、模型选择和公开接口频控形成统一安全层。
- 核心能力：capability、工具权限策略、提示词安全策略、模型白名单、应用内限流、认证回查超时。
- 影响范围：`LiuTech-AI`、Web AI service/store、Admin Agent service/types。
- 不影响范围：主后端 JWT 规则、数据库结构、Nginx 路由、Docker 服务拓扑。

## 2. 影响的系统模块

| 模块 | 是否影响 | 变化说明 |
| --- | --- | --- |
| Web 前台 | 是 | 普通非流式站内任务也会调用 `/ai/agent/chat` |
| Admin 后台 | 是 | Agent SSE 支持 `agent-start` capability 和更清晰错误 |
| LiuTech-AI | 是 | 新增 AI 安全横切层 |
| LiuTech 主后端 | 否 | 仍作为用户身份权威来源 |
| 数据库 / 存储 | 否 | 无表结构变更 |
| 部署 / 配置 / CI | 是 | 新增 `spring.ai.security.*` 配置，默认值内置 |

## 3. 目录与文件变化

| 路径 | 变化 | 职责 |

## 4. 核心类、组件与职责变化

- 接口入口：`AiChatController`、`AgentChatController` 保持路径不变。
- 业务服务：`AiModelPolicy` 负责模型白名单和参数约束；`AiPromptSecurityPolicy` 负责提示词安全规则。
- 数据访问：无新增 mapper。
- 前端页面 / 客户端：Web 聊天 store 和 Admin Agent service 对接结构化安全字段。
- 可复用组件：`AiCapabilityResolver`、`AiToolAccessPolicy`、`SensitiveLogSanitizer`。
- API 调用层：`AiRateLimitInterceptor` 在 Controller 前拦截公开 AI 请求。
- 状态管理 / 缓存：限流使用应用内 `ConcurrentHashMap` bucket，并定期清理。

## 5. 接口与调用链路变化

```text
Web/Admin 请求
-> JwtAuthenticationFilter 回查主后端身份
-> AiRateLimitInterceptor 按 user/IP/role 限流
-> AiChatController / AgentChatController
-> AiCapabilityResolver / AiModelPolicy / AiPromptSecurityPolicy
-> AgentOrchestrator / AiChatServiceImpl
-> LLM 或工具确认流
-> 结构化 response/SSE
-> 前端渲染文本、文章卡片、确认卡片或错误
```

新增或调整的接口：

| 方法 | 路径 | 调用方 | 鉴权 | 说明 |
| --- | --- | --- | --- | --- |
| POST | `/ai/chat` | Web | 公开 + 限流 | 闲聊入口，新增安全提示词和模型策略 |
| POST | `/ai/chat/stream` | Web | 公开 + 限流 | 流式闲聊入口 |
| POST | `/ai/agent/chat` | Web/Admin | 公开 + 限流 | 非流式站内任务和身份问答 |
| POST | `/ai/agent/stream` | Web/Admin | 公开 + 限流 | 流式 Agent |

## 6. 数据模型与状态流转变化

- 新增字段 / 表：无数据库字段；`AgentChatResponse` 增加 `capabilities`。
- 状态枚举：无新增数据库状态。
- 数据创建路径：Agent task/action 仍沿用既有路径。
- 数据更新路径：confirm 仍按 pending -> executed/failed。
- 数据删除或失效路径：无变化。
- 兼容旧数据方式：无数据库迁移。

## 7. 权限与安全变化

- 登录态：AI 服务仍通过主后端 `/user/current` 确认登录态，增加超时。
- 角色权限：新增 capability 作为能力描述；真实授权仍由后端策略和主后端鉴权决定。
- 数据归属：pending action 仍只能由发起管理员确认。
- 输入校验：用户输入、文章上下文、草稿上下文均作为不可信内容传给模型。
- 敏感信息：新增日志脱敏工具，不应记录 token、API Key、长篇敏感正文。
- 文件 / 富文本 / AI 输出：不新增渲染入口；AI 写文章仍必须草稿优先和发布确认。

## 8. 性能与缓存变化

- 查询路径：无新增数据库查询。
- 索引：无变化。
- 分页：无变化。
- 缓存：应用内限流 bucket 定期清理。
- 长连接 / 线程池：SSE 行为保持；主后端认证回查增加 timeout。
- 前端加载：仅 service/type 小改动，包体积影响低。

## 9. 部署与配置变化

- 环境变量：无新增必填项。
- Docker：无变化。
- Nginx：无变化。
- CI/CD：无变化。
- 数据库迁移：无。
- 新增配置：`spring.ai.security.prompt-guard.*`、`spring.ai.security.model-policy.*`、`spring.ai.security.rate-limit.*`、`spring.ai.security.auth-*-timeout-ms`。

## 10. 对总体架构的影响

- 模块边界：新增 `chat.liuxin.ai.security` 横切安全层，避免权限和提示词规则散落在 Agent 编排中。
- 数据流：AI 请求先经过限流和 capability/模型/提示词策略，再进入模型或工具调用。
- 接口协议：Agent response/SSE 可携带 `capabilities`，错误使用 `RATE_LIMITED`、`FORBIDDEN_CAPABILITY` 等 code。
- 权限模型：LLM 不能认证、授权或直接执行写操作；服务端策略决定工具可用性。
- 部署拓扑：不变。

## 11. 后续演进建议

- 多实例生产部署改用 Redis 或 Nginx 限流。
- 推荐引擎重构时移除旧文本推荐标记，完全使用结构化事件。
- 将 `AiChatServiceImpl` 中 TTS、SSE、模型参数等职责继续拆分，降低长期维护成本。
