## 1. 问题 / 需求概述

- 背景：结构化 SSE 已经把前后端协议收敛到 Agent，但模型能力、提示词来源和 legacy 路径边界仍需统一。
- 用户目标：纳西妲身份稳定，guest/user/admin 能力清晰，Web/Admin 主路径统一走 Agent。
- 本次要解决的问题：Agent 文本生成未复用完整人格提示词；旧路径未显式标识 legacy；能力禁止项缺少可测试约束。
- 本次不解决的内容：不删除旧接口，不重构 `AgentOrchestrator`，不引入 Python/LangChain，不改数据库。

## 2. 原因定位

- 现象：`PromptAssembler` 和 `AgentOrchestrator` 分别构造系统提示词，Agent 路径只使用安全规则，长期可能出现人格和能力边界漂移。
- 根因 / 缺口：缺少统一的系统提示词 Provider；旧 `/ai/chat/**` 和 `/ai/recommend` 未在代码层标识 legacy。
- 证据：`AgentOrchestrator.generateText` 只创建 `new SystemMessage(promptSecurityPolicy.systemRules())`；旧 Controller 注释仍称普通/流式模式。
- 涉及模块：`LiuTech-AI` 安全层、Agent 编排、legacy Controller、Web AI service。

## 5. 实现内容

### 5.1 后端

- 新增 `AiSystemPromptProvider`，统一组合 `AiPromptConfig`、`AiPromptSecurityPolicy` 和能力边界规则。
- `PromptAssembler` 和 `AgentOrchestrator` 都改为使用统一系统提示词。
- legacy `/ai/chat`、`/ai/chat/stream` 返回 `X-LiuTech-AI-Route: legacy-chat`。
- legacy `/ai/recommend` 返回 `X-LiuTech-AI-Route: legacy-recommend`。
- 删除意图不映射为任何管理动作，保持普通聊天/拒绝路径。

### 5.2 前端

- Web AI service 注释明确：`agentEnabled === false` 只作为内部故障/开发回退，不是 UI 模式。
- 正常 Web 主流程仍 `agentEnabled: true`，不改变用户可见体验。

### 5.3 数据库 / 配置 / 部署

- 数据库：无变更。
- 配置：无新增配置。
- 部署：无 Nginx、Docker 或 CI/CD 变化。

## 6. 安全与性能处理

- 安全影响：统一提示词明确禁止删除、用户管理、自然语言模型配置、SQL/Shell；授权仍由服务端策略兜底。
- 性能影响：系统提示词略增，token 成本小幅增加。
- 已采取措施：能力边界规则保持短文本；不注入大段 PRD。
- 遗留风险：legacy 路径仍公开存在，但已标识 legacy；后续可单独规划下线或加更严格访问策略。
