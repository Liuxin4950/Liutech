## 1. 问题 / 需求概述

- 背景：智能看板娘 Agent 已具备文章推荐、搜索、总结、管理员草稿和发布确认能力，需要补齐 AI 身份、权限、提示词注入和成本防护边界。
- 用户目标：AI 可以自然聊天和辅助写作，但不能被用户或文章内容诱导改变身份、越权发布或绕过确认。
- 本次要解决的问题：身份问答服务端化、提示词安全策略、工具权限集中化、应用内限流、模型白名单兜底、主后端认证超时、前端非流式 Agent 对接。
- 本次不解决的内容：不重写 Agent 框架，不引入 LangChain/LangGraph，不做 RAG，不开放删除能力，不做 Redis/Nginx 分布式限流。

## 2. 原因定位

- 现象：普通聊天身份表达仍可能由模型猜测；未知模型在无启用白名单时会沿用前端传入值；公开 AI 接口缺少应用级频控；JWT 回查主后端无显式超时。
- 根因 / 缺口：AI 安全边界缺少统一横切层，权限、提示词、模型选择、限流分别散落在不同链路。
- 证据：已检查 `AiChatServiceImpl`、`PromptAssembler`、`AgentOrchestrator`、`AgentActionService`、`JwtAuthenticationFilter`、`Web/src/stores/chat.ts`。
- 涉及模块：`LiuTech-AI`、`Web`、`Admin`。

## 5. 实现内容

### 5.1 后端

- 新增 `AiCapabilityResolver`，统一生成 guest/user/admin 能力列表。
- 新增 `AiToolAccessPolicy`，限制草稿、发布、下架等写操作只能由管理员发起。
- 新增 `AiPromptSecurityPolicy`，追加身份、防注入、防提示词泄露和工具边界规则。
- 新增 `AiModelPolicy`，未知或禁用模型回退默认模型，并限制 `temperature/maxTokens`。
- 新增 `AiRateLimitInterceptor`，对公开 AI 接口进行应用内轻量限流。
- `JwtAuthenticationFilter` 改为带超时的 `RestTemplate`。

### 5.2 前端

- Web 普通模式在 `agentEnabled=true` 时调用 `/ai/agent/chat`。
- Web 普通 Agent 响应支持渲染 `articleResults`。
- Admin Agent service 支持 `agent-start`，并对 429/403 给出可读错误。

### 5.3 数据库 / 配置 / 部署

- 不新增数据库结构。
- 新增 `spring.ai.security.*` 配置，默认启用提示词安全、严格模型白名单和应用内限流。
- 不修改 Docker/Nginx 拓扑。

## 6. 安全与性能处理

- 安全影响：本次触及 AI、认证、授权、提示词、模型和限流，属于高风险变更。
- 性能影响：应用内限流使用内存 bucket，有过期清理；认证回查增加 timeout，降低阻塞风险。
- 已采取措施：工具权限集中化、模型白名单兜底、上下文不可信包装、429 限流、敏感日志脱敏工具、单元测试覆盖。
- 遗留风险：应用内限流不跨实例共享，生产多实例时建议升级 Redis 或 Nginx 限流。

## 9. 回滚方案

- 代码回滚：回退本次安全层、前端契约和测试变更。
- 配置回滚：可设置 `spring.ai.security.rate-limit.enabled=false` 关闭应用内限流；可设置 `spring.ai.security.prompt-guard.enabled=false` 关闭安全提示词追加。
- 数据回滚：无数据库变化。
- 用户影响：回滚后 AI 身份和提示词注入防护变弱，但旧聊天与 Agent 能力恢复到变更前行为。
