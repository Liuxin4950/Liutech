## 1. 问题 / 需求概述

- 背景：GPT-SoVITS 本地推理能保持看板娘主音色，但把推理压力放到服务器上成本过高；SiliconFlow 云端 TTS 可作为备用，但不能把 API Key 暴露给前端。
- 目标：主后端统一代理 TTS 推理，支持本地 GPT-SoVITS 与 SiliconFlow 双引擎；AI 服务只调用主后端；Web 前台在聊天时同时处理音频、嘴型、表情和动作提示。
- 体验要求：TTS 关闭或失败时，Live2D 仍能根据文本切换表情；表达和动作切换需要节流，避免连续高频变化。
- 本次不解决：更复杂的模型级情绪规划、精确音素级口型、具备 motions 的 Live2D 模型资源补齐。

## 4. 实现内容

### 4.1 主后端

- `POST /tts/speech` 接收文本并按当前配置选择 provider。
- GPT-SoVITS provider 调用本地 `/infer_single`，读取返回的音频地址并下载到主后端缓存目录。
- SiliconFlow provider 调用 `https://api.siliconflow.cn/v1/audio/speech`，使用 `stream:false` 获取二进制音频并缓存。
- 缓存音频通过 `GET /tts/audio/{fileName}` 同源播放，前端不直接访问笔记本 TTS 服务或 SiliconFlow。
- SiliconFlow TTS API Key 按 `SILICONFLOW_TTS_API_KEY`、`SILICONFLOW_API_KEY`、`SPRING_AI_OPENAI_API_KEY` 顺序读取；本地开发还会兜底读取项目根目录 `.env`。
- SiliconFlow API Key 不写入数据库，也不返回给前端；状态接口只返回是否配置和变量来源。
- 可选 `TTS_PROXY_INTERNAL_TOKEN` / `tts.proxy.internal-token` 用于 AI 服务调用 `/tts/speech` 时加内部 header。
- SiliconFlow voice list 兼容官方 `results` 和用户实测 `result` 两种返回字段。
- `system_settings` 新增 TTS 配置种子：`tts.provider`、`tts.siliconFlowModel`、`tts.siliconFlowVoiceUri`、`tts.responseFormat`、`tts.sampleRate`、`tts.speed` 等。当前权威初始化脚本为 `sql/sql.sql`。

### 4.2 AI 服务

- `AgentChatRequest` 增加 `ttsEnabled`。
- `TtsClient` 改为调用主后端 `/tts/speech`，并用 `Semaphore(1)` 限制全局 TTS 并发，保护本地笔记本推理。
- 普通聊天原来的切句逻辑抽到 `TtsSegmenter`，Agent 与普通聊天共用。
- Agent 在回复完成后按分段发送：
  - `avatar-cue`：表情/动作提示，TTS 关闭或失败时仍发送。
  - `audio`：TTS 成功时发送音频 URL。
  - `audio-skip`：TTS 关闭、未配置或失败时发送跳过原因。
  - `audio-complete`：本轮 TTS 队列结束。
- 首版 cue 使用后端规则分类，覆盖 `happy`、`sad`、`angry`、`thinking`、`surprised`、`shy`、`neutral`。

### 4.3 Web 前台

- `chat.ts` 新增 avatar cue 顺序队列，按 `seq` 保证表情提示顺序。
- `MainLayout.vue` 在 Live2D 显示时消费 cue 队列，音频播放仍使用既有播放队列。
- `Live2d.vue` 暴露 `applyAvatarCue`，将通用 expression 映射到当前纳西妲模型的 expression。
- 表情最短间隔为 `1200ms`，动作最短间隔为 `3000ms`；当前模型没有 motions 时只执行 expression。
- 表情会按 cue 时长延迟恢复默认，避免长时间停留在极端表情。
- 音频 URL 为相对 `/tts/audio/**` 时，会自动拼接主后端服务地址。

### 4.4 Admin 后台

- AI 设置页的语音推理区新增 provider 分段按钮。
- GPT-SoVITS 区保留服务地址、读取模型和模型选择。
- SiliconFlow 区支持：
  - 选择 `FunAudioLLM/CosyVoice2-0.5B`、`IndexTeam/IndexTTS-2`、`fnlp/MOSS-TTSD-v0.5`。
  - 填写或选择 `speech:...` voice URI。
  - 设置音频格式、采样率、语速。
  - 通过弹窗上传参考音频和参考文本。
  - 调用后台测试试听当前配置。
- 云端音色默认优先选 `customName=naxida`，匹配用户已上传的 `speech:naxida:...` 音色。

## 5. 安全与性能处理

- 不在代码、数据库和前端响应中保存 SiliconFlow API Key。
- `/tts/speech` 默认可被 AI 服务调用；生产环境建议配置 `TTS_PROXY_INTERNAL_TOKEN`，让外部请求必须携带内部 token。
- 所有音频都落到主后端临时缓存目录，再同源播放，避免浏览器暴露第三方接口和本地笔记本地址。
- TTS 推理全局并发默认 `1`，避免本地 GPT-SoVITS 被多句并行压垮。
- 文本合成请求限制单段长度，Agent 侧继续按句段切分，降低单次推理压力。
- 上传第三方音色存在授权风险，后台只提供技术能力，实际应上传有权使用的参考音频。

## 8. 回滚方案

- 后端回滚：关闭 TTS 总开关，或把 provider 切回 `GPT_SOVITS` 并清空 SiliconFlow 配置。
- AI 服务回滚：前端可继续显示文本；TTS 失败只会产生 `audio-skip`，不会影响聊天主链路。
- 前端回滚：移除 `avatar-cue` 消费后，聊天和旧音频播放仍可工作。
- 数据回滚：本次未新增数据库表；新增配置项在旧逻辑下不会被读取。
