# 项目问题排查修复开发记录

## 基本信息

- 日期：2026-04-30
- 类型：安全整改 / Bug 修复
- 范围：前端 Admin、主后端、AI 服务、Docker/Nginx/部署配置、项目文档

## 问题与根因

1. `.env` 被 Git 跟踪，且多个配置文件存在真实形态密钥或密码默认值。
   - 根因：后续加入 `.gitignore` 不能自动取消已跟踪文件；配置兜底值使用了真实凭据。
2. Admin 403 页样式类名以数字开头，构建时产生 CSS 语法警告。
   - 根因：`.403-container` / `.403-content` 不是合法的普通 CSS 类选择器。
3. Admin 前端路由守卫沿用了前台路由名白名单，未保护实际管理页面。
   - 根因：路由迁移后 `requiresAuth` 未同步管理后台路由。
4. AI 服务 `/admin/**` 只要求认证，没有管理员角色限制。
   - 根因：AI 服务 SecurityConfig 与主后端管理员 Controller 的 `ROLE_ADMIN` 边界不一致。
5. 文章详情对未购买付费资源仍返回 `externalLink` 和 `purchasedNote`。
   - 根因：只隐藏了 `fileUrl`，没有把外链和购买后说明纳入同一购买态判断。
6. `/uploads/resources/**` 可被静态资源路径直连，可能绕过 `/resource/download/{id}`。
   - 根因：静态资源白名单放行了整个 `/uploads/**`。
7. 资源下载服务拼接数据库中的 `fileUrl` 时没有校验 normalize 后路径仍位于上传根目录。
   - 根因：路径解析缺少目录穿越防御。
8. Admin 容器内 Nginx 代理 `/ai/` 时保留路径前缀，直连 3001 端口时 AI 管理接口可能 404。
   - 根因：`proxy_pass http://ai:8081;` 未带尾斜杠。
9. 服务器部署脚本的证书挂载目录与 Nginx 配置读取目录不一致。
   - 根因：脚本内嵌 Compose 与仓库 Nginx 配置漂移。
10. Web 前台过期 token 仍可进入受保护页面，401 后只清 token 不跳登录。
    - 根因：路由守卫只检查 token 是否存在，响应拦截器未统一跳转登录页。
11. Nginx `/api/` 同时返回 `Access-Control-Allow-Origin: *` 和 credentials。
    - 根因：Bearer Token 请求不需要 cookie credentials，但 Nginx 仍添加了 credentials 响应头。

## 修复内容

- 从 Git 索引移除 `.env`，新增 `.env.example`，并将后端、AI、Compose、部署脚本中的真实默认凭据改为环境变量或占位值。
- 新增 `scripts/run-backend-dev.ps1` 与 `scripts/run-ai-dev.ps1`，本地开发启动前自动加载根目录 `.env`。
- 修正 Admin 403 页 CSS 类名。
- Admin 路由守卫改为除 `/login`、`/403` 外全部要求登录且角色为 `admin`。
- AI 服务 `/admin/**` 改为 `hasRole("ADMIN")`。
- 主后端 `/admin/**` 也统一改为 `hasRole("ADMIN")`，形成过滤器链和方法注解双层保护。
- 未购买的付费附件不再返回 `fileUrl`、`externalLink`、`purchasedNote`。
- `/uploads/resources/**` 改为拒绝静态访问，资源文件只能通过受控下载接口返回。
- `ResourceDownloadService` 增加空 URL、资源目录前缀、normalize 后根目录校验。
- 修正 Admin 容器 Nginx `/ai/` 代理路径重写。
- 修正服务器部署脚本证书目录挂载到 `/etc/nginx/ssl`。
- Web 前台受保护路由会校验当前用户信息，401 响应会清理 token 并跳转登录页。
- 移除 Nginx `/api/` 中与通配来源冲突的 credentials 响应头。
