# 项目问题排查修复开发记录

## 基本信息

- 日期：2026-04-30
- 类型：安全整改 / Bug 修复
- 范围：前端 Admin、主后端、AI 服务、Docker/Nginx/部署配置、项目文档

## 问题与根因

1. `.env` 被 Git 跟踪，且多个配置文件存在真实形态密钥或密码默认值。
   - 根因：后续加入 `.gitignore` 不能自动取消已跟踪文件；配置兜底值使用了真实凭据。
2. Admin 403 页样式类名以数字开头，构建时产生 CSS 语法警告。
   - 根因：`.403-container` / `.403-content` 不是合法的普通 CSS 类选择器。
3. Admin 前端路由守卫沿用了前台路由名白名单，未保护实际管理页面。
   - 根因：路由迁移后 `requiresAuth` 未同步管理后台路由。
4. AI 服务 `/admin/**` 只要求认证，没有管理员角色限制。
   - 根因：AI 服务 SecurityConfig 与主后端管理员 Controller 的 `ROLE_ADMIN` 边界不一致。
5. 文章详情对未购买付费资源仍返回 `externalLink` 和 `purchasedNote`。
   - 根因：只隐藏了 `fileUrl`，没有把外链和购买后说明纳入同一购买态判断。
6. `/uploads/resources/**` 可被静态资源路径直连，可能绕过 `/resource/download/{id}`。
   - 根因：静态资源白名单放行了整个 `/uploads/**`。
7. 资源下载服务拼接数据库中的 `fileUrl` 时没有校验 normalize 后路径仍位于上传根目录。
   - 根因：路径解析缺少目录穿越防御。
8. Admin 容器内 Nginx 代理 `/ai/` 时保留路径前缀，直连 3001 端口时 AI 管理接口可能 404。
   - 根因：`proxy_pass http://ai:8081;` 未带尾斜杠。
9. 服务器部署脚本的证书挂载目录与 Nginx 配置读取目录不一致。
   - 根因：脚本内嵌 Compose 与仓库 Nginx 配置漂移。
10. Web 前台过期 token 仍可进入受保护页面，401 后只清 token 不跳登录。
    - 根因：路由守卫只检查 token 是否存在，响应拦截器未统一跳转登录页。
11. Nginx `/api/` 同时返回 `Access-Control-Allow-Origin: *` 和 credentials。
    - 根因：Bearer Token 请求不需要 cookie credentials，但 Nginx 仍添加了 credentials 响应头。

## 修复内容

- 从 Git 索引移除 `.env`，新增 `.env.example`，并将后端、AI、Compose、部署脚本中的真实默认凭据改为环境变量或占位值。
- 新增 `scripts/run-backend-dev.ps1` 与 `scripts/run-ai-dev.ps1`，本地开发启动前自动加载根目录 `.env`。
- 修正 Admin 403 页 CSS 类名。
- Admin 路由守卫改为除 `/login`、`/403` 外全部要求登录且角色为 `admin`。
- AI 服务 `/admin/**` 改为 `hasRole("ADMIN")`。
- 主后端 `/admin/**` 也统一改为 `hasRole("ADMIN")`，形成过滤器链和方法注解双层保护。
- 未购买的付费附件不再返回 `fileUrl`、`externalLink`、`purchasedNote`。
- `/uploads/resources/**` 改为拒绝静态访问，资源文件只能通过受控下载接口返回。
- `ResourceDownloadService` 增加空 URL、资源目录前缀、normalize 后根目录校验。
- 修正 Admin 容器 Nginx `/ai/` 代理路径重写。
- 修正服务器部署脚本证书目录挂载到 `/etc/nginx/ssl`。
- Web 前台受保护路由会校验当前用户信息，401 响应会清理 token 并跳转登录页。
- 移除 Nginx `/api/` 中与通配来源冲突的 credentials 响应头。

## 第二轮深度排查

### 新发现问题与根因

1. 文章详情、公告卡片、后台公告预览存在富文本直出路径。
   - 根因：多个 `v-html` 入口直接渲染后端内容，没有统一做客户端 HTML 消毒。
2. 后台旧 `/user` 管理接口未限制管理员，`GET /user/{id}` 还可能返回密码哈希字段。
   - 根因：历史 Controller 仍保留公开或仅认证边界，响应对象复用了实体模型。
3. 主后端和 AI 服务 JWT 过滤器直接信任 token 中的角色。
   - 根因：登录时写入的 `role` claim 被当作授权依据，账号降权、禁用、删除后旧 token 仍可携带旧权限；AI 服务没有主库用户表，需要通过主后端做权威用户状态校验。
4. 普通用户可创建分类和标签。
   - 根因：公开 Controller 的写接口缺少 `ROLE_ADMIN` 方法级授权。
5. 未发布文章详情可通过 `/posts/{id}` 公开读取。
   - 根因：详情查询 Mapper 未过滤 `published`，Service 层也缺少访问者身份判定。
6. 付费资源仍存在静态目录或异常 `downloadType` 绕过风险。
   - 根因：应用级静态资源目录映射过宽，资源付费判断只精确匹配 `downloadType == 1`。
7. 文章附件查询引用了不存在的 `resources.file_size` 字段。
   - 根因：Mapper XML 与现有数据库表结构漂移。
8. 分类永久删除只检查未软删文章，存在外键失败风险。
   - 根因：MyBatis-Plus 默认逻辑删除条件隐藏了已软删但仍保留外键的文章。
9. 前后端多个 API 契约漂移。
   - 根因：Admin 公告/轮播分页参数使用 `page`，后端使用 `current`；后台文章状态提交数字，后端使用字符串；前台热门排序传 `sortBy=popular`，后端使用 `sort=hot`；AI 服务最新文章参数传 `size`，后端使用 `limit`。
10. 前台收藏页缺少路由认证。
    - 根因：路由守卫的受保护页面名单漏掉 `favorites`。
11. 生产构建中仍引用 `/src/assets/...`。
    - 根因：部分组件把开发期源码路径当作运行期资源 URL。
12. 后台公告批量置顶和关键字筛选前端已接入但后端缺口，公告导入导出按钮指向未实现接口。
    - 根因：管理端页面先行开发，后端接口没有完全补齐。

### 第二轮修复内容

- Web 与 Admin 增加 `dompurify`，文章详情、文章预览、公告卡片、公告预览统一消毒后再 `v-html`。
- 旧 `/user` 管理接口补充 `@PreAuthorize("hasRole('ADMIN')")`，用户详情响应改为 `UserResp`，不再暴露 `passwordHash`。
- 主后端 JWT 认证改为回查数据库当前用户，账号禁用、删除、降权、用户名不匹配或旧 token 密码哈希不一致时拒绝注入认证上下文；授权角色以数据库当前角色为准。
- AI 服务 JWT 认证改为先本地校验签名，再携带原 token 调用主后端 `/user/current` 获取当前用户状态和角色，AI 管理接口不再信任旧 token claim。
- 分类和标签创建接口改为仅管理员可调用，并新增反射式安全回归测试覆盖。
- 公开文章详情增加发布态与作者身份校验，未发布文章只允许作者本人或后台管理详情接口读取。
- 移除上传根目录级静态映射，只公开 images/documents/music；`/resources/**` 与 `/uploads/resources/**` 均不作为静态入口。
- 资源上传和元数据更新统一校验 `downloadType`，付费判断改为 `downloadType != 0` 或 `pointsNeeded > 0` 即需要购买。
- 修正附件 Mapper 对不存在 `file_size` 字段的引用。
- 分类永久删除改用包含软删文章的 ID 查询，避免隐藏外键关系导致删除失败。
- 对齐 Admin 公告/轮播分页参数、后台文章状态枚举、Web 热门排序参数和 AI 最新文章参数。
- 收藏页加入前台认证守卫。
- 将前台默认图片、热门文章图片和移动端菜单图标改为 Vite import 资源引用，避免生产环境 404。
- 补齐公告关键字筛选和批量置顶后端接口；公告导入导出入口先禁用，避免点击后访问不存在的接口。

- AI 服务认证现在依赖主后端 `/user/current` 可用；如果未来需要降低请求时延或提高容错，应设计带短 TTL 的 token introspection 缓存，而不是回退信任 token role。
- 公告 Excel 导入导出尚未实现；当前只禁用入口避免 404，后续应单独加 Excel 依赖、模板、导入校验和导出权限测试。

- Admin 用户角色筛选、轮播批量状态接口等低频管理契约仍建议继续核对。
