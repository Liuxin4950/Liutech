## 1. 问题 / 需求概述

- 背景：上一轮实现了 TTS 双引擎和 Live2D 表情控制，但实际运行时发现三个问题：表情不生效、思考状态缺失、表情种类不足。
- 目标：修复表情事件丢失 bug，增加思考状态反馈，扩充纳西妲模型表情库，实现表情与音频同步。

## 2. 问题排查与修复

### 2.1 SSE 事件顺序导致表情丢失

**现象**：AI 回复正常，TTS 音频能播放，但 Live2D 表情始终不变。

**根因**：`AgentOrchestrator.executeStreamWithIntent()` 中事件发送顺序错误：

```
publishResponse(context, response);           // 发送 data 事件
streamPublisher.sendComplete(...);             // ⚠️ complete 事件
publishSpeechAndAvatarEvents(context, ...);    // avatar-cue 事件
emitter.complete();                            // 关闭连接
```

前端收到 `complete` 后停止监听 SSE 流，后续 `avatar-cue` 事件全部丢失。

**修复**：将 `publishSpeechAndAvatarEvents` 移到 `sendComplete` 之前。

### 2.2 TTS 播放结束后表情不恢复

**现象**：最后一段语音播完后，Live2D 停留在最后一个表情不恢复。

**修复**：在 `MainLayout.vue` 的 `playNextTts` 函数 `finally` 块中，所有音频播完后发送 `neutral` 表情 cue。

### 2.3 思考状态缺失

**现象**：用户发消息后，AI 思考期间 Live2D 无任何反馈。

**实现**：
- `chat.ts` 新增 `aiThinking` 响应式状态
- 用户发消息时设为 `true`，收到第一个 `avatar-cue` 或流结束时设为 `false`
- `MainLayout.vue` 监听 `aiThinking`，触发时应用"思考"表情（半眼 + 手势变化组合）

### 2.4 表情与音频脱节

**现象**：所有 avatar-cue 在 120ms 内被 `applyNextAvatarCues` 全部消耗，但音频还在播第一段。表情和音频完全错位。

**修复**：
- `TtsAudioItem` 新增 `cue` 字段
- `enqueueTtsAudio` 时从 `avatarCueBuffer` 取出对应 seq 的 cue，绑定到音频 item 上
- `playNextTts` 每播一段音频前，应用绑定的 cue
- `applyNextAvatarCues` 在 TTS 播放期间不消费 cue，避免冲突

### 2.5 cue 绑定后 `avatarCueNextSeq` 未推进

**现象**：`enqueueTtsAudio` 绑定 cue 时删除了 buffer 条目但没推进 `avatarCueNextSeq`，导致后续孤儿 cue 永远消费不到。

**修复**：绑定 cue 后同步推进 `avatarCueNextSeq`。

### 2.6 发新消息时旧音频不停止

**现象**：用户在 TTS 播放中发新消息，旧音频继续播放，与新回复重叠。

**修复**：
- `chat.ts` 新增 `ttsStopSignal` 计数器，`sendStreamMessage` 时递增
- `MainLayout.vue` 监听 `ttsStopSignal`，触发 `stopTtsPlayback()` 停止当前音频

### 2.7 段间表情闪回 neutral

**现象**：两段音频之间，`durationMs` 计时器触发导致表情短暂恢复默认再切换，产生闪烁。

**修复**：
- `Live2d.vue` 的 `AvatarCue` 接口新增 `skipResetTimer` 字段
- `playNextTts` 应用 cue 时传 `skipResetTimer: true`，跳过计时器
- `playNextTts` 的 `finally` 块统一处理最终 neutral 重置

## 3. 表情关键词扩充

`AvatarCueService.inferExpression()` 关键词从 ~35 个扩展到 ~150 个：

| 表情 | 旧关键词数 | 新关键词数 | 新增示例 |
| --- | --- | --- | --- |
| sad | 7 | 30 | 委屈、心酸、惆怅、泪目、惋惜 |
| angry | 6 | 28 | 抓狂、崩溃、服了、过分、忍无可忍 |
| surprised | 7 | 22 | 天哪、厉害了、震撼、万万没想到 |
| shy | 4 | 15 | 脸红、忐忑、嘿嘿、娇羞、含蓄 |
| thinking | 8 | 25 | 梳理、复盘、推敲、斟酌、琢磨 |
| question（新增） | 0 | 16 | 为什么、怎么、如何、能否、？ |
| happy | 8 | 37 | 感谢、加油、棒、牛、温暖、欣慰 |

新增**疑问类别**（`？`、`为什么`、`怎么` → thinking），让提问时也有表情变化。

## 4. Live2D 表情库扩充

### 4.1 单参数表情（6 个）

从模型参数表（`cdi3.json`）中发现多个未使用的表情参数，创建对应 exp3.json：

| 文件名 | 注册名称 | 参数 | 效果 |
| --- | --- | --- | --- |
| `Angry2.exp3.json` | 生气动画 | ParamAngry2 | 生气动画效果 |
| `StarEye2.exp3.json` | 星星眼动画 | Param19 | 星星眼动画 |
| `HandChange2.exp3.json` | 手势变化2 | Param18 | 另一个手势 |
| `MouthPout.exp3.json` | 嘟嘴 | ParamMouthForm3 | 嘴巴嘟起 |
| `MouthShape.exp3.json` | 嘴型变化2 | ParamMouthForm2 | 另一种嘴型 |
| `BrowUpDown.exp3.json` | 挑眉 | ParamBrowLY | 眉毛上下 |

### 4.2 组合表情（7 个）

多个参数同时控制，叠加产生更丰富的表情效果：

| 文件名 | 注册名称 | 参数组合 | 效果 |
| --- | --- | --- | --- |
| `Thinking.exp3.json` | 思考 | Param17 + Param24 | 手势变化 + 半眼 |
| `PoutThink.exp3.json` | 嘟嘴思考 | Param24 + ParamMouthForm3 | 半眼 + 嘟嘴 |
| `AngryFull.exp3.json` | 生气完整 | ParamAngry + ParamAngry2 + ParamMouthForm(-1) | 生气 + 动画 + 嘴型 |
| `SadFull.exp3.json` | 伤心完整 | ParamBrowLY(-1) + ParamMouthForm(-1) + Param24 | 眉毛下垂 + 嘴型 + 半眼 |
| `ShyPout.exp3.json` | 害羞嘟嘴 | ParamCheek + ParamMouthForm3 + Param24 | 脸红 + 嘟嘴 + 半眼 |
| `SurprisedFull.exp3.json` | 惊讶完整 | Param15 + Param19 + ParamBrowLY | 星眼 + 星眼动画 + 挑眉 |
| `HappyFull.exp3.json` | 开心完整 | ParamMouthForm + ParamEyeLSmile + ParamEyeRSmile + Param16 | 笑嘴 + 笑眼 + 草元素力 |

**参数值规范**：原版表情中 `ParamMouthForm`、`ParamEyeLSmile`、`ParamCheek` 等使用 0~1 范围；`Param15`~`Param25` 等自定义参数使用 30。组合表情严格参考原版数值。

## 5. 后端安全修复（代码审查发现）

| 问题 | 修复 | 文件 |
| --- | --- | --- |
| `/tts/speech` 无认证可被滥用 | `assertInternalToken` 改为 fail-closed，token 未配置时拒绝请求 | `TtsController.java` |
| SSRF：`downloadAudio` 可请求任意 URL | 新增 `isAllowedAudioHost` 校验，只允许配置的 baseUrl 和 localhost | `TtsSpeechService.java` |
| 错误信息泄露上游响应 | `siliconFlowErrorMessage` 截断到 200 字符 | `TtsSpeechService.java` |
| INFO 日志记录完整请求体 | GPT-SoVITS 请求日志改为 `debug` 级别 | `TtsSpeechService.java` |
| Semaphore(1) 并发瓶颈 | 提升到 5 个并发许可 | `TtsClient.java` |
| `.env` 缺少 TTS token | 添加 `TTS_PROXY_INTERNAL_TOKEN` 必填项 | `.env` |
