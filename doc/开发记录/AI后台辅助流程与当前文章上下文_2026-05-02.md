## 1. 问题 / 需求概述

- 背景：后台文章编辑器接入 Agent 后，写作辅助、发布和当前文章上下文体验不完整。
- 用户目标：后台看板娘能围绕当前文章做润色、标题、摘要、草稿和发布辅助；前台阅读页能总结当前文章；前端能展示 Agent 的计划与工具执行过程。
- 本次要解决的问题：写作辅助被误走创建草稿流程；总结当前文章没有读取文章详情；相关文章推荐不能利用当前文章；发布确认后表单状态不同步；前端没有把 plan/tool 事件可视化。
- 本次不解决的内容：不新增删除能力；不重做模型调度；不新增数据库表；不改 Nginx 和 Docker。

## 2. 原因定位

- 现象：在后台输入“帮我润色当前文章”会进入草稿确认，而不是返回可应用的润色内容。
- 根因 / 缺口：`AgentOrchestrator` 将 `WRITE_ARTICLE` 和 `CREATE_DRAFT` 合并处理；`SUMMARIZE` 只走普通文本生成，没有通过 `postId` 读取文章详情；Web/Admin 只消费少量结构化 SSE 事件。
- 证据：`AgentIntentClassifier` 能识别发布/润色，但 `executeTask` 中 `WRITE_ARTICLE, CREATE_DRAFT -> handleDraft`；`buildChatContext` 只传 `postId`，后端没有 `getArticleDetail` 工具链；前端只在 `article-results` 和 `agent-plan` 上做最小处理。
- 涉及模块：`LiuTech-AI` Agent 编排与工具层、`Web` 看板娘聊天、`Admin` 文章管理弹窗。

## 5. 实现内容

### 5.1 后端

- `WRITE_ARTICLE` 改为 `handleWritingAssist`：读取编辑器草稿和当前文章详情，只返回可应用的写作内容，不创建 action。
- `CREATE_DRAFT` 保持待确认动作，新生成文章首次仍只能保存为草稿。
- `SUMMARIZE` 在存在 `postId` 时调用 `public.getArticleDetail`，只基于真实文章生成总结。
- 相关文章推荐在当前文章页优先从当前文章标签、分类或标题推断查询词，并过滤掉当前文章。
- 发布/下架无法定位文章时，明确提示先打开已保存文章；确认动作仍由 `AgentActionService` 执行。

### 5.2 前端

- Web 聊天消息新增 `agentPlanSteps`、`agentToolEvents`、`confirmation` 等展示状态。
- Web 聊天体渲染 Agent 的执行过程，避免只显示“思考中”。
- Admin Agent 侧边栏展示启动意图、角色、计划和工具调用。
- Admin 发布/下架/创建草稿确认成功后回填表单状态或新草稿 ID。

### 5.3 数据库 / 配置 / 部署

- 无数据库结构变化。
- 无新增环境变量。
- 无部署和 Nginx 变化。

## 6. 安全与性能处理

- 安全影响：继续保持管理员写操作待确认；写作辅助不执行写入；当前文章详情只通过主后端公开接口读取。
- 性能影响：当前文章总结和相关文章推荐会增加一次主后端文章详情调用。
- 已采取措施：文章上下文注入模型前截断到 6000 字；主后端调用沿用现有连接/读取超时；工具调用继续审计。
- 遗留风险：前台公开文章详情接口对未发布文章的可见性仍由主后端控制；后台未保存的新文章不能直接发布，需先保存草稿。
