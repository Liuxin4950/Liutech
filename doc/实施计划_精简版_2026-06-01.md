# 博客平台实施计划 — 精简版

> 生成日期：2026-06-01
> 基于：架构师返工 + PM 参考验证
> 原则：个人博客，非企业级 SaaS

---

## 一、返工总结

### 砍掉的过度设计

| 原方案 | 砍掉理由 |
|--------|---------|
| SSR/预渲染（5-8d） | meta 标签 + sitemap 已足够，收益不值 5-8 天 |
| 支付宝/微信支付（5-8d） | 个人博客无真实货币支付需求，积分签到够用 |
| Prometheus + Grafana（2-3d） | 额外 500MB 内存 + 2-3 个容器，`docker compose logs` 够用 |
| 蓝绿部署（1-2d） | `docker compose down && up` 够用，不需要零停机 |
| CI 门禁改造（3-5d） | 个人项目不需要复杂测试门禁，编译通过即可 |
| Flyway 迁移（1-2d） | 单人项目、单 SQL 文件，无迁移冲突 |
| 微信/微博社交分享 | 开发者读者不用微信，"复制链接"够用 |
| 微信 OAuth | 需企业资质，个人开发者用不了 |
| 测试覆盖 5-8d | 只为核心路径写测试，不需要 80% 覆盖率 |
| 多角色支持 | 只有 1 个 admin，不需要 editor/author 角色 |

### 保留的高价值项

| 改进项 | 理由 | 工作量 |
|--------|------|--------|
| Live2D 懒加载 | 943KB 阻塞首屏，全站最大性能瓶颈 | 0.5d |
| 全局搜索入口 | 5/5 PM 共识的最大 UX 盲点 | 1.5d |
| 密码重置 | 有积分系统的安全底线 | 2.5d |
| JWT refresh + 自动保存 | 防止编辑内容丢失 | 1.5d |
| RSS Feed | 博客标配，传播基础 | 0.5d |
| 评论审核状态反馈 | 用户发评论后不知道是否通过 | 0.5d |
| Nginx CORS 统一 | 消除配置维护负担 | 0.5d |
| GitHub OAuth | 降低开发者注册门槛（可选） | 2d |

## 三、详细分解

### Week 1：立即开始

#### Live2D 懒加载（0.5d）
- 从 `Web/index.html` 移除 4 个同步 script 标签
- `Live2d.vue` 组件挂载时动态加载，Promise 链确保顺序
- **涉及文件**：`Web/index.html`、`Web/src/components/Live2d.vue`
- **无后端依赖，无新依赖**

#### 全局搜索入口（1.5d）
- `TheHeader.vue` 添加搜索图标
- 新建 `GlobalSearchModal.vue`（命令面板式模态框，Cmd+K）
- 后端：复用现有 `GET /posts?keyword=` 接口，或新建 `SearchController` 聚合文章+分类+标签
- **涉及文件**：`TheHeader.vue`、`GlobalSearchModal.vue`（新建）、`main.ts`
- **后端接口**：`GET /search?keyword=`（可选，现有接口已够用）

#### RSS Feed（0.5d）
- 后端：新建 `RssController.java`，复用 SitemapController 模式
- 前端：`index.html` 添加 `<link rel="alternate">` 标签
- **接口**：`GET /rss.xml`

#### Nginx CORS 统一（0.5d）
- 提取 CORS 配置到 `cors.include`，各 location 块 include 引用
- **涉及文件**：`nginx/conf.d/default.conf`、`Web/nginx.conf`、`Admin/nginx.conf`

### Week 2：用户系统完善

#### 密码重置（2.5d）
- 前端：新建 `ResetPassword.vue`（单页面，token-in-URL 流程），`Login.vue` 添加"忘记密码"链接
- 后端：`POST /user/password/reset/send` + `POST /user/password/reset/confirm`
- **DB 变更**：新增 `password_reset_tokens` 表（或复用现有字段）
- **依赖 SMTP 服务**（开发环境可用控制台输出替代）

#### JWT refresh + 自动保存（1.5d）
- 前端：`api.ts` 的 401 拦截器改为先尝试 refresh
- 后端：利用已有的 `JwtUtil.refreshToken()` 方法，暴露为 API 端点
- 自动保存：`CreatePost.vue` debounce 30s 保存草稿
- **接口**：`POST /user/token/refresh`
- **DB 变更**：可选，新增 `refresh_tokens` 表或用 JWT 自身机制

#### 评论审核状态反馈（0.5d）
- 前端：`CommentItem.vue` 显示"审核中"徽章
- 后端：`comments` 表新增 `status` 字段
- **DB 变更**：`ALTER TABLE comments ADD COLUMN status VARCHAR(20) DEFAULT 'approved'`

### Week 3：可选

#### GitHub OAuth（2d）
- 前端：登录页添加 GitHub 登录按钮
- 后端：引入 `spring-boot-starter-oauth2-client`
- **DB 变更**：`users` 表新增 `oauth_provider`/`oauth_id` 字段
- **仅限 GitHub**，不做微信（需企业资质）
