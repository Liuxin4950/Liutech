## 三、Phase 详细分解

### Phase 1：立即开始（第 1 周）

#### P1-1: Live2D 脚本懒加载
- **前端**：从 `Web/index.html` 移除 4 个同步 script 标签（~943KB），改为 `Live2d.vue` 组件挂载时动态加载
- **基础设施**：Nginx 对 live2d 目录添加长期缓存头
- **涉及文件**：`Web/index.html`、`Web/src/components/Live2d.vue`、`Web/src/layouts/MainLayout.vue`
- **风险**：全局变量 pixi/LIVE2DCUBISMCORE 必须在组件使用前加载完毕，需 Promise 链确保顺序
- **工作量**：0.5-1d

#### P1-2: 全局搜索入口
- **前端**：新建 `GlobalSearch.vue`（命令面板式模态框），`TheHeader.vue` 添加搜索图标，`main.ts` 注册 Cmd+K 快捷键
- **后端**：新建 `SearchController.java` + `SearchService.java`，聚合文章+分类+标签搜索结果
- **涉及文件**：
  - 前端：`Web/src/components/GlobalSearch.vue`（新建）、`TheHeader.vue`、`MainLayout.vue`、`main.ts`
  - 后端：`SearchController.java`（新建）、`SearchService.java`（新建）、`SecurityConfig.java`
- **接口**：`GET /search?keyword=&page=&size=`、`GET /search/suggestions?keyword=`
- **风险**：SQL LIKE 在数据量大时性能差，建议为 title/summary 添加索引
- **工作量**：前端 1.5d + 后端 1-2d

#### P1-3: Nginx CORS 统一
- **基础设施**：提取 CORS 配置到 `cors.include`，各 location 块 include 引用
- **涉及文件**：`nginx/conf.d/default.conf`、`Web/nginx.conf`、`Admin/nginx.conf`
- **风险**：if 块中的 CORS 配置无法直接 include，需仔细测试 OPTIONS 预检
- **工作量**：0.5d

#### P1-4: RSS Feed
- **前端**：`Web/index.html` 添加 `<link rel="alternate">` 标签
- **后端**：新建 `RssController.java`，复用 SitemapController 模式生成 RSS 2.0 XML
- **基础设施**：Nginx 添加 `/feed.xml` 和 `/rss.xml` 路由
- **接口**：`GET /rss.xml`（返回 `application/rss+xml`）
- **风险**：高流量下 RSS 全文输出对数据库有压力，需加缓存；建议只放 summary 不放全文
- **工作量**：前端 0.5d + 后端 0.5-1d + 基础设施 0.5d

#### P1-5: Flyway 数据库迁移
- **后端**：pom.xml 添加 `flyway-core` + `flyway-mysql`，将 sql.sql 拆分为 V1__init.sql 基线
- **基础设施**：调整 docker-compose.yml 初始化逻辑，与 Flyway 协调
- **涉及文件**：`LiuTech/pom.xml`、`application.yml`、`docker-compose.yml`、`sql/` 目录重组
- **风险**：生产库已有数据需先 baseline，Docker entrypoint 与 Flyway 可能冲突
- **工作量**：后端 1-2d + 基础设施 0.5d

### Phase 2：第 2 周

#### P2-1: 密码重置 + 邮箱验证
- **前端**：新建 `ForgotPassword.vue`、`ResetPassword.vue`，`Login.vue` 添加"忘记密码"链接，`user.ts` 新增 API 方法
- **后端**：新建 `PasswordResetService.java`、`EmailService.java`，新增 `password_reset_tokens` 和 `email_verification_codes` 表
- **涉及文件**：
  - 前端：`ForgotPassword.vue`（新建）、`ResetPassword.vue`（新建）、`Login.vue`、`user.ts`、`router/index.ts`
  - 后端：`PasswordResetService.java`（新建）、`EmailService.java`（新建）、`UserController.java`、`SecurityConfig.java`、`pom.xml`（加 mail 依赖）
- **接口**：
  - `POST /user/password/reset/send-code`（匿名）
  - `POST /user/password/reset/verify`（匿名）
  - `POST /user/email/verify/send`（需认证）
  - `POST /user/email/verify/confirm`（需认证）
- **DB 变更**：
  - `ALTER TABLE users ADD COLUMN email_verified TINYINT UNSIGNED NOT NULL DEFAULT 0`
  - 新增 `password_reset_tokens` 表
  - 新增 `email_verification_codes` 表
- **风险**：邮件发送依赖外部 SMTP 服务，验证码频率限制防滥用
- **工作量**：前端 2d + 后端 3-4d

#### P2-2: JWT Refresh Token
- **前端**：`api.ts` 的 401 拦截器改为先尝试 refresh，成功则重试原请求
- **后端**：`JwtUtil.java` 新增 refresh token 生成/验证，新增 `refresh_tokens` 表，access token 缩短为 2 小时
- **涉及文件**：
  - 前端：`Web/src/services/api.ts`、`stores/user.ts`、`services/user.ts`
  - 后端：`JwtUtil.java`、`LoginResp.java`、`UserAuthService.java`、`JwtAuthenticationFilter.java`、`TokenRefreshService.java`（新建）
- **接口**：
  - `POST /user/token/refresh`（匿名，携带 refresh token）
  - `POST /user/logout`（需认证，撤销 refresh token）
- **DB 变更**：新增 `refresh_tokens` 表
- **风险**：安全关键变更，必须前后端同步上线；refresh token rotation 增加并发复杂性
- **工作量**：前端 1.5d + 后端 2-3d

#### P2-3: 评论审核状态反馈
- **前端**：`CommentItem.vue` 显示审核状态徽章，提交评论后乐观更新显示 pending 状态
- **后端**：`comments` 表新增 `status` 字段，新建审核通过/拒绝端点
- **涉及文件**：
  - 前端：`CommentItem.vue`、`CommentSection.vue`、`comment.ts`
  - 后端：`Comments.java`、`CommentResp.java`、`CommentsService.java`、`CommentsAdminService.java`、`CommentsAdminController.java`
- **接口**：
  - `PUT /admin/comments/{id}/approve`（ADMIN）
  - `PUT /admin/comments/{id}/reject`（ADMIN）
  - `GET /comments/mine`（需认证）
- **DB 变更**：`ALTER TABLE comments ADD COLUMN status VARCHAR(20) NOT NULL DEFAULT 'approved'`
- **风险**：已有评论默认设为 approved，拒绝时应支持填写原因
- **工作量**：前端 0.5d + 后端 1-2d

---

### Phase 3：第 3 周

#### P3-1: 社交分享
- **前端**：新建 `ShareButtons.vue`，支持微信（二维码）、微博、Twitter/X
- **涉及文件**：`PostDetail.vue`、`ShareButtons.vue`（新建）、`package.json`（加 qrcode 库）
- **工作量**：1d

#### P3-2: 社交登录 OAuth
- **前端**：登录页添加 GitHub/微信登录按钮
- **后端**：引入 `spring-boot-starter-oauth2-client`，`users` 表新增 `oauth_provider`/`oauth_id` 字段
- **接口**：
  - `GET /oauth2/authorization/{provider}`
  - `GET /oauth2/callback/{provider}`
- **DB 变更**：`ALTER TABLE users ADD COLUMN oauth_provider/oauth_id`，`password_hash` 允许 NULL
- **风险**：微信 OAuth 需企业资质，个人开发者只能用 GitHub
- **工作量**：前端 1d + 后端 3-4d

#### P3-3: 文章自动保存
- **前端**：`CreatePost.vue` 监听表单变化，debounce 30s 调用保存草稿 API
- **依赖**：JWT refresh 完成（否则 token 过期会丢失内容）
- **工作量**：1d

#### P3-4: 监控告警
- **后端**：引入 Actuator + Micrometer，暴露 `/actuator/health` 和 `/actuator/prometheus`
- **基础设施**：docker-compose 添加 Prometheus + Grafana（或轻量 Uptime Kuma）
- **风险**：Prometheus + Grafana 需额外 ~500MB 内存
- **工作量**：后端 1d + 基础设施 2-3d

#### P3-5: CI 门禁改造
- **基础设施**：CI 分离 test job，先 `mvn test` 通过后再构建镜像，前端加 `npm run lint`
- **涉及文件**：`.github/workflows/deploy.yml`、`pom.xml`
- **风险**：skipTests 移除后可能暴露已有测试失败
- **工作量**：3-5d

---

### Phase 4：第 4-5 周

#### P4-1: 支付网关集成（高风险）
- **后端**：新建 `PaymentService.java`、`Order.java`、`orders` 表，支付宝/微信回调验签
- **前端**：充值页面、订单列表
- **接口**：
  - `POST /payment/create`
  - `GET /payment/status/{orderNo}`
  - `POST /payment/callback/alipay`
  - `POST /payment/callback/wechat`
- **风险**：涉及资金，必须有完善的幂等性、对账、异常处理
- **工作量**：前端 2-3d + 后端 5-8d

#### P4-2: 测试覆盖补充
- **后端**：优先覆盖认证链路、积分并发、资源下载权限
- **建议**：每个 Phase 的功能变更都附带测试，而非最后集中补充
- **工作量**：5-8d（贯穿始终）

---

### Phase 5：第 6 周+

#### P5-1: SSR/预渲染
- **前端+基础设施**：使用 Vite-SSG 对 SEO 关键页面预渲染，Nginx 调整返回静态 HTML
- **风险**：动态路由需构建时获取所有文章 URL，hydration 可能与 Live2D 冲突
- **工作量**：5-8d

#### P5-2: 蓝绿部署
- **基础设施**：使用 git SHA tag 部署，`docker compose up -d --no-deps` 逐服务滚动更新
- **依赖**：CI 门禁 + Flyway 完成
- **工作量**：1-2d

## 五、风险登记册

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|---------|
| SMTP 服务不可用 | 密码重置功能无法使用 | 中 | 提前配置 SMTP，备选方案：控制台输出验证码（开发环境） |
| JWT refresh 前后端不同步 | 用户被强制登出 | 高 | 前后端同步上线，先在开发环境充分测试 |
| 支付回调伪造 | 资金损失 | 低 | 严格验签，日志记录所有回调 |
| skipTests 移除后测试失败 | CI 阻断 | 高 | 先修复已有测试，再移除 skipTests |
| SSR 与 Live2D 冲突 | 页面渲染异常 | 中 | 用 `<ClientOnly>` 包裹 Live2D 组件 |
| 生产库 Flyway baseline 失败 | 迁移阻断 | 中 | 先在开发环境验证 baseline 流程 |
