# 当前架构

> 本文档描述 LiuTech 当前生效的总体架构，供开发与 AI 协作参考。
> 团队分析报告与改进方案见 [doc/团队反馈/](../团队反馈/)。

## 顶层模块

| 路径 | 角色 | 端口 |
| --- | --- | --- |
| `Web/` | 用户前台博客（Vue3 + TS + Vite） | 3000 |
| `Admin/` | 管理后台（Vue3 + Ant Design Vue） | 3001 |
| `LiuTech/` | 主后端 REST API（Spring Boot 3.5.6 + MyBatis-Plus） | 8080 |
| `LiuTech-AI/` | AI 服务（聊天/写作/TTS/推荐） | 8081 |
| `nginx/` | 反向代理、CORS、SSE | 80/443/81 |
| `sql/sql.sql` | MySQL 初始化（`liutech` + `liutech_ai` 两库） | 3306 |

容器内服务名通信：`backend:8080`、`ai:8081`、`mysql:3306`。完整编排见 `docker-compose.yml`。

## 后端分层（LiuTech）

`controller/{admin,web}` -> `service` -> `mapper` -> `model`，横切关注点在 `common/`、`config/`、`aspect/`、`filter/`。

- **Controller**：只做"参数接收 -> 调 Service -> 返回 Result"。异常由 `GlobalExceptionHandler` 统一兜底，认证由 `@PreAuthorize` 保证，方法内不再 try-catch 与冗余 null 检查。
- **Service**：业务逻辑所在地。
- 管理端 Controller（`/admin/**`）类级 `@PreAuthorize("hasRole('ADMIN')")`，认证在方法体执行前由 Spring Security 拦截。

## AI 服务架构（LiuTech-AI）

`controller/{,admin}` -> `service`，横切 `common/{client,mcp,tts,monitor,utils}`、`infra/{config,security,filter,exception,aspect}`。

- **聊天模式**（`/ai/chat`，permitAll 支持游客）：注册 `BlogMcpTools`（公开博客查询/搜索/推荐）
- **写作模式**（`/ai/writing`，hasRole('ADMIN')）：注册 `WritingTools`（分类/标签/读文章）
- **写作助手**：前端传 `draft`（`AdminArticleDraftSnapshot`：标题/正文/摘要/分类/标签），`PromptService` 注入为不可信上下文，使用写作专用系统提示词（与看板娘人设隔离）
- **SSE 流式**：`StreamingChatService`，事件 `start`/`data`/`avatar-cue`/`audio`/`article-results`/`complete`
- **TTS**：分段合成，`/tts/speech` 代理（`TTS_PROXY_INTERNAL_TOKEN` 跨服务一致）
- **安全**：prompt injection 防护（不可信内容边界包裹）、JWT 跨服务校验（调主后端 `/user/current`，60s 缓存）、Resilience4j 熔断 + 限流 + Spring Retry

## 跨服务集成约束

- `JWT_SECRET`：backend 与 ai **必须完全一致**
- `TTS_PROXY_INTERNAL_TOKEN`：backend 与 ai **必须一致**
- `BLOG_API_URL`：Docker 内 `http://backend:8080`，本地 `http://localhost:8080`
- JDBC URL 必须含 `allowPublicKeyRetrieval=true`（兼容 MySQL 8 认证）
- 文件上传：容器内 `/app/uploads` 绑定宿主机 `/liuxin/uploads`；**不要**用 `docker compose down -v`（清空 `mysql_data` 卷）
- SSE：Nginx 必须 `proxy_buffering off;` 并提高 `proxy_read_timeout`；**不要**给非 SSE 路径加 `Accept: text/event-stream`（破坏 JSON 响应 406）

## 部署

- Docker Compose 编排 6 服务（mysql/backend/ai/web/admin/nginx）
- 生产应仅暴露 nginx 的 80/443/81，其余服务走 Docker 内网（当前 compose 仍暴露全部端口，属待修技术债，见 [04-运维工程师](../团队反馈/04-运维工程师.md)）
- HTTPS 证书（生产）：`/opt/liutech/nginx/liuxin.chat_bundle.crt` 与 `liuxin.chat.key`
- 环境变量从根目录 `.env` 注入；`.env.example` 是模板，生产替换为强密钥
