## 1. 本次变更概览

- 变更目标：把一次问答式 AI 助手升级为可规划、可调用工具、可确认执行的博客智能看板娘 Agent。
- 核心能力：文章搜索/推荐结构化返回、管理员写作辅助、草稿创建、发布/下架确认、Agent 任务与 action 审计。
- 影响范围：AI 服务、主后端文章管理接口、Admin 文章编辑器、Web AI 类型契约、AI 数据库脚本。
- 不影响范围：旧 `/ai/chat`、旧 `/ai/recommend`、文章删除、部署拓扑。

## 4. 核心类、组件与职责变化

- 接口入口：`AgentChatController` 提供 `/chat` 和 `/stream`，`AgentActionController` 提供确认 action。
- 业务服务：`AgentOrchestrator` 负责任务编排，`AgentIntentClassifier` 负责轻量意图识别，`AgentPlanService` 生成计划，`AgentToolCallRecorder` 记录工具调用。
- 数据访问：`AgentTaskMapper`、`AgentActionMapper`、`AgentToolCallMapper` 写入任务、确认动作和工具调用记录。
- 前端页面 / 客户端：`PostsManagement.vue` 提供编辑器上下文，`AdminAgentSidebar.vue` 渲染 Agent 工作区。
- 可复用组件：结构化文章结果已被 Web 看板娘用于可点击文章卡片，确认卡片用于 Admin 写操作。
- API 调用层：`PublicArticleTool` 调用公开博客查询并做短 TTL 缓存；`AdminBlogClient` 透传管理员 token 调主后端管理接口并设置超时。


## 6. 数据模型与状态流转变化

- 新增字段 / 表：
  - `ai_agent_task`：记录 Agent 任务状态。
  - `ai_agent_action`：记录待确认和已执行的管理员动作。
  - `ai_agent_tool_call`：记录工具调用结果，供后续审计和性能分析。
  - `ai_chat_message` 补齐 `user_id`、`metadata`、`updated_at`。
- 状态枚举：
  - `AgentTaskStatus`: `PLANNING`、`RUNNING`、`WAITING_CONFIRMATION`、`COMPLETED`、`FAILED`、`CANCELLED`。
  - `AgentActionStatus`: `PENDING`、`CONFIRMED`、`EXECUTED`、`FAILED`、`EXPIRED`。
  - `AgentActionType`: `CREATE_DRAFT`、`UPDATE_DRAFT`、`PUBLISH_POST`、`OFFLINE_POST`。
- 数据创建路径：用户发起 Agent 请求时创建 task；写操作创建 pending action。
- 数据更新路径：只读任务完成后更新 task；管理员确认后更新 action 执行结果。
- 数据删除或失效路径：本期不删除 Agent 记录；pending action 20 分钟后视为过期。
- 兼容旧数据方式：新增表不影响旧聊天；已有数据库通过迁移脚本补表和字段。

## 7. 权限与安全变化

- 登录态：只读 Agent 能力允许匿名访问；写入确认必须登录。
- 角色权限：写操作由后端确认当前用户 `isAdmin()`，不信任前端按钮状态。
- 数据归属：用户只能确认自己发起的 pending action。
- 输入校验：Agent message 限制 4000 字；管理员草稿快照限制标题、正文、摘要、标签和图片地址长度。
- 敏感信息：AI 服务只透传 Bearer Token 到主后端，不记录 token。
- 文件 / 富文本 / AI 输出：AI 生成文章只能先存草稿；发布前必须管理员确认。

## 8. 性能与缓存变化

- 查询路径：搜索和推荐复用现有主后端文章列表能力。
- 索引：Agent 表按用户、状态、任务和创建时间建立索引。
- 分页：公开文章工具限制单次返回 1 到 8 条。
- 缓存：公开文章工具对搜索、最新、热门文章结果做短 TTL 内存缓存，默认 60 秒。
- 长连接 / 线程池：SSE 沿用 Spring `SseEmitter`；流式入口先发 start/plan，再执行模型或工具，改善首包体验。
- 前端加载：Admin 侧边栏按事件增量渲染计划、文本和确认卡片；Web 聊天按 `article-results` 增量挂载文章卡片。

## 9. 部署与配置变化

- 环境变量：无新增必填环境变量；可通过 Spring 配置覆盖 `spring.ai.agent.tool-cache-ttl-ms`、`spring.ai.agent.max-article-results`、`spring.ai.agent.blog-connect-timeout-ms`、`spring.ai.agent.blog-read-timeout-ms`。
- Docker：无新增服务。
- Nginx：沿用 `/ai/` 代理到 AI 服务，并保留 `/ai` 前缀；AI 服务对需要兼容的管理接口提供 `/ai/admin/**` 别名。
- CI/CD：无新增流水线。
- 数据库迁移：当前权威结构已合并到 `sql/sql.sql`；已有数据库按该文件与线上库差异补齐 Agent 表结构。

## 10. 对总体架构的影响

- 模块边界：AI 服务新增 `agent` 领域边界，新功能不再堆入旧 `service`。
- 数据流：AI Agent 写操作统一经主后端 API，不直接写主业务库。
- 接口协议：新增结构化 SSE 事件和 `ArticleResultItem` 文章卡片契约。
- 权限模型：普通用户只读；管理员写操作需要 pending action 和确认。
- 部署拓扑：不改变服务拓扑和端口。

## 11. 后续演进建议

- 将旧 AI 聊天、模型、TTS、博客上下文逐步迁移到实现 PRD 中规划的领域包，避免一次性大重构。
- 增加 Agent 工具超时、步骤上限配置、短 TTL 缓存和工具调用耗时统计。
- Web 前台看板娘可复用 `article-results` 契约渲染文章卡片。
- 引入 RAG 或语义搜索前，先沉淀文章切片、索引刷新和权限过滤方案。
- 如果未来确实改用 Python/LangChain，保留当前 Java AI 服务作为网关和权限/审计边界会更稳。
