## 1. 问题 / 需求概述

- 背景：现有 AI 写作助手流程过于复杂（生成草稿 → 展示卡片 → 用户点"应用" → 写入表单），需要 5 步操作。
- 用户目标：管理员发送消息后 AI 直接写入表单字段，不需要手动"应用"；不满意可回退。
- 本次要解决的问题：去掉草稿中间层，AI 直接写入字段；新增底部回退栏；合并后端逻辑（保留 URL 隔离）。
- 本次不解决的内容：不合并前端 UI（Admin 和 Web 布局不同）、不改变普通聊天体验、不做多轮上下文。

## 2. 原因定位

- 现象：用户需要点击"应用全部"才能把 AI 生成的内容写入表单，操作繁琐。
- 根因 / 缺口：设计时采用了"草稿 → 应用"两步模式，前端有独立的草稿卡片和应用按钮。
- 证据：`AdminAgentSidebar.vue` 和 `AdminWritingAssistant.vue` 均有 `writingDraft`、`applyWritingDraft`、`apply` 等逻辑。
- 涉及模块：AI 服务（AgentOrchestrator、AgentChatController）、Admin 前端、Web 前端。

## 5. 实现内容

### 5.1 后端

- 新增 `FieldUpdatePayload`：只包含 title、summary、contentHtml、categoryId、tagIds 等被修改的字段，null 表示不修改。
- `AgentOrchestrator.handleWritingAssist()` 改为构建 `FieldUpdatePayload` 并设置到 `AgentChatResponse.fieldUpdate`。
- `AgentOrchestrator.handleWritingAssist()` 会根据 `context.requestedFields` 或用户话术推断本次可修改字段，只把允许字段放进 `field-update`；例如“增加几个标签”只返回合并后的 `tagIds`，不会返回正文、标题或摘要。
- `publishResponse()` 新增 `field-update` SSE 事件发送。
- `executeAdminStream()` 通过 `isAdminWritingContext()` 判断是否为写作场景（`context.page == "admin-post-editor"`），自动使用 WRITE_ARTICLE 意图。
- Web `/create` 与 Admin 文章编辑器统一传递 `context.page == "admin-post-editor"`；后端兼容历史 `web-create-post`，避免快捷提示词误判成发布/下架等非写作意图。
- `AdminAgentChatController` 保留，简化为直接调用 `executeAdminStream`，URL 隔离不变。
- AI 输出的分类/标签 ID 只作为候选值，后端必须回查真实分类/标签列表；不存在的 ID 会被丢弃并降级为建议名称，不直接写入表单。
- 写作 HTML 进入正文/摘要生成前会先执行 `stripWritingPreamble()`，剔除模型开场白、工具说明和“先获取分类标签”等执行旁白，防止摘要出现非文章内容。
- `AgentToolExecutionService` 对 `admin.generateWritingHtml` 的 tool-result 只返回“已生成富文本 HTML”，不再把 HTML 正文片段放入 `resultSummary`。
- 写作结果末尾的分类/标签 JSON 元数据兼容 fenced code block 和松散 `json\n{...}` 两种形态；解析成功后会从 HTML 正文中剥离。
- 当只得到建议分类/标签名称、没有真实 ID 时，后端仍发送 `field-update`，但不写入不存在的 ID；前端需要管理员确认创建后才真正新增字典项。
- `chatForWriting()` 改用流式调用（`.stream()` + `.collectList().block()`），不注册 MCP 工具，避免 RestClient 90s 超时。
- 意图分类器扩充 WRITE_ARTICLE 关键词：新增"整理"、"富文本"、"丰富"、"优化内容"、"改进文章"等。
- SSE timeout 从 180s 提升到 300s，async timeout 从 120s 提升到 300s。

### 5.2 前端

- Admin 和 Web 的 service 层新增 `FieldUpdatePayload` 类型和 `onFieldUpdate` handler。
- `AdminAgentSidebar` 和 `AdminWritingAssistant`：移除草稿卡片、应用按钮、`applyWritingDraft`/`apply` 方法。发送请求时附带 `requestedFields` / `appendTags`；消费 `onWritingDraft` 和 `onFieldUpdate` 时按同一字段白名单过滤后再 emit，作为兼容事件的第二道保护。
- Web/Admin 写作执行过程改为紧凑进度卡：只显示当前阶段、最近几个阶段和最近工具摘要；完成后隐藏流程卡，避免移动端长日志撑开页面。
- `PostsManagement` 和 `CreatePost`：新增 `handleFieldUpdate()` 直接写入表单字段（DOMPurify 消毒 content），新增 `undoStack` 和 `undoField()` 回退逻辑，新增底部悬浮回退栏。
- `PostsManagement` 和 `CreatePost` 只应用非 null 字段；分类必须有真实 ID，标签必须有非空 ID 列表，避免 AI 未匹配时清空已有分类/标签。
- `CreatePost` 和 `PostsManagement` 支持 AI 建议分类/标签：已有名称会直接选中，不存在的名称展示“创建并选中”按钮；点击后调用现有分类/标签创建接口并写入当前表单。
- Web 创建页分类列表加载完整分类，避免 AI 已匹配真实分类 ID 但前端下拉只加载前几项导致显示不上的问题；分类和标签建议同时存在时支持一键处理全部建议。
- Web `/create` 的回退入口并入底部工具栏；标题输入使用明确卡片背景和聚焦态，和页面其他编辑区域保持一致。
- 文章详情页代码块明确设置 `pre/pre code/token` 的背景和文字色，避免 Prism 默认主题或 CSS 变量组合造成黑底黑字。

### 5.3 数据库 / 配置 / 部署

- 数据库：无结构变化。
- 配置：SSE timeout 和 async timeout 调整。
- 部署：Nginx 路由不变，`/ai/admin/agent/**` 仍指向 AI 服务。

## 6. 安全与性能处理

- 安全影响：AI 生成的 HTML 仍通过 DOMPurify 消毒后写入表单，与之前一致；AI 生成的分类/标签 ID 不可信，必须在后端用真实列表校验。
- 权限风险：管理员接口仍通过 `/ai/admin/**` 安全规则保护。
- 性能影响：chatForWriting 使用流式调用避免超时，无额外性能开销。
