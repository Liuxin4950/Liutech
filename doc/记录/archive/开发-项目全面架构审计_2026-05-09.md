## 2. 后端架构问题

### 高优先级

| # | 问题 | 位置 | 说明 |
|---|------|------|------|
| B-1 | 父 POM Spring Boot 版本冲突 | `pom.xml` | 3.5.9 vs 3.5.6 vs 3.5.4 混用，应移除 dependencyManagement 中的手动版本覆盖 |
| B-2 | `allow-circular-references: true` | `application.yml:7` | 掩盖循环依赖，应逐个解决（OperationLogAspect 用事件驱动，MyMetaObjectHandler 用 @Lazy） |
| B-3 | PostsService 超过 1300 行 | `PostsService.java` | 应拆分为 PostCrudService、PostInteractionService、PostQueryService、PostAdminService |
| B-4 | JWT 白名单重复维护 | `SecurityConfig.java` + `JwtAuthenticationFilter.java` | 两处独立维护公开路径列表，不同步会导致安全漏洞 |
| B-5 | AI 服务每次请求 RPC 调用主后端 | `LiuTech-AI/.../JwtAuthenticationFilter.java:126` | 主后端不可用时 AI 全部 401，应加降级策略 |

### 中优先级

| # | 问题 | 位置 | 说明 |
|---|------|------|------|
| B-6 | 内存缓存无容量限制和 TTL | `CacheConfig.java` | ConcurrentMapCacheManager 无上限，长期运行可能内存泄漏，应换 Caffeine |
| B-7 | AI 异常响应格式不一致 | LiuTech-AI GlobalExceptionHandler | AI 用 Map，主后端用 Result，前端需处理两种格式 |
| B-8 | Controller 层自行 try-catch | PostsController 等 | 绕过 GlobalExceptionHandler 和 @OperationLog 切面 |
| B-9 | 读操作 @Transactional 未设 readOnly | PostsService 等 | 性能损失，Hibernate 会做脏检查 |
| B-10 | 站点 URL 硬编码 | `PostsService.java:59` | `PUBLIC_SITE_BASE_URL = "https://liuxin.chat"` 应从配置读取 |
| B-11 | 逻辑删除值配置不一致 | 主后端用 `"NOW()"`/`"NULL"`，AI 用 `1`/`0` | 跨模块行为不一致 |
| B-12 | JwtUtil 完全重复 | 两个模块各有一份 | 应提取到共享模块 |
| B-13 | RequestTraceFilter 完全重复 | 两个模块各有一份 | 应提取到共享模块 |
| B-14 | 暴力破解防护用内存 Map | `UserAuthService.java` | 重启失效，多实例不共享，应改 Redis 或数据库 |

### 低优先级

| # | 问题 | 说明 |
|---|------|------|
| B-15 | ErrorCode 混合 HTTP 状态码和业务码 | 前端判断逻辑复杂 |
| B-16 | CheckinService 返回 Result 而非业务对象 | 违反分层原则 |
| B-17 | 废弃方法 likePost() 未清理 | 代码卫生 |
| B-18 | JJWT 0.11.5 过时 | 应升级至 0.12.x |
| B-19 | TransactionConfig 允许嵌套事务 | 数据一致性风险 |
| B-20 | AI 模块 pom.xml 版本号末尾多余连字符 | `0.0.1-` 应为 `0.0.1` |
