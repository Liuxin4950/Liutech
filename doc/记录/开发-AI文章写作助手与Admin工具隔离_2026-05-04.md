## 1. 问题 / 需求概述

- 背景：现有 Agent 能聊天和做少量文章辅助，但不能真正形成文章写作闭环。
- 用户目标：管理员输入一句话后，AI 能生成标题、摘要、TinyMCE HTML 正文、分类标签建议，并可一键填入 Admin/Web 编辑器。
- 本次要解决的问题：管理员 AI 与普通 AI 路径隔离；结构化写作草稿；SSE 进度利用；Admin 分类标签快捷创建；Web 创建页接入管理员写作助手。
- 本次不解决的内容：不自动删除、不管理用户/角色、不自动生成并上传封面图、不改数据库表。

## 2. 原因定位

- 现象：AI 回复偏自然语言，不能自动填标题、摘要、正文、分类、标签。
- 根因 / 缺口：缺少结构化 `writing-draft` 契约；Admin 写作仍走公共 `/ai/agent/**`；前端缺少写作草稿卡片和应用动作。
- 证据：`AgentChatResponse` 只有 `message/articleResults/confirmation`；Admin service 调用 `/ai/agent/stream`；Web `/create` 未接入写作助手。

## 5. 实现内容

### 5.1 后端 / AI 服务

- 新增管理员专用 Agent 路径，由现有 `/ai/admin/**` 安全规则保护。
- `AgentOrchestrator` 为管理员写作生成 `WritingDraftPayload`，包含标题、摘要、`contentHtml`、分类/标签、建议新分类/标签、封面提示词、检查项。
- SSE 响应新增 `writing-draft` 事件，前端无需从自然语言解析字段。
- 写作提示词明确要求 TinyMCE HTML，禁止 Markdown、script、iframe、style 和事件属性。
- 通过 `AdminBlogClient` 读取主后端分类/标签列表，只匹配真实 ID；不存在的分类/标签仅作为建议名称。
- 写作流程读取分类、读取标签、生成 HTML 均通过 `tool-start` / `tool-result` 暴露给 SSE，而不是只在后端同步内部执行。

### 5.2 前端

- Admin 文章弹窗右侧侧边栏展示结构化草稿，可应用全部、标题、摘要、替换正文、追加正文、分类标签。
- Admin 文章弹窗新增分类/标签快捷创建按钮，创建后立即刷新并选中。
- Web `/create` 在 admin 用户身份下显示 `AdminWritingAssistant`，可使用同一管理员 AI 接口生成并应用草稿。
- Web 应用 AI 正文前使用 DOMPurify 消毒。
- Admin 应用 AI 正文前也使用 DOMPurify 消毒，避免 AI HTML 进入文章表单时形成持久化 XSS 风险。
- Web 全局看板娘聊天默认调用公共 `/ai/agent/stream`；登录用户为 `admin` 时才切到 `/ai/admin/agent/stream`。
- 普通用户/游客即使收到 Agent 过程事件也不展示 plan/tool/confirmation，保持原来的“思考中 -> 回复”体验；管理员才可看见执行过程。
- 根据浏览器反馈，Web 全局聊天中的执行过程只作为流式执行中的临时状态：`CHAT` 不展示执行过程，流式完成后自动隐藏执行过程，避免完成后的消息残留 `running/pending` 调试状态。
- 当前文章页带 `postId` 时，`这篇文章讲了啥/总结这篇文章` 等话术优先识别为 `SUMMARIZE`，避免误走文章搜索并返回“找不到匹配文章”。
- Web `/create` 写作助手的执行过程改为本地渐进状态机：初始只显示当前步骤，收到 tool/data/writing-draft/complete 后推进到下一步；状态文案统一为中文。
- Web `/create` 写作助手应用草稿后显示成功反馈；`应用全部` 会清除生成草稿卡片，避免用户误以为没有生效。

### 5.3 数据库 / 配置 / 部署

- 数据库：无结构变化。
- 配置：无新增环境变量。
- 部署：无 Nginx / Docker 变化，沿用 `/ai/` 前缀代理。

## 6. 安全与性能处理

- 安全影响：管理员写作接口独立到 `/ai/admin/agent/**`，普通用户不能调用；写操作仍保留确认。
- 富文本风险：模型 HTML 被视为不可信，后端做基础过滤，Web/Admin 应用时 DOMPurify 消毒。
- 权限风险：公共 `/ai/agent/**` 仍可聊天和只读，管理员写作工具改用 admin 路径。
- 性能影响：长文生成会增加 token 和 SSE 时间；当前限制上下文长度并沿用 SSE 超时。
- 遗留风险：Admin 前端应用正文目前没有额外 DOMPurify，建议后续补齐与 Web 一致的应用前消毒。
