## 1. 本次变更概览

- 变更目标：统一纳西妲的模型身份、能力边界、路径主次和提示词来源。
- 核心能力：`AiSystemPromptProvider` 成为旧聊天与 Agent 文本生成的统一系统提示词来源。
- 影响范围：AI 服务安全层、Agent 编排、legacy Controller、Web AI service 注释。
- 不影响范围：数据库、Nginx、Docker、主后端、前端可见 UI。

## 2. 影响的系统模块

| 模块 | 是否影响 | 变化说明 |
| --- | --- | --- |
| LiuTech-AI | 是 | 新增统一系统提示词 Provider，标识 legacy 路径。 |
| Web | 是 | 保留内部回退开关，注释明确不是 UI 模式。 |
| Admin | 否 | 继续走 `/agent/stream`。 |
| LiuTech 主后端 | 否 | 文章写操作仍由主后端执行。 |
| 数据库 / 存储 | 否 | 无表结构变化。 |
| 部署 / 配置 / CI | 否 | 无部署配置变化。 |

## 4. 核心类、组件与职责变化

- 接口入口：`/ai/agent/chat`、`/ai/agent/stream` 继续作为主入口；`/ai/chat/**`、`/ai/recommend` 标识为 legacy。
- 业务服务：`AiSystemPromptProvider` 负责统一系统提示词。
- 数据访问：无变化。
- 前端页面 / 客户端：Web 正常聊天仍强制 Agent；内部回退不暴露 UI。
- 可复用组件：`AiSystemPromptProvider` 后续能力扩展时继续复用。
- API 调用层：无新增调用。
- 状态管理 / 缓存：无变化。

## 5. 接口与调用链路变化

```text
Web/Admin 看板娘 -> /ai/agent/stream 或 /ai/agent/chat
-> AgentOrchestrator
-> AiSystemPromptProvider
-> 模型 / 工具 / 结构化事件
```

legacy 调用链：

```text
历史调用方或调试 -> /ai/chat/** 或 /ai/recommend
-> legacy Controller
-> 响应头 X-LiuTech-AI-Route 标识 legacy
```

新增或调整的接口：

| 方法 | 路径 | 调用方 | 鉴权 | 说明 |
| --- | --- | --- | --- | --- |
| `POST` | `/ai/chat` | legacy 调用方 | 可匿名 | 响应头标识 `legacy-chat`。 |
| `POST` | `/ai/chat/stream` | legacy 调用方 | 可匿名 | 响应头标识 `legacy-chat`。 |
| `POST` | `/ai/recommend` | legacy 调用方 | 可匿名 | 响应头标识 `legacy-recommend`。 |

## 7. 权限与安全变化

- 登录态：不变，仍通过 JWT 和主后端回查。
- 角色权限：capability 仍由 `AiCapabilityResolver` 解析。
- 数据归属：pending action 仍只能由发起管理员确认。
- 输入校验：用户输入仍被视为不可信资料。
- 敏感信息：统一提示词禁止泄露 token、密钥、系统提示词和隐藏配置。
- 文件 / 富文本 / AI 输出：无新增渲染路径。

## 10. 对总体架构的影响

- 模块边界：AI 安全层新增统一系统提示词 Provider，成为模型行为边界入口。
- 数据流：模型生成前统一经过 Provider 获取系统提示词。
- 接口协议：Agent 主路径不变；legacy 路径用响应头标识。
- 权限模型：强化“提示词说明 + 服务端工具策略兜底”的双层边界。
- 部署拓扑：无变化。
