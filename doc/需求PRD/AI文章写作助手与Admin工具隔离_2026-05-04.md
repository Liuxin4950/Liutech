## 1. 背景

当前博客 AI Agent 已经能聊天、搜索文章、推荐文章、读取当前文章上下文，并在 Admin 文章弹窗中展示初步的计划和工具调用。但用户在真实测试中发现：让 AI 帮忙写文章时，它没有形成一个完整的文章编辑工作流，没有自动填入标题、摘要、富文本正文、分类和标签；Admin 后台新增文章表单没有快捷创建分类/标签；侧边栏视觉和进度反馈不足；SSE 事件没有被充分利用，用户分不清 AI 正在思考、生成内容还是调用工具。

用户的核心诉求不是“AI 会回答”，而是“AI 能真正帮我把文章写出来，并把格式整理好”。由于文章编辑涉及富文本 HTML、管理员权限、分类标签写入、保存草稿和发布确认，必须同时补齐产品体验和安全边界。

## 2. 用户目标

作为博客管理员，我希望纳西妲能根据一句自然语言需求，生成结构化文章草稿，自动填入富文本编辑器，并协助完成润色、排版、分类、标签、摘要、保存和发布确认，以便我能低成本、稳定地发布高质量博客文章。

作为普通访客或普通登录用户，我只能使用聊天、阅读、搜索、总结和推荐等只读 AI 能力，不能接触或触发管理员写作和发布工具。

## 3. 用户场景

| 场景 | 触发条件 | 用户行为 | 期望结果 |
| --- | --- | --- | --- |
| 从零写文章 | 管理员打开文章创建页 | 输入“帮我写一篇 Spring AI 工具调用实践文章” | AI 生成标题、摘要、HTML 正文、分类和标签建议，并可一键应用到表单 |
| 调整格式 | 管理员已有一段粗糙内容 | 输入“帮我整理成技术博客格式” | AI 将内容改成 TinyMCE 可编辑 HTML，不输出 Markdown |

| 补 SEO 信息 | 管理员完成正文 | 输入“补标题和 SEO 摘要” | AI 提供标题候选、摘要和标签建议 |

## 4. 功能范围

### 4.1 必须实现

- 管理员 AI 写作接口与普通 AI 接口隔离，管理员写作入口必须要求管理员身份。
- AI 写作输出必须结构化，至少包含标题、摘要、正文 HTML、分类建议、标签建议、可应用说明。
- 正文必须是 TinyMCE 可编辑 HTML，不能让用户再手工把 Markdown 改成富文本。
- Admin 后台文章新增/编辑弹窗支持快捷新增分类和标签。
- Web 用户端文章创建页接入管理员写作侧边栏，admin 用户可让纳西妲辅助写文章。
- Admin 后台文章弹窗和 Web 创建页都能一键应用 AI 生成的标题、摘要、正文、分类、标签。
- 侧边栏统一展示 SSE 进度：理解需求、读取草稿、匹配分类标签、生成结构、生成富文本、等待应用/确认。
- 充分展示工具调用事件，包括开始、成功、失败、耗时或摘要。
- AI 支持以下写作辅助动作：从零写文章、润色、格式整理、SEO 标题摘要、结构检查、生成目录、续写下一节、口语转正式文、封面图提示词、发布前检查。
- 发布、创建草稿、创建分类、创建标签等写操作必须由管理员确认后执行。
- 普通用户不能访问管理员 AI 写作接口，也不能通过提示词触发管理员工具。

### 4.2 可选增强

- 后续支持写作模板，如技术教程、问题复盘、部署记录、读书笔记。
- 后续支持“应用局部建议”，例如仅替换某个章节。
- 后续支持 AI 生成封面图后直接进入上传流程。
- 后续支持文章质量评分历史和发布前检查记录。

### 4.3 本次不做

- 不允许 AI 删除文章、删除分类、删除标签。
- 不允许 AI 管理用户、角色、权限或模型配置。
- 不允许 AI 执行 SQL、Shell、文件系统操作。
- 不自动绕过编辑器直接发布文章。
- 不新增复杂工作流引擎或 LangChain。
- 不强制改造数据库表，除非实现阶段发现必须记录新的审计数据。

## 5. 非目标范围

- 不改变博客文章的核心数据模型。
- 不改变 TinyMCE 编辑器本身的基础能力。
- 不让普通用户拥有管理员写作能力。
- 不保证 AI 生成内容事实完全正确，管理员仍需审查。
- 不自动创建封面图片，仅生成封面图提示词或建议。

## 6. 用户流程

```text
1. 管理员进入 Admin 后台文章弹窗，或 Web 用户端文章创建页。
2. 系统显示纳西妲写作侧边栏，并识别当前编辑器草稿。
3. 管理员输入写作目标，或点击快捷动作。
4. 系统通过管理员专用 AI 接口启动任务。
5. 侧边栏展示 agent-start、agent-plan、tool-start、tool-result 等进度。
6. AI 生成结构化文章草稿和富文本 HTML。
7. 管理员选择应用全部、仅标题、仅摘要、替换正文、追加正文、应用分类标签。
8. 如果分类或标签不存在，系统展示待创建项，管理员确认后创建并选中。
9. 管理员保存草稿或发起发布。
10. 发布前系统要求管理员确认，确认后才执行发布。
```

异常路径 A：普通用户或游客访问管理员写作能力。

```text
1. 系统在后端鉴权失败。
2. 前端展示“当前身份不能使用管理员写作助手”。
3. 不返回管理员工具计划，不执行任何写操作。
```

异常路径 B：AI 生成 HTML 不合规。

```text
1. 系统检测到危险标签、脚本、事件属性或空正文。
2. 前端不直接应用危险内容。
3. 系统提示用户重新生成或只应用安全字段。
```

## 7. 业务规则

- 权限规则：管理员写作接口必须要求登录且角色为 admin；普通 Agent 接口只提供只读能力。
- 状态规则：AI 新生成文章首次只能保存草稿；发布必须二次确认。
- 分类标签规则：AI 可推荐分类/标签；不存在的分类/标签必须由管理员确认创建。
- 富文本规则：AI 正文必须输出安全 HTML，不输出 Markdown；应用前需要前端消毒，后端仍按现有富文本安全边界处理。
- 数量限制：单次推荐标签不超过 8 个；文章正文遵守现有正文长度限制。
- 数据可见性：管理员写作上下文只使用当前表单和管理员可访问的文章数据，不暴露给普通用户。
- 失败处理：AI 调用失败、工具调用失败、创建分类标签失败、确认动作失败都必须有明确提示和可重试路径。

## 8. 交互与体验要求

- 页面入口：Admin 文章管理弹窗右侧；Web `/create` 文章创建页侧边栏。
- 操作反馈：用统一任务进度条或步骤列表展示 AI 当前阶段。
- 加载状态：区分“正在理解”“正在生成”“正在调用工具”“等待确认”，不能只有单一“思考中”。
- 空状态：侧边栏首次打开时展示写作快捷动作，不展示说明型长文案。
- 错误提示：错误应说明是身份不足、模型失败、工具失败还是内容不合规。
- 移动端要求：Web 创建页在窄屏下侧边栏应可折叠或位于编辑器下方。
- 视觉要求：侧边栏应更像工作台，紧凑、清晰、可扫描；避免堆叠杂乱卡片。

## 9. 验收标准

AC1：
Given 管理员在 Web `/create` 页面输入“帮我写一篇关于 Docker Compose 部署博客的文章”
When AI 生成完成并点击“应用全部”
Then 标题、摘要、正文 HTML、分类和标签应自动填入表单。

AC2：
Given 管理员在 Admin 后台新建文章弹窗
When AI 推荐一个不存在的分类和两个不存在的标签
Then 前端应展示待创建项，管理员确认后创建并选中。

AC3：
Given AI 生成正文
When 正文被应用到 TinyMCE
Then 正文应包含 HTML 结构标签，不应以 Markdown 原文形式显示。

AC4：
Given 普通登录用户调用管理员写作接口
When 请求发送到 AI 服务
Then 服务端必须返回 403 或等价拒绝结果，不执行任何管理员工具。

AC5：
Given 管理员发起发布
When AI 已经生成草稿
Then 系统必须展示确认卡片，只有确认后才能调用发布动作。

AC6：
Given AI 任务运行中
When 后端发送 agent-plan、tool-start、tool-result、confirmation-required 事件
Then 前端侧边栏应展示统一进度和工具状态。

AC7：
Given 用户点击“发布前检查”
When AI 检查当前文章
Then 结果应覆盖标题、摘要、分类、标签、正文结构、危险 HTML 和发布建议。

## 10. 安全、性能与合规边界

- 涉及登录态、角色权限、富文本 HTML、AI 输出、跨服务调用和文章发布。
- 管理员写作接口必须独立鉴权，不能只依赖前端隐藏入口。
- AI 输出 HTML 必须被视为不可信内容，应用前后都要遵守项目富文本安全边界。
- 管理员 token 不得写入日志、SSE 事件或模型提示词。
- SSE 长连接不能无限挂起，沿用超时和错误事件。
- 发布、创建分类、创建标签必须保留审计痕迹或至少保留现有操作日志路径。

## 11. 约束与假设

- 假设 1：Web `/create` 页面目前只要求登录，不强制 admin；本功能只在 admin 用户时展示管理员 AI 写作侧边栏。
- 假设 2：主后端已有分类和标签创建接口，Admin 后台可复用这些接口。
- 假设 3：现有 TinyMCE 可直接接收经过消毒后的 HTML 字符串。
- 假设 4：现有 Agent 任务、动作和工具调用表足够支撑本次审计，不新增数据库表。

## 13. 需求审查记录

### 13.1 与当前代码一致的部分

- 当前 AI 服务已有 Agent 入口、SSE envelope、agent-plan、tool-start、tool-result、confirmation-required 等事件。
- 当前 Admin 后台文章弹窗已有初版 `AdminAgentSidebar`，可作为管理员写作侧边栏基础。
- 当前 Web 创建页已经有分类/标签创建弹窗和 TinyMCE 富文本编辑器。
- 主后端已有 Admin 分类、标签、文章接口，并通过 `ROLE_ADMIN` 保护管理端路径。

### 13.2 与当前代码或架构冲突的部分

- `/ai/agent/chat` 和 `/ai/agent/stream` 当前是 `permitAll`，不适合作为管理员写作工具入口。
- Web `/create` 当前只要求登录，不限制 admin，因此管理员 AI 写作入口必须额外判断用户角色。
- Admin 后台文章弹窗缺少快捷创建分类/标签按钮。
- 当前 AI 写作响应偏自然语言，不是完整结构化文章草稿。

### 13.3 安全与性能风险

- 管理员工具若继续挂在公共 Agent 路径，容易形成越权误用风险。
- AI HTML 若直接应用，存在 XSS 风险，必须消毒和限制标签属性。
- 长文章生成会增加模型 token 消耗和 SSE 持续时间。

### 13.4 需要用户决策的问题

- 是否接受管理员 AI 独立接口、普通 Agent 保持只读：用户已确认。
- 是否接受 AI 生成封面图提示词但不自动生成/上传图片：按建议纳入本次范围。

### 13.5 调整结论

- 保持原需求：让 AI 真正辅助文章编写、格式整理、分类标签和发布前检查。
- 调整后的需求：必须先隔离管理员 AI 接口，再扩展结构化写作能力。
- 暂缓内容：自动生成并上传封面图、删除类能力、用户/角色管理。
