# 功能名 PRD - YYYY-MM-DD

> 使用说明：PRD 是业务需求 + 实现方案的合并文档。业务需求章节描述"用户要什么、边界是什么、怎样算完成"；实现方案章节描述代码落地方案（影响范围、接口、数据流、回滚）。若用户只是头脑风暴，不创建本文件；只有用户明确要实现、生成 PRD、或推进落地时才创建。

## 1. 背景

说明为什么要做这个功能：

- 当前用户遇到什么问题。
- 现有流程哪里不顺、缺失或有风险。
- 这个需求来自真实使用、运营目标、安全问题、性能问题，还是产品规划。

不要写代码实现，不要提前假设数据库、接口、组件如何改。

- 目标用户是谁。

推荐格式：

```text
作为【用户角色】，我希望【完成某事】，以便【获得价值】。
```
