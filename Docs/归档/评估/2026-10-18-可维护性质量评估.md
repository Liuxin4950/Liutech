# LiuTech 可维护性质量评估（2026-10-18）

> 评估方式：只读静态勘察。证据来自文件行数统计、grep 规范执行度、docker-compose/env/git/文档链接机检，以及代表性页面与组件抽样。未运行构建与测试（本机未验证），未做浏览器视觉验收。历史评估见[归档索引](../README.md)；当前维护状态以[维护清单](../../维护清单.md)为准。

## 1. 总体结论

**综合可维护性：7.5 / 10（良好）。结构性规范治理明显高于个人项目平均水准；短板集中在前端工程门禁、Admin 设计令牌迁移尾巴和 CI/CD 停用三处。**

## 2. 规模基线（事实）

- Java：主后端 244 文件 / 26,173 行；AI 服务 168 文件（main）；测试文件 81 + 52。
- 前端：Web 47 个组件 + 21 个 vitest 测试；Admin 18 个管理页 + 10 个逻辑测试。
- TODO/FIXME/HACK 标记：主后端 0（2 处为时间格式 XXX 误命中）、AI 服务 0——债务被显式维护在 `Docs/维护清单.md`，而不是散落代码里，这是好信号。

## 3. 强项（可列为护城河）

1. **规范有牙齿**：`Docs/架构/跨服务规范.md` 不是摆设——`@Autowired` 字段注入仅存 4 处且全在规范豁免清单（SecurityConfig/JwtFilter/MyMetaObjectHandler/VerificationCodeService @Lazy）；缓存集中在 `CacheConfig` + 注解（13 个文件使用），仅 `UserAuthService` 登录失败计数两个 `ConcurrentHashMap` 属规范明文豁免；Controller 零 Mapper 注入；`${}` SQL 拼接零命中。
2. **测试面罕见地完整**：81 个主后端测试文件覆盖 Controller/Service/Mapper/Filter/存储/AOP/MySQL 回归（含 `SqlInitializationMysqlTest`、`MigrationMysqlTest`、`ArchitectureBoundaryTest` 这种"规范守卫测试"）；AI 服务 52 个测试含并发（`MemoryServiceConcurrencyTest`）、流式生命周期（`StreamLifecycleTest`）、韧性（`AiResilienceConfigurationTest`）。
3. **Compose 工程化到位**：healthcheck + `depends_on: condition: service_healthy`、`${VAR:?required}` 强校验、资源 limits/reservations、端口收敛到 Nginx 80/443/81、restart 策略齐全。
4. **文档零腐化**：944 个相对链接机检零失效；维护清单按"证据 + 边界 + 完成条件"逐项维护；新旧方案分层（现行 Docs/架构 vs 归档）清晰。
5. **Git 纪律**：近 50 条提交 46 条符合 `<type>(<scope>): subject` + 为什么/验证格式；交付基线纪律（主目录 main 与 origin/main 一致）有文档且有踩坑记录。

## 5. UI 质量专评

### Web 前台（7.5）

- **设计体系（好）**：`theme.css` 190 行完整 CSS 变量（布局/品牌/背景/文本/边框/状态六段式）+ `_tokens.scss` + `.dark` 暗色区块；`utils/theme.ts` 提供 light/dark 切换，TheHeader 有月亮/太阳切换按钮，暗色模式是完整实现而非半成品。
- **响应式（中上）**：18 处 `@media`，配合 `composables/breakpoints.ts`；TheHeader 834 行大部消耗在移动端菜单/搜索/主题切换上，属于合理复杂。
- **交互状态（中上）**：8 个 views 处理了空态；AI 聊天有 streaming/loading/guest/error/retry 全状态（AiChat 的 `dialogueStatus`、`responseActive` 计算属性设计细致）。
- **扣分点**：CreatePost/PostDetail 体量已到"改动恐惧"级别；51 处硬编码 hex 说明变量体系没有被严格遵守；Login.vue 712 行对于一个登录页偏重。

### Admin 后台（7.0）

- **设计体系（迁移中）**：`tokens.css` 330 行 `--lt-*` 令牌 + `theme.css` 别名层是正确路线；settings store 支持 light/dark/auto 三态且同步 `<html class="dark">`，比 Web 更完整。但 5/18 页未迁移，别名层删除时间点被拖住。
- **组件使用（好）**：Ant Design Vue 4.2.6 使用规范，表格/表单/模态成体系；筛选栏已出现 `lt-filter-bar` 统一类名（部分页）。
- **可访问性与响应式（弱）**：aria/role 仅 27 处；21 处 @media 但 git 历史仍有"页面头窄屏挤压"类修复，说明后台以桌面为先、窄屏属次优。
- **扣分点**：CRUD 页复制粘贴是最大结构问题（见 P1-5）；CommunityAiManagement 1937 行是全仓最大单文件。

## 6. 行动建议（按性价比排序）

1. **恢复 CI（周级）**：先把 `ci.yml.disabled` 复核启用，跑 `mvn test` + 两个前端 `npm run build/test`；这是把"本地通过"变成"可发布"的最低成本一步。
2. **上 lint 门禁（天级）**：加 ESLint（vue/typescript 推荐预设）+ `no-console` 规则，先 `--max-warnings` 灰度不清历史，只卡新增。
3. **完成 Admin token 迁移（周级）**：剩 5 页 + 删 `theme.css` 别名层，一劳永逸消除双体系。
4. **拆两个最大组件（周级）**：PostDetail.vue（script 拆 composable）、CommunityAiManagement.vue。
5. **CRUD 页抽象（周级）**：`useCrudTable` + 通用表格页组件，把 4+ 个相似页收敛。
6. 顺手项：提交 `.gitignore` 改动、清理 `AI_MAX_CONCURRENT_STREAMS`、补 LICENSE。

## 7. 评估边界声明

- 本报告未运行 `mvn test` / `npm test` / `npm run build`，测试"存在性"已核实，"通过性"未验证。
- UI 结论基于代码与样式体系静态分析，未做浏览器视觉验收（维护清单中"未重做浏览器视觉验收"项仍然有效）。
- AI 服务的响应契约（`{success,message,code}`）是按现行规范保留的差异，本报告不将其判为违规，仅指出实体直出的演进风险。
