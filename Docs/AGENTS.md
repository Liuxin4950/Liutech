# Docs 维护约定

修改本目录前先读 [文档总览](README.md)、[架构总览](架构/总览.md)及相关模块的 `总览.md`；架构文档同时遵循仓库 `docs-architecture` 技能。

- 当前事实先对照代码、配置或实际验证。区分现行行为、规范目标、待验证事项与历史结论；不要把估算、提案或旧测试结果写成已实现能力。
- 当前架构放在 `架构/<领域>/<模块>/`，模块入口固定为 `总览.md`，单篇不超过 500 行。总体关系放 `架构/总览.md`，编码规则放 `架构/跨服务规范.md`，具体实现与接口放对应模块。
- 同一事实保留一个正文来源，其它文档使用相对链接。改动模块、HTTP/SSE 契约、配置或数据库时，同步相应现行文档与索引。
- 历史评估、需求与未实施方案放 `归档/`，保留原始状态和结论。归档不代表所有问题已修复或所有需求已验收；重新启用前先复核代码。已核实的当前事项汇总到 `维护清单.md`。
- `SQL/sql.sql` 是唯一完整初始化脚本，保持固定路径并同步最新结构与基础数据。已发布 `SQL/migrations/**/V*.sql` 不修改、不移动、不删除；`baseline/` 仅作冻结的旧结构测试夹具。已有库按迁移说明升级。
- 发布结果只在 `架构/运维/部署运维/总览.md` 维护，记录实际版本、备份与验证范围。没有线上验证时写明未验证，不沿用旧日期声称当前已完成。
- 移动文档时修正全部相对链接、根目录 README/AGENTS/CLAUDE 与技能中的入口。确需兼容旧路径时仅保留简短跳转；归档中的失效代码路径保留为历史文字，不挂到不存在的文件。
- 密码、Token、API Key、私钥与真实环境文件不进入文档。引用代码用可点击路径与准确的方法名，避免大量复制实现或依赖易漂移的行号。
- 完成后核验文档链接、章节锚点、索引及路径大小写 和 `git diff --check`。文档整理本身不触发服务部署或改写数据库。
