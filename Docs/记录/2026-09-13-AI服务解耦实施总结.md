## 目标结果

本轮把原先“主服务与 AI 双向承载 AI 能力”的结构调整为：

```text
主服务：博客核心业务 + JWT 唯一身份权威
AI 服务：聊天 + 写作 + 模型 + 会话 + TTS

AI → 主服务：博客公开查询、用户身份内省
主服务 → AI：仅彻底删除用户前清理 AI 会话数据
```

保留当前聊天、写作、模型与 SSE 协议，没有拆仓、引入 Redis/消息队列、共享 DTO JAR 或全量 API v1。

## 已完成实现

### TTS 归 AI 服务

- TTS 配置、状态探测、GPT-SoVITS/SiliconFlow 推理、音色管理、并发限制、临时音频缓存与定时清理已迁入 `LiuTech-AI`。
- 新配置表：`liutech_ai.ai_tts_config`，固定单行 `id=1`；新库初始化已写入 `Docs/SQL/sql.sql`。
- `StreamingChatService` 直接调用 AI 本地 `TtsSpeechService`，已删除 `TtsClient`、`TTS_PROXY_INTERNAL_TOKEN` 和主服务 `/tts/**`。
- TTS 缓存目录为 AI 容器 `/app/tts-cache`，不与主服务 uploads 共享，也不持久化。
- 新接口：
  - `GET /ai/runtime`
  - `GET /ai/tts/audio/{fileName}`
  - `/ai/admin/tts/**`
- SSE `audioUrl` 改为 AI baseURL 相对地址 `tts/audio/{fileName}`。
- TTS 使用禁止自动重定向的专用 JDK `HttpClient`，保留逐跳同源校验；音色 HTTP 请求增加明确读超时。

### 身份权威收口

- `JWT_SECRET` 只保留在主服务；AI 的 `JwtUtil`、JJWT 依赖和本地 JWT Filter 已删除。
- 主服务新增 `GET /internal/auth/introspect`，只返回 `userId/username/role`。
- AI 新增 `RemoteAuthenticationFilter` 和 `AuthIntrospectionClient`：
  - 成功身份按 token SHA-256 摘要缓存 60 秒。
  - 无 token 聊天仍为游客。
  - 无效 token 返回 401。
  - 主服务不可用返回 503，不再静默降级为游客。
  - runtime、公开模型、音频和健康检查不触发身份回查。
- 两服务新增 `LIUTECH_INTERNAL_TOKEN` 和常量时间比较过滤器；公网 Nginx、Web 容器 Nginx、Admin 容器 Nginx 均屏蔽 `/api/internal/**`、`/ai/internal/**`。

### 用户数据生命周期

- AI 新增幂等单个/批量用户数据清理接口，批量最多 100 个 ID。
- 主服务彻底删除用户前先清理 AI 会话与消息；失败时中止主库物理删除。
- 普通软删除不清理 AI 数据。

### 数据库与部署边界

- 新增 `mysql/init-users.sh`：创建 `liutech_app` 与 `liutech_ai_app`，只授予各自数据库的 `SELECT/INSERT/UPDATE/DELETE`。
- Compose 和生产 profile 已改用 `DB_APP_PASSWORD`、`DB_AI_APP_PASSWORD`；应用不再使用 MySQL root。
- SiliconFlow/TTS 密钥只注入 AI；`JWT_SECRET` 只注入 backend。
- Compose 支持 backend/ai/web/admin/nginx 独立镜像标签变量。
- CI 和镜像构建工作流加入路径过滤，服务可按改动范围独立验证和构建。
- `服务器部署脚本.sh` 已同步最小权限账户、内部令牌、AI TTS 和不暴露内部服务端口的规则。

### 前端与代理

- Web/Admin 的运行时状态改为直接请求 AI `/runtime`。
- Admin TTS 管理改用 `aiApi` 和 `/ai/admin/tts/**`。
- Web TTS 播放与 Admin 试听统一按 AI baseURL 解析音频地址。
- 删除旧 `/tts/` 主服务代理；`/ai/tts/audio/**` 使用独立一天缓存，不继承 SSE `no-store`。
- 修正 Admin 容器 `/ai/` 代理尾斜杠导致的路径前缀剥离问题。
