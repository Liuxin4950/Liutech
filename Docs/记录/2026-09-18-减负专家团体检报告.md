## 1. 结论

1. **git 历史是真实的、可量化的负担，但规模被初版低估**：历史 blob 原始合计 **401.9 MB**，其中**当前已不跟踪的历史孤儿 319.5 MB**（757 个路径），当前仍跟踪的资产仅 82.4 MB（1005 个路径）。

2. **孤儿中最大且最安全的清理对象是构建产物与已替换的旧模型**：`target` 构建产物 195.2 MB（53 个），已被 Nahida 取代的 Live2D 旧模型 `huohuo` 52.5 MB（27 个）。二者合计 247.7 MB，占孤儿总量 78%。

3. **代码级"减负"空间远小于初版估计**：真正能确认"无引用且已入库"的前端资源只有约 5 MB（`坐下.gif` 3.17、`moon.png` 1.60、`about-hero-studio.png` 0.14）。所谓"超大 Service 拆分""36 个未使用 CSS 类"等条目，经复核**均不成立或收益近零**，已撤回。

4. **多个初版判断为"可删"的对象实为功能必需**：`dd.ttf`（Web/Admin 均通过 `@font-face` 注册为 `DDFont`）、`logo.png`（`TheHeader.vue:11`、`TheSidebar.vue:25` import）、`rich-content.css`（`main.ts:8` 全局引入 + `TinyMCEEditor.vue:21` 以 `?inline` 注入编辑器）——**都不能删**，只能优化。

5. **方法论教训（比结论更重要）**：初版用"文件名 grep 不到"作为删除依据，在 Windows Git Bash 与 git 八进制转义下会**双向出错**——既会漏掉真实引用，也会把转义路径误判为"未入库"。本版所有引用判定改用 Python 直接读字节 + `git ls-files -z` 绕过转义。

### 方法论缺陷（根因）

1. **bash + 中文文件名 = 假阴性**：Windows Git Bash 下 `grep -rl "坐下.gif"` 因编码问题返回 0，实际该文件确实存在且曾被引用。
2. **`git ls-files` 八进制转义 = 假阴性**：中文路径被输出为 `"Docs/\346\236\266...` 形式，导致 `grep` 与 Python 的"非 ASCII 检测"双双失效，误判 66 个中文文件"未入库"。**正确做法：用 `git ls-files -z`**。
3. **循环论证**：三个待删图片的唯一"命中"是两份文档——一份是 `2026-09-07` 的检查记录，另一份是初版报告自己。删除依据不能是"前一份文档也这么说"。
4. **不同方法给出不同数字却未察觉**：未使用 CSS 类，awk 得 36、正则得 65。数字打架本身就是方法失效的信号。
5. **把"看着像负担"当负担**：未回答"它为什么存在、删了收益多少、风险多大"——`dd.ttf`、`logo.png`、`rich-content.css` 都是因此被误判。
