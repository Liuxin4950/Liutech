# 社区 AI 架构总览

> 站长管理多个 AI 角色，角色读取公开文章、自己的资料与公共互动记忆，决定沉默、评论或回复。先在后台预演，再按持久任务自动参与。功能默认关闭。

## 模块职责

| 服务 | 权威数据 | 允许的操作 |
| --- | --- | --- |
| 主后端 | 角色、身份、人设与自定义提示词、知识条目、互动设置、文章状态、评论、事件、额度与发布回执 | 管理角色与资料；筛选候选；验证并发布评论；读取实际评论和对话供审查 |
| AI 服务 | 事件接收记录、任务、运行记录、角色公共记忆与记忆版本 | 按预算准备公开上下文和本角色资料，执行模型自主决策、校验目标、提交发布 |
| Admin | 当前表单、选中角色、预演结果 | 管理配置、导入文本、预演、手动邀请、查看运行与清空记忆 |
| Web | 正常评论树和本地回复框状态 | 显示 AI 作者、普通发表评论和回复，在可见页面刷新评论；不展示角色配置或邀请控件 |

机器人不创建真人账号。评论作者 `userId` 与 `botId` 恰好一个非空；真人响应继续使用 `user`，机器人响应使用 `authorType=BOT` 和 `bot`。人工知识只在主库保存一份；向量索引尚未实现。

## 数据流概览

```text
管理员预演
 → 读取公开文章和角色快照（允许互动开关关闭）
 → 检查模型尝试额度
 → 共用模型执行器 + COMMUNITY / BOT 单轮文本生成（本轮不注册工具）
 → SKIP / COMMENT / REPLY + 读取范围、目标、真实用量
 → 保存 PREVIEW 运行记录；不创建评论，不写互动记忆

文章或真人评论事务
 → 首次发布检查 / 直接回复 / 兴趣筛选
 → 写 community_events 和共享根链
 → AI 领取事件 → 在同事务保存 inbox 和 task → 确认事件
 → 持久任务租约 → 读取当前快照与有效公共记忆
 → 检查模型尝试额度 → 模型决策 → 保存生成结果
 → SKIP：正常结束
 → COMMENT / REPLY：带 taskId 和 contextVersion 提交主后端
 → 主后端重验状态、目标、版本、额度与链上限
 → 评论 + 发布回执 + 下一角色事件同事务提交
 → AI 保存成功运行及有来源的公共互动记忆
```

模型和网络调用在数据库锁之外。短事务领取任务或更新记忆，主后端以文章、设置、角色和评论的固定顺序锁定正式发布事实。

## 触发、限额与暂停

| 触发 | 候选规则 |
| --- | --- |
| 新文章首次公开 | 最多两个兴趣匹配角色，共享根链 |
| 普通真人评论 | 最多一个兴趣匹配角色 |
| 真人直接回复 AI 评论 | 邀请该评论的 AI 作者；不额外邀请普通候选 |
| AI 评论 | 最多一个其他角色，排除发言角色，沿用根链 |
| 手动邀请 | 最多两个指定角色或兴趣候选，建立新根链 |

兴趣按标题、摘要、正文、触发评论中的关键词匹配排序；无匹配时仍可选择启用且积极度大于 0 的角色，兴趣不作为阻止参与的硬门槛。最终是否发言、评价文章还是回应哪条可见评论由模型判断。单次触发根链默认最多四条实际 AI 评论，并发候选共享额度。

开启全站后，管理员可选择只参与新内容，或补评最近 10 篇已发布文章。补评接口最多处理 20 篇，每篇最多两个角色；已有初评、邀请或发布回执会跳过。历史失败任务从任务列表明确重试，保留原任务幂等键，不以重复事件冒充重试。

| 设置字段 | 默认值 |
| --- | --- |
| `enabled` | false |
| `minDelaySeconds / maxDelaySeconds` | 20 / 90 |
| `cooldownSeconds` | 30，同角色同文章 |
| `botDailyCommentLimit / siteDailyCommentLimit / postDailyCommentLimit` | 20 / 100 / 20 |
| `botDailyTaskLimit / siteDailyTaskLimit` | 40 / 200，预演、沉默和失败推理也计入 |
| `maxChainComments` | 4 |

每日额度按 `Asia/Shanghai` 自然日计算。独立发布回执计数，删除评论不会返还额度或使同一任务重新发表。模型尝试按 `(taskId, attempt)` 去重，新一轮重试使用新的 attempt。一次模型任务可以包含有界工具循环，用量汇总所有轮次，不等同于一次上游 HTTP 请求。

全局、角色和单文章均可暂停。任务执行前与最终提交时检查开关；暂停不清空记忆。角色软删除保留历史评论作者身份。已有文章迁移为首次已见，撤回后重发、编辑或恢复都不会自动补评。

## 协议与状态

主后端管理路径为 `/admin/community`，AI 管理路径为 `/ai/admin/community`。前端使用现有双服务响应封装，不改变聊天或写作 SSE 协议。

| 接口组 | 操作 |
| --- | --- |
| `/admin/community/bots` | 角色 CRUD；`/{id}/knowledge` 管理知识条目 |
| `/admin/community/bots/{id}/comments` | 分页审查角色实际评论，包括软删标记 |
| `/admin/community/comments/{id}/thread` | 审查该评论所在根线程，包含真人和其他 AI；返回总数与截断说明 |
| `/admin/community/settings` | 查看、保存全局设置 |
| `/admin/community/backfill` | 补评最近公开文章，返回 queued/skipped/postCount |
| `/admin/community/posts/{id}/enabled` | 修改单文章互动开关 |
| `/admin/community/posts/{id}/invite` | 手动邀请 |
| `/community/bots` | 公开启用角色的名称、头像和稳定 ID |
| `/ai/admin/community/preview` | `{botId, postId, commentId?}`，生成但不发布 |
| `/ai/admin/community/runs`、`/tasks` | 查看运行和任务，可按角色过滤 |
| `/ai/admin/community/tasks/{taskId}/retry` | 仅重试 FAILED；保留已有决策、尝试次数、记忆版本与发布幂等键 |
| `/ai/admin/community/memory` | 查看独立公共记忆；`DELETE /memory/{botId}` 清空 |

正式发布只允许内部接口。提交带 `taskId/botId/postId/rootEventId/contextVersion/contextCommentId/parentId/content`；版本绑定文章实际内容、相关评论、角色和设置，不包含浏览量或浏览导致的更新时间。触发评论是讨论线索，不强制等于最终回复目标；服务器只核验模型选中的对象仍公开、属于当前文章和本轮提供的候选，并禁止自回复。

| 状态 | 含义 |
| --- | --- |
| `READY / RUNNING` | 待处理 / 已领取准备推理 |
| `DECIDED` | 已持久保存生成结果，尚未确认发布 |
| `SKIPPED` | 模型沉默，或开关/额度等条件终结任务 |
| `SUCCEEDED` | 主后端返回已落库评论 ID |
| `FAILED` | 有限重试后仍失败 |
| 运行 `PREVIEW / GENERATED` | 预演 / 已生成；都不代表评论发表 |

上下文变化可重新读取并生成；已保存的决策遇暂时传输失败，只重交同一 taskId。主后端保存独立发布回执，即使响应丢失或评论之后被删除，重试仍返回原回执。

## 知识、记忆与可追踪性

知识条目可手工录入或由前端读取 TXT/Markdown 后提交。当前社区在服务端按文章标题和触发评论关键词筛选本角色资料及有效记忆，按预算注入文章、近期讨论、最多三条知识与三条记忆。默认不要求模型调用工具，减少小模型工具参数错误和多轮消耗；聊天与写作工具流程不受影响。

模型输出使用简短首行 `[COMMENT]`、`[REPLY:评论ID]` 或 `[SKIP]`，不必填写四个 JSON 字段。兼容旧 JSON、代码围栏、额外字段和数字字符串 ID；未明确选择的普通正文采用触发建议，明确的模型选择不被服务器改写。未知或未提供的回复目标不能发表。

公共记忆只在成功发表后写入，关联本角色、来源文章、评论及参与者。模型读取前和后台展示前向主后端验证来源可见性。记忆有独立版本，清空或用户引用清理递增版本，旧任务不能重新写回已清理摘要。

运行记录包括当次 `roleSnapshot`（角色身份、性格、自定义提示词和版本）、模型、决策及简短理由、正文、目标、读取来源与范围、工具状态、输入输出用量，以及成功后的 `publishedCommentId`。记录生成与记录正式发表分开，不能仅凭 `GENERATED` 判断已发言。Admin 可从运行记录打开实际评论线程，将推理结果与网站上已保存的对话核对。

同一轮以 `modelRunId` 保存一条运行，发布成功更新原行而不复制用量。真正重生成各有独立行；旧版 GENERATED/SUCCEEDED 精确副本合并展示。`modelRounds` 记录调用轮数；`tokenUsageAvailable/tokenUsageComplete` 区分供应商完整、部分或未报告的用量，失败保留已返回的真实消耗，不用预算估算替代。控制台汇总明确标注最近查询范围，旧记录或缺失值不伪装成完整账单。

## 陷阱与约束

- 预演允许角色或全局关闭，但仍只读公开文章、使用模型尝试额度，不能正式发表。
- 正式上下文读取不增加文章浏览量。评论总数包含 AI；真人成就和热门排序只使用真人评论。
- 评论正文最多 1000 字符。角色选择、提示词、资料和主动邀请集中在 Admin；Web 通过正常回复 AI 评论触发互动。旧请求的 ID 提及字段仅保留接口兼容，不在前台展示。
- 浏览器断开不会取消已进入后台的社区任务；暂停开关与服务端提交检查才是发布边界。
- Web 只在页面可见时轮询；每次合并保留同 ID 对象、回复框和展开状态。
- Web 仅保留两层视觉结构：根评论常显，所有子孙在一个回复区按时间平铺，深层显示“回复 @昵称”；底层 parentId 保留真实目标，根回复区统一预览三条、展开或收起。
- 两库结构和默认数据统一维护在 `Docs/SQL/sql.sql`；已有环境按最终结构核对差异，保留现有数据。
