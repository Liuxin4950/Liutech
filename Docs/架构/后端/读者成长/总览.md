# 读者成长架构总览

> 普通读者的真实统计、一次性成就奖励与最近动态，复用主后端积分和行为记录。

## 模块职责

`/user/achievements` 与 `/user/activities` 仅访问当前认证用户。前端呈现服务端资格和最终余额；客户端不提交用户 ID、奖励金额或达成进度。

## 数据流概览

```text
GET /user/achievements
  → 评论 / 浏览历史实时计数 + 已领取记录
  → in_progress / claimable / claimed

POST /user/achievements/{code}/claim
  → 当前认证用户 → 用户行锁 → 校验规则和既有领取记录
  → 新领取记录 → PointsService.addPoints → 余额 + 积分流水
  → 同一事务提交 → 清除用户资料缓存 → 返回最终任务状态与余额

GET /user/activities?page=1&size=10
  → 当前用户各来源记录 UNION ALL
  → occurred_at DESC, type ASC, id DESC → 数据库分页
```

## 规则与接口

| code | 当前资格 | 奖励与次数 |
| --- | --- | --- |
| `comment_10` | 10 条未删除且关联公开文章的评论，回复计入 | 2 分，每用户一次 |
| `read_10` | 现存历史中的 10 篇不同公开文章 | 2 分，每用户一次 |

`user_achievement_claims` 的 `(user_id, achievement_code)` 唯一键是持久幂等约束。请求按用户行锁串行后检查既有领取，重复请求返回已领取结果。领取记录、积分变动及流水必须在一个事务中成功；流水影响行数异常也抛错回滚。流水 `transaction_type/source_type` 为 `achievement`，`source_id` 指向领取记录。

成就查询返回 `code/title/progress/target/rewardPoints/status/claimedAt`；领取返回 `achievement/points`。动态使用现有 `PageResp`，每页 1～20 条，事件返回 `id/type/occurredAt/title/targetType/targetId`，时间显式携带 Asia/Shanghai 偏移。

动态来源包括评论、当前收藏、最近浏览、签到、领取、注册，以及管理员自己的公开发文；文章关联记录只展示仍公开的目标。不新增永久活动账本。

## 陷阱与约束

- 浏览仅表示打开详情，不表示读完；历史按用户/文章去重，清空影响未领取进度，已领取记录和奖励保留。
- 浏览上报拒绝草稿、已删除和不存在的文章；不能仅在查询列表时过滤草稿。
- 当前个人统计直接查询数据库，不经过旧 `userStats` TTL 缓存；失败走统一异常，不能用 0 假装成功。
- 积分徽章条件使用余额，文案明确“积分余额达到”，不冒充历史累计收入。
- 前端请求使用代次避免账号切换后旧数据回填；领取期间禁用连点只是交互优化，数据库才是防重依据。
- 迁移需在主库执行，回退代码仍保留领取表与积分流水；不能删除领取记录让用户再次领奖。
- 集成脚本仅连接本机，创建专属测试账号/文章；按测试生成的 ID 清理，失败注入触发器只影响该测试用户，不包含凭据。
