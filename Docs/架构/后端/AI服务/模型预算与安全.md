# 模型预算与安全

> 模型配置如何贯穿聊天、写作与工具循环，以及不可信输入、取消、权限和生成结果的边界。

## 模型配置与预算

权威配置为 `ai_model_config` 的默认启用模型、`max_tokens`、`context_window` 和 `temperature`。
实现入口：[AiModelPolicy](../../../../LiuTech-AI/src/main/java/chat/liuxin/ai/infra/security/AiModelPolicy.java)、[PromptBudget](../../../../LiuTech-AI/src/main/java/chat/liuxin/ai/infra/security/PromptBudget.java)。

管理入口为 [`Admin/AiModelsManagement.vue`](../../../../Admin/src/views/admin/AiModelsManagement.vue)，首屏显示全局默认与启用数量，行内具名操作管理默认、启用、编辑和删除。默认变更明确提示聊天、写作及跟随默认的评论角色影响；角色单独指定的模型不变。页面读列表失败时保留上次结果并禁用写操作，重新读取成功后恢复。新增/更新请求失败直接抛出，不返回假成功或关闭编辑草稿；提交与行操作各自防止重复触发。预设仅帮助填写，须按供应商当前规格核对。

| 项目 | 行为 |
| --- | --- |
| 模型 | 使用数据库默认启用模型；无默认记录时回退应用默认 DeepSeek-V3.2；配置查询故障明确失败 |
| 单次输出 | 使用配置值；请求只能要求更小。工具循环已消耗输出从下一轮 `maxTokens` 中扣除 |
| 总上下文 | 使用配置的 `context_window`；缺失时保守回退 32768，不按模型名称猜测 |
| 输入预算 | 上下文减单次输出预留，再减 512 安全余量；每轮重新核对完整消息和工具 schema |
| 可选输出护栏 | `AI_MODEL_MAX_OUTPUT_TOKENS`，默认 0；显式配置为正数时才额外限制 |
| 可选输入护栏 | `AI_MODEL_MAX_INPUT_TOKENS`，默认 0；显式配置为正数时才额外限制 |
| 温度 | 模型配置优先；未配置才使用合法请求值，写作再回退 0.3 |

```text
输入预算 = context_window - 有效单次输出上限 - 512
有正数输入成本护栏时，再取二者较小值
每轮发送前：完整消息预算 + 工具定义预算 <= 输入预算
每轮输出上限：有效单次输出上限 - 前序轮次输出消耗
```

当前没有各模型的精确 tokenizer，输入采用 UTF-8 字节数作保守 Token 上界。ASCII、中文、emoji、未配对代理字符均占预算，不使用字符数除以4。该策略可能少用一部分模型窗口；监控和成本统计使用供应商真实 `usage`，不把本地预算值冒充实际用量。

## 初始消息分配

[PromptBudget.prepareInitial](../../../../LiuTech-AI/src/main/java/chat/liuxin/ai/infra/security/PromptBudget.java) 统一初始消息分配：先保留系统规则、必需资料和当前输入，再计工具 schema、预留工具空间、按剩余预算加入参考与最近历史。聊天和写作由 [ChatServiceHelper](../../../../LiuTech-AI/src/main/java/chat/liuxin/ai/service/ChatServiceHelper.java) 准备业务资料，社区单独准备角色和讨论资料后调用同一预算入口。

- 写作草稿完整保留。无法放入配置预算时明确拒绝，禁止截前6000字后再要求整篇改写。
- 当前文章和站点信息是可节选参考，节选有明确说明，不因整篇文章太长而阻断所有简单聊天。
- `getPostSection(postId, offset, toolContext)` 支持继续读取后续正文；返回区间、总字符数和下一段偏移。
- 历史从最旧整条裁剪。登录会话读取服务端历史，游客取末7条临时历史，写作取末7轮（14条），再按预算裁剪。
- 外部请求体最多1MiB，草稿最多200000字符，临时历史最多14条。正文是否适合本模型仍由预算判断。

## 有界工具循环

[SiliconFlowChatClient](../../../../LiuTech-AI/src/main/java/chat/liuxin/ai/service/SiliconFlowChatClient.java) 直接使用 Spring AI 2 `ChatModel.stream` 和 `ToolCallingManager` 驱动循环，保留框架的模型协议与工具执行实现。

```text
按模型预算构建本轮 Prompt
 → 发送模型请求并聚合 finish reason / usage
 → 检查是否完整结束、输出额度是否耗尽
 → 工具请求核验名称与角色/模式白名单
 → 执行已授权工具，限制累计返回值
 → 把工具参数与结果加入完整消息，重新核对预算
 → 下一轮或正常结束
```

`spring.ai.agent.max-tool-rounds=8`、`max-tool-calls=24` 是服务器限制，请求或模型不能提高。模型与SDK不自动重发请求，以免重复推理和工具副作用。

模型返回 `length`、`max_tokens`、过滤终态、未知终态、异常或超预算，都走失败路径。只有正常 `stop` 才算完成；仅结构化字段、已验证的局部补丁或明确零修改的合法写作可以有空文本。未完整结束的正文不能作为成功修改。

## 服务端权限与提示词边界

[RoleBasedToolRegistry](../../../../LiuTech-AI/src/main/java/chat/liuxin/ai/common/tools/RoleBasedToolRegistry.java) 同时检查 `allowedRoles()` 与 `allowedModes()`。

| 入口 | 可用工具 |
| --- | --- |
| CHAT，游客/用户/管理员 | `BlogTools` 公开只读工具 |
| WRITING，管理员 | `WritingTools` 读取与待采纳字段工具 |
| WRITING，游客/普通用户 | URL和模型客户端均拒绝 |
| COMMUNITY，服务端 BOT 主体 | 默认服务端预算预取当前文章、讨论、本角色知识和有效记忆，单轮无工具；普通客户端不能自行切换模式或主体 |

`ModelExecutionPolicy` 由业务入口明确绑定观察、工具失败与空结果规则。社区结构化决策只收集正常结束的最终轮文本，工具调用前的过渡文字不拼入 JSON；聊天与写作保持现有分片协议。

- `draft`、历史或自然语言不决定入口模式，`context.role` 等未知字段被拒绝。
- 临时历史仅允许 `user/assistant`，不能传 `system/developer` 角色。
- 页面上下文白名单为 `page/postId/recommendations/requestedFields/source/appendTags/contentMode`；字段范围只能收窄写作行为。
- 检查模式不生成修改；只改标题等范围不会产生正文预览或其他字段更新。
- 分类、标签ID必须存在；标签按顺序去重。所有字段验证通过后才进入收集器。
- `null` 表示不改，`summary=""` 和 `tagIds=[]` 表示明确清空；建议新分类和标签仍由管理员确认。
- 搜索返回量限定1到8，关键词最多200字符，不能由模型放大成无限列表。

[PromptService](../../../../LiuTech-AI/src/main/java/chat/liuxin/ai/service/PromptService.java) 将博客与草稿包在不可信参考边界，转义资料中同名边界结束标记；写作身份与看板娘人设分开。工具结果也标为不可信资料。最近推荐中的文章ID和标题重新由博客接口核验。

提示词用于引导回答，不能作为鉴权或保密机制。编码、翻译、角色扮演和恶意文章仍可能影响模型措辞；真正的执行能力由服务器白名单、数据校验和前端采纳控制。模型输入不含 JWT、内部令牌或供应商密钥。跨服务身份约束见 [AGENTS.md](../../../../AGENTS.md)。

## 流生命周期与资源

[StreamingChatService](../../../../LiuTech-AI/src/main/java/chat/liuxin/ai/service/StreamingChatService.java) 由内部 `StreamSession` 管理每轮请求，使用共享有界准备队列、活动流配额与心跳调度。当前读取 `spring.ai.agent.max-concurrent-requests`（默认16）与 `max-queued-requests`（默认32）；模型入口也限制同步和流式推理的总活动请求。旧的 `AI_MAX_CONCURRENT_STREAMS` / `spring.ai.max-concurrent-streams` 仍在配置中，但不控制当前 SSE 调度入口，后续清理见[维护清单](../../../维护清单.md)。

同步模型调用同样使用 `max(1000,sseTimeout)` 的总执行时限；超过时限取消上游订阅、释放模型容量并抛项目 `TimeoutException`，非流式入口返回 408。模型入口容量满保留 429 与明确繁忙原因，取消订阅后释放容量。社区 Worker 的领取、阶段与运行证据见[社区后台执行状态](../社区AI/总览.md#后台执行状态)，不以 health UP 判断是否处理队列。

模型编辑、启停、删除与默认切换在短事务中按主键顺序锁定现有模型目录，再读取当前目标状态。编辑与开关均禁止禁用当前默认模型；删除默认模型前须先切换，切换目标必须启用。编辑不写默认标志，开关只修改启用列，避免陈旧实体覆盖默认选择或预算配置；并发默认切换、停用和删除使用同一锁序裁定。

- 保存启动 Future 和模型 Disposable；晚登记的句柄仍观察取消状态。
- 应用层 deadline 先通知超时再关闭；Servlet timeout 是稍后的兜底。
- 客户端断开、停止、超时会取消订阅和待执行工具；正常模型完成后的持久化不因随后断开而重复或中断。
- 取消/失败最多保存一次部分回复错误态，不把半截内容标成正常。
- [CancellableOpenAiChatModel](../../../../LiuTech-AI/src/main/java/chat/liuxin/ai/common/client/CancellableOpenAiChatModel.java) 每订阅建立独立SDK取消域，cancel/complete/error均关闭 `AsyncStreamResponse`；晚到句柄立即关闭。
- 模型请求构造、流解析、工具参数、usage和观测仍委托框架；所有订阅共享SDK连接池，彼此取消隔离。

## 结果采纳与指标

写作使用统一 `writing-event`；正文建议只在正常结束后发送 `proposal`。已有正文默认精确段落补丁，原稿锚点唯一且修改不重叠；空稿/整文重写返回完整HTML，合法短文无200字符门槛。详见[写作事件与局部修改](写作事件与局部修改.md)。客户端将全部字段暂存为预览，明确应用后修改编辑器，并保留本轮原稿快照；撤销仅恢复本轮改动字段，不覆盖其后手改的封面、状态或其他字段。见[网络封装](../../设计/网络封装/总览.md)。

`article-results` 从回复解析候选文章后，向博客接口核验真实ID与标题；不存在的文章不生成卡片。

[AiMetrics](../../../../LiuTech-AI/src/main/java/chat/liuxin/ai/common/monitor/AiMetrics.java) 记录主SSE请求、活动数、首字延迟、成功/失败/超时/取消和每轮真实usage。供应商未返回用量时不虚构费用。`/ai/internal/metrics/prometheus` 复用内部令牌保护，公网代理屏蔽；Actuator公开端点仍只有health。

限流仅在显式 `AI_TRUSTED_PROXIES` 范围内信任代理覆盖的 `X-Real-IP`，始终忽略可伪造的XFF首段；满桶拒绝新身份，保留已有额度。生产需填写真实受控代理地址，默认空时按直连地址限流。
