# AI 职责边界与行为判断

> 从一次请求理解谁决定行为、谁读取资料、谁执行工具、谁保存业务结果。聊天、写作和社区角色的产品行为分别定义，共用一套模型执行能力。

## 三个业务入口

| 问题 | 看板娘聊天 | 写作助手 | 社区角色 |
| --- | --- | --- | --- |
| 谁触发 | 用户提问 | 管理员编辑器指令 | 文章、评论事件或管理员预演 |
| 读什么 | 当前页面、公开博客资料、当前用户会话 | 原稿快照、临时写作历史、公开参考资料 | 公开文章、相关评论、本角色知识和公共互动记忆 |
| 允许做什么 | 回答与公开资料查询，可选语音 | 提出字段或局部正文建议 | 选择沉默、文章评论或回复 |
| 状态在哪里 | AI 库的会话和消息 | 服务端本轮建议；前端草稿、预览与采纳状态 | 主库角色和评论；AI 库任务、运行与记忆 |
| 谁最终保存 | 聊天服务保存用户会话 | 管理员采纳后，文章业务接口保存 | 主后端验证身份、可见性、额度后发布 |

社区接口、数据表和运行状态见[社区 AI](../社区AI/总览.md)。TTS 与身份规则见[TTS 与认证边界](TTS与认证边界.md)。

## 共用执行与业务编排

```text
聊天请求 → 聊天资料与历史组装 ─┐
写作请求 → 草稿与写作资料组装 ─┼→ 初始预算 → 模型执行器 → 本轮授权工具
社区任务 → 角色与讨论资料组装 ─┘                  │
                                                  └→ 模型 SDK 传输

执行结果 → 聊天：回复、会话持久化、可选 TTS
         → 写作：结果校验 → 待采纳建议 → 前端明确采纳
         → 社区：决策校验 → 主后端幂等发布
```

| 层次 | 权威实现 | 职责与限制 |
| --- | --- | --- |
| 业务资料组装 | [PromptService](../../../../LiuTech-AI/src/main/java/chat/liuxin/ai/service/PromptService.java)、[ChatServiceHelper](../../../../LiuTech-AI/src/main/java/chat/liuxin/ai/service/ChatServiceHelper.java) | 聊天和写作准备资料；资料内容不能切换执行模式或权限 |
| 预算 | [PromptBudget](../../../../LiuTech-AI/src/main/java/chat/liuxin/ai/infra/security/PromptBudget.java) | 统一初始预算与历史裁剪；执行器在每轮追加工具结果后再次检查 |
| 模型执行 | [SiliconFlowChatClient](../../../../LiuTech-AI/src/main/java/chat/liuxin/ai/service/SiliconFlowChatClient.java) | 唯一模型与工具循环；白名单、预算、取消、用量；不保存文章或评论 |
| 运行观察 | [ModelExecutionObserver](../../../../LiuTech-AI/src/main/java/chat/liuxin/ai/common/client/ModelExecutionObserver.java) | 接收实际模型轮次和工具活动，业务适配为展示或运行记录 |
| 本地工具 | [RoleBasedToolRegistry](../../../../LiuTech-AI/src/main/java/chat/liuxin/ai/common/tools/RoleBasedToolRegistry.java) | 按服务端主体和业务模式注册工具；工具自己核验数据范围 |
| 写作结果 | [WritingResultValidator](../../../../LiuTech-AI/src/main/java/chat/liuxin/ai/service/WritingResultValidator.java) | 同步与流式共用字段、正文和局部补丁的最后校验 |
| 流式应用适配 | [StreamingChatService](../../../../LiuTech-AI/src/main/java/chat/liuxin/ai/service/StreamingChatService.java) | 聊天与写作的准备、取消、结果和可选语音编排；社区任务不经过它 |
| SSE 发送 | [SseEmitterHelper](../../../../LiuTech-AI/src/main/java/chat/liuxin/ai/service/SseEmitterHelper.java) | 编码并串行发送浏览器事件；不决定业务动作 |
| SDK 传输 | [CancellableOpenAiChatModel](../../../../LiuTech-AI/src/main/java/chat/liuxin/ai/common/client/CancellableOpenAiChatModel.java) | 委托框架请求与解析，关闭对应 HTTP 流资源 |

初始预算和逐轮预算控制两个时点。删除其中一处，会分别失去请求开始前的容量判断或追加工具结果后的容量判断。具体公式只在[模型预算与安全](模型预算与安全.md)维护。

## 本地工具、MCP、RAG 与记忆

当前 `common/tools` 中的 `@Tool` 是进程内 Java 方法，由 `ToolCallbacks` 注册，再由 Spring AI `ToolCallingManager` 执行。原 `common/mcp` 命名已收敛为本地工具；本服务没有 MCP 客户端、服务端或 JSON-RPC 工具协议。

MCP 是外部工具与上下文交换协议。将来接入时，它提供另一种工具来源，仍受本轮授权、结果预算和取消规则控制。

读取当前文章可直接按文章 ID 获取。知识检索负责从角色资料中选择相关内容；向量检索只是以后可增加的检索实现。会话历史、写作原稿和公共互动摘要不混用成一个记忆库。

## 三类事件

| 事件 | 谁消费 | 完成含义 | 失败与重试 |
| --- | --- | --- | --- |
| 模型运行观察 | 业务编排器 | 模型轮次或工具执行结束 | 工具可能失败；结束不能证明业务已保存 |
| SSE 展示事件 | 浏览器 | 收到对应进度或结果 | 断流需明确失败；写作不接受不完整建议 |
| 文章、评论业务事件 | 社区任务消费者 | 数据库业务事实已提交 | 持久保存，允许重复投递，消费者与发布入口去重 |

写作 `completed` 表示建议生成结束，不表示文章保存或发布。社区任务的成功必须关联已落库的评论 ID。浏览器连接关闭可以取消该聊天或写作请求；社区任务与浏览器连接没有生命周期绑定。

## 一次聊天如何判断

```text
/ai/chat/stream
 → 认证与当前会话归属检查
 → PromptService 选择聊天身份、页面资料和当前用户历史
 → ChatServiceHelper + PromptBudget 准备预算
 → 模型选择公开查询工具；执行器核验角色、模式、工具名称
 → 工具结果标为参考资料，按预算节选后继续模型循环
 → StreamingChatService 交付回复并保存聊天结果
```

检查点：当前文章是否由真实 ID 获取；全文是否被节选；工具是否确实执行成功；当前账号是否读取自己的会话；断开后是否停止同一次模型订阅。模型说“我已经读完”不构成读取全文的证据，应核对工具范围和截断说明。

## 一次写作如何判断

```text
/ai/writing/stream + 原稿快照
 → 管理员权限检查
 → 草稿和 requestedFields/contentMode 限制
 → 模型读取参考资料或生成本轮修改建议
 → WritingResultValidator 检查字段范围、正文与补丁
 → writing-event 的 proposal 暂存前端预览
 → completed + 原稿签名匹配 + 管理员采纳
 → 编辑器内容变化
 → 管理员保存/发布 → 主后端文章业务接口
```

“只检查”不能生成修改；“仅改标题”不能改正文；局部补丁必须定位唯一原稿片段。停止、断流、超额度、工具失败或原稿已变化时，不接受旧提案。前端采纳规则见[写作事件与局部修改](写作事件与局部修改.md)。

## 常见现象的定位顺序

| 现象 | 先看哪里 | 可判断的证据 |
| --- | --- | --- |
| 回复与文章后半段不符 | 上下文预算和分段读取 | 实际读取区间、截断提示、工具调用结果 |
| 看得到生成文本但没有可采纳建议 | 模型终态与写作结果校验 | 正常结束、proposal、合法字段或补丁 |
| 写作显示完成但文章未发布 | 前端采纳和文章业务调用 | 是否采纳、是否调用保存/发布接口 |
| 停止后还有旧内容进入编辑器 | 请求标识、原稿签名和取消 | requestId、baseRevision、活动请求是否一致 |
| @角色后没有回复 | 社区事件、任务和角色决策 | 任务是否建立、额度/开关、SKIP 原因或失败状态 |
| 同一任务出现重复评论 | 事件去重与发布幂等 | 事件 ID、任务 ID、已发布评论 ID |

运行记录展示实际输入来源、工具活动、用量、简短决策说明与发布结果，不以隐藏推理文本作为执行证据。

## 扩展检查

- 新业务定义自己的触发、资料范围、状态和结果，再调用共用模型执行器。
- 新工具声明主体与模式，并在服务端核验可读取的文章、角色和资料范围。
- 模型生成的 ID、指令或参数不能扩大权限，也不能直接代表数据库已写入。
- 业务正式保存与展示事件分别验收；异常和取消路径必须有明确终态。
- 更改协议需同步消费者；每个数据库事实只有一个权威服务。
