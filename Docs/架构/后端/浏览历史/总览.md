# 浏览历史架构总览

> 记录登录用户浏览过的文章：打开文章详情自动记录，个人中心可查看最近浏览列表并一键清空。读完能定位数据表、接口与前端上报链路。

## 模块职责

用户浏览行为的记录与查询。核心设计是**「用户 + 文章」唯一键去重**：同一用户反复浏览同一篇文章只刷新浏览时间（列表置顶），不无限堆积。所有接口需登录，仅本人可见；清空为物理删除（历史是瞬态痕迹，无恢复价值）。

前端在 `Web/`（详情页上报 + 浏览历史页展示），数据层与接口在 `LiuTech/`。

## 数据流概览

```
打开文章详情（已登录）
  │
  ▼
PostDetail.loadPostDetail 成功后 → PostService.recordView(postId)   ← 失败静默，不影响阅读
  │  POST /posts/{id}/view（需登录，未登录 401 由 JWT 拦截）
  ▼
ViewHistoryService.recordView → 校验文章存在（selectById，@TableLogic 过滤已删除）
  │  → upsertViewHistory：INSERT ... ON DUPLICATE KEY UPDATE viewed_at = NOW()
  ▼
user_view_history 表（uk_user_post 冲突即更新，列表置顶）

浏览历史页 /view-history
  │
  ├─ GET /posts/view-history?page=&size=   → JOIN posts 分页查询
  │    仅 p.status='published' AND p.deleted_at IS NULL（已删除/下线文章不显示）
  │    ORDER BY viewed_at DESC，复用 PostListRespMap 映射 + viewed_at 列
  │
  └─ DELETE /posts/view-history            → 物理删除该用户全部记录
        记 log.info 审计（PostsController.java:268：清除条数）
```

## 陷阱与约束

- **认证白名单必须同步**：`/posts/view-history` 落在 GET 公开前缀 `/posts/` 下，曾因未列入 `AUTHENTICATED_PATHS` 导致被当作公开路径、拿不到当前用户返回 401。新增 `/posts/` 下的需登录 GET 接口时，必须同步加进 `SecurityWhitelist.AUTHENTICATED_PATHS`（[认证授权](../认证授权/总览.md) 有完整机制说明）
- **重复浏览不堆积**：`(user_id, post_id)` 唯一键 + upsert 是容量控制的关键，不要改成每次浏览插一行
- **查询过滤已删除/下线文章**：文章被删或下线后历史记录不显示（JOIN 条件过滤），表内残留记录无害，清空时一并删除
- **生产建表**：`sql.sql` 只在初始化时执行，生产库新增表需手动执行建表语句（`docker exec liutech-mysql mysql -u root -p"$DB_PASSWORD" liutech -e "CREATE TABLE IF NOT EXISTS ..."`）
- **PostListResp.viewedAt 仅浏览历史接口填充**：其他列表接口不 SELECT `viewed_at` 列，映射为 null，无影响
- **上报时机**：详情加载成功即记录（刷新页面会再次刷新浏览时间，属预期行为）；未登录不上报
