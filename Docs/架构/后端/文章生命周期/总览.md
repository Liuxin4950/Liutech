# 文章生命周期架构总览

> 文章发布、软删除、恢复、永久删除及关联交互的可见性与一致性边界。

## 模块职责

文章状态由 `posts.status` 与 `posts.deleted_at` 决定。公开读取只呈现已发布且未删除的文章；管理端使用独立查询查看草稿和回收站。标签、点赞、收藏、评论及附件是文章的关联数据，软删除保留这些数据，永久删除才清理。

## 数据流概览

```text
软删除文章
  → 只设置 posts.deleted_at
  → 公开文章、标签、评论、收藏查询过滤该文章
  → 保留标签关系与交互状态

恢复文章
  → 清除 posts.deleted_at
  → 原有关系重新可见

永久删除文章
  → 找到全部根评论（含软删除）
  → 复用 CommentsAdminService 按深度删除评论树
  → 清除标签、点赞、收藏、附件等关系
  → 物理删除文章，调整图片引用数

点赞 / 收藏
  → 事务内锁文章行
  → 读取交互状态 → 写交互记录 → 统计真实条数 → 更新文章计数
  → 清除 postList / hotPosts / latestPosts
```

## 一致性规则

- 软删除与永久删除分开。软删除不能物理删除 `post_tags`，也不能覆写点赞/收藏的独立删除状态，否则无法撤销。
- 所有关联公开查询同时检查文章和关联记录。按评论 ID 读取也走专用公开入口，后台继续使用管理查询。
- 公开标签统计、收藏列表和个人收藏数量使用已发布、未删除文章的同一口径。文章写操作清除 `allTags` 与 `hotTags`，避免计数缓存漂移。
- 点赞与收藏共享文章行锁；锁持续至单次数据库事务结束，状态读取与计数更新在锁之后。列表缓存中含交互状态，写成功后必须失效。
- 评论 `parent_id` 是无级联自引用外键。永久删除按最大深度倒序去重，逐条删除子孙后删除根；不要依赖一次 `DELETE IN` 的行处理顺序。

## 陷阱与约束

- 修复前已物理删除的标签关系没有保存副本，代码不能自动恢复；旧点赞/收藏删除标记也不能无差别清除。
- `@Transactional` 只定义事务边界，不自动串行化读改写。业务计数需要行锁或原子 SQL。
- `@TableLogic` 的通用 `deleteById` 是软删除，永久删除必须走显式物理 SQL。
- 已有计数漂移不在写操作中全库重算；需要修复旧数据时应另做有范围的对账。
