# 认证授权架构总览

> 前后端一体的登录与访问控制：后端 JWT + 白名单双源机制，前端登录弹窗体系与 401 统一拦截。读完能定位"谁在拦、怎么放行、未登录怎么办"的完整链路。

## 模块职责

**后端**（`LiuTech/`）：JWT 无状态认证 + 路径白名单。白名单定义在 `SecurityWhitelist.java` 单点，被 `SecurityConfig`（授权规则）与 `JwtAuthenticationFilter`（是否解析 token）**同源消费**——同一份列表，两处行为不会漂移。

**前端**（`Web/`）：登录入口统一为全局登录弹窗（不跳页），表单逻辑单点定义，HTTP 401 统一在 axios 拦截器处理。登录成功停留当前页，不打断阅读。

## 数据流概览

### 后端白名单判定（一次请求）

```
请求进入
  │
  ├─ JwtAuthenticationFilter: shouldSkipAuthentication(uri, method)？
  │     ├─ 命中公开路径（GET 前缀 / POST 精确 / FULLY_PUBLIC）→ 跳过，不解析 token
  │     ├─ 命中 AUTHENTICATED_PATHS → 必须解析（覆盖公开前缀的例外）
  │     └─ 其余 → 解析 token 注入 SecurityContext
  │
  └─ SecurityConfig 授权：白名单 permitAll / /admin/** hasRole('ADMIN') / 其余 authenticated
```

**关键顺序**：`AUTHENTICATED_PATHS` 在 `SecurityConfig` 中先于 GET 公开前缀配置（98-110 行），`shouldSkipAuthentication` 中也先判断它（116 行）——保证"公开前缀下的特例"两处都优先生效。

### 前端登录链路

```
触发点（任选其一）
  ├─ TheHeader「登录/注册」按钮 → authModalStore.show()
  ├─ 路由守卫 requiresAuth 未登录  → show(提示, to.fullPath) + next(false)
  ├─ api.ts 拦截器 401（会话失效）→ 清 token + show('登录状态已失效')
  ├─ 点赞/收藏/购买/下载未登录     → show(具体提示)
  └─ BottomNavigation 发布文章/我的文章 → show(具体提示)
        │
        ▼
LoginModal（全局唯一实例，MainLayout 挂载）
  ├─ useAuthForm 提交：密码登录 / 邮箱验证码登录 / 注册
  │    └─ 失败：字段级红字（校验）/ toast（业务错误，弹窗保持可重试）
  └─ 成功 → 关弹窗 + 清 redirect
        ├─ 有 redirect（守卫拦截）→ router.push 跳回目标页
        └─ 无 redirect → 停留当前页；PostDetail watch isLoggedIn 自动刷新点赞收藏状态
```

## 陷阱与约束

- **白名单单点定义，双处消费**：`SecurityConfig` 与 `JwtAuthenticationFilter` 共用 `SecurityWhitelist.shouldSkipAuthentication`，改白名单只改这一处；若两处各自判断会产生"授权放行但 JWT 不解析"或相反的不一致（曾踩：`/posts/view-history` 漏列 `AUTHENTICATED_PATHS`，被公开前缀放行后 controller 拿不到用户）
- **公开前缀下的需登录接口必须加 AUTHENTICATED_PATHS**：`/posts/` GET 前缀是公开的，新增 `/posts/` 下的登录接口（如 `/posts/my`、`/posts/favorites`、`/posts/view-history`）必须同步列入，否则 401
- **拦截器内不能顶层实例化 store**：`router/index.ts` / `api.ts` 在模块加载期执行，pinia 尚未安装；`useAuthModalStore()` 必须在守卫回调 / 拦截器回调内调用
- **401 排除 `/user/` 接口**：登录/注册/验证码接口的 401 属于业务失败（防御性），走业务提示而非"会话失效"弹窗（`api.ts:105-112`）
- **守卫拦截用 `next(false)` + 弹窗**：不跳登录页，登录成功后经 redirect 跳回被拦截页；`next(false)` 取消导航，当前页不丢失
- **弹窗关闭必须清理**：`resetForm()` 统一清理验证码倒计时 timer（防泄漏）与表单残留（防下次打开带旧输入）；组件卸载同样调用 `cleanupTimers`
- **跨服务约束**：`JWT_SECRET` 在 backend 与 ai 必须一致，否则 token 验证失败（见 CLAUDE.md）
