# 资源管理架构总览

> 资源（zip/pdf/音频等）的上传、购买鉴权下载、管理端维护与下载记录。读完本文能看懂一个资源从「上传」到「被积分用户下载」再到「被彻底删除」的完整链路，以及下载鉴权与积分扣减的安全设计。

## 模块职责

资源 = 可下载的文件或外部链接，分**免费**与**积分**（付费）两种下载类型。涉及：

- 上传：文件走存储层（本地磁盘/COS，与图片共用 `FileStorage` 抽象），外部链接直接存 URL
- 购买：积分资源先购买（扣积分）再下载，唯一索引防重复购买
- 下载：后端鉴权后经存储层流式返回（不直出 URL，防止绕过积分）
- 管理：管理端 CRUD、软删/恢复/物理删除、下载记录查询

前端位置：Web 端在文章详情页下载附件（[`Web/src/views/PostDetail.vue:281`](../../../../Web/src/views/PostDetail.vue) 的 `handleDownload`，优先直链、失败回退流式下载），Admin 端在资源管理页（[`Admin/src/views/admin/ResourcesManagement.vue`](../../../../Admin/src/views/admin/ResourcesManagement.vue)）。

## 数据流概览

```
上传（≤5MB 普通上传）
  FileUploadController /upload/resource
    → FileUploadService.uploadResource → saveResourceFile
      → 查重候选：同用户 + 同名 + 同一未绑定草稿任务 + 10 分钟窗口
      → 元信息相同且存储内容逐字节一致 → 复用资源/草稿关联（isDuplicate=true）
      → 无草稿任务 / 内容或元信息不同 → 新建独立资源
      → fileStorage.save（本地或 COS，路径 resources/...）
      → resources 表插入（downloadType/pointsNeeded）
      → （可选）post_attachments 草稿附件关联
      → DB 回滚：补偿删除本次新保存的文件

上传（>5MB 分片上传，规避 CDN 传输超时）
  前端切 5MB/片（post.ts uploadAttachment）
    → POST /upload/resource/chunk × N（降低每次请求体积，耗时依实际链路而定）
    → POST /upload/resource/merge
      → 校验片数/单片大小/总大小（默认 ≤100MB）→ 按序拼接
      → saveResourceFile（同一草稿任务内查重，与普通上传同路径）
      → 提交成功：清理分片；失败回滚：保留分片供再次 merge

购买（积分资源）
  ResourceDownloadController POST /resource/purchase/{id}
    → purchaseResource：先插 download_logs（唯一索引防重）
    → PointsService.deductPoints（原子扣减，SOURCE_RESOURCE_DOWNLOAD）
    → 任一失败事务回滚

下载
  ResourceDownloadController GET /resource/download/{id}
    → 鉴权：免费 / 已购买 / 上传者本人，否则拒绝
    → extractResourceRelativePath（统一走 FileUtil 口径 + resources/ 前缀 + 穿越校验）
    → fileStorage.open 读取 → 流式返回（不直出 URL）

直链下载（大文件/对象存储）
  ResourceDownloadController GET /resource/download-url/{id}
    → 同一套鉴权（资源存在 / 免费或已购买 / 路径安全）
    → fileStorage.generateDownloadUrl(relativePath, name, 10min)
        ├─ COS：返回预签名 URL（带 content-disposition: attachment）
        └─ 本地磁盘：返回 null → DownloadUrlResp(url=null) → 前端回退 /resource/download/{id}

管理端
  ResourcesAdminController /admin/resources/*
    → 列表 / 创建 / 更新 / 软删 / 恢复 / 物理删（删物理文件 + 下载记录 + DB 记录）/ 下载记录分页
```

## 陷阱与约束

- **大文件分片**：前端对 >5MB 文件按 5MB/片上传，以降低 CDN 链路中单次请求体积。历史超时与重复提交的排查见[CDN 案例](../../../教程/CDN上传事故排查.md)；案例中的秒数不是当前链路的延迟保证。
- **重试与独立上传**：查重仅限「同用户 + 同名 + 同一非空 `draftKey` 下未绑定文章的附件 + 10 分钟窗口」，还需下载类型、积分、说明与文件字节一致。同名不同内容、不同草稿、无草稿上下文都保存为独立资源，避免价格和删除动作影响其它文章。候选时间参数使用应用 `Date`，与 `created_at` 入库类型一致，不与数据库 `NOW()` 混用。
- **查重保留附件关联**：命中后通过 `selectByDraftKeyAndResourceId` 返回原关联；关联缺失时补建，避免只显示资源但保存文章时绑定不到附件。
- **前端 blob 下载要解包**：axios 响应拦截器会把非标准响应包成 `{code,message,data}` 对象，`new Blob([response.data])` 会得到 15 字节的 `[object Object]`——取 `response.data.data`。
- **COS 控制台手动删对象不同步数据库**：对象删了数据库记录还在，下载报 400「文件不存在」；恢复需把原文件补传到原对象 key（数据库存的就是该 key）。
- **URL 解析必须走 `FileUtil.extractRelativePath` 统一口径**：曾自实现只认 `/uploads/` 前缀，COS 直出 URL（`https://static.liuxin.chat/resources/...`）解析失败导致下载报「非法资源路径」——已收敛到 FileUtil（兼容相对路径/站内完整 URL/COS 直出），新写解析不要自己拼。
- **永久删除与清理**：`ResourcesAdminService` 先删除下载/附件关联与资源元数据，数据库提交后才经 [StorageFileCleanup](../../../../LiuTech/src/main/java/chat/liuxin/liutech/storage/StorageFileCleanup.java) 清理文件；回滚保留原文件。该回调在当前进程执行，异常退出可能留下孤儿文件，不能视作持久清理队列。
- **下载鉴权在服务端**：流式下载（`/resource/download/{id}`）文件经后端代理返回，不暴露本地磁盘路径；直链下载（`/resource/download-url/{id}`）在**同一套鉴权之后**才签发短期签名 URL（COS 模式，10 分钟有效），前端拿到 `url=null` 必须回退流式下载，不能当作错误
- **分片边界与清理**：`uploadId` 仅接受 1～64 位字母、数字、下划线、短横线；临时目录按用户隔离，不跟随目录或分片符号链接。普通上传和合并均有外层事务；分片只在提交成功后清理，新正式文件在 DB 回滚后做补偿删除。
- **共享资源删除保护**：`DELETE /upload/attachments/{resourceId}` 没有文章/附件关联上下文，存在多个有效引用时拒绝删除；只有单一引用或未引用资源可销毁，物理文件在数据库提交后删除。显式引用已有资源仍共享价格和资源状态。
- **路径安全**：`isInvalidRelativePath` 拦截绝对路径与 `..` 目录穿越（[`ResourceDownloadService.java:229`](../../../../LiuTech/src/main/java/chat/liuxin/liutech/service/ResourceDownloadService.java)），对本地磁盘与 COS 统一生效。
- **防重复购买**：`download_logs` 表 `uk_user_resource` 唯一索引 + `DuplicateKeyException` 捕获（[`Docs/SQL/sql.sql`](../../../SQL/sql.sql)）。
- **扣积分顺序**：先插购买记录、后扣积分，扣减失败靠事务回滚，避免"积分扣了但购买记录没插上"。
- **免费判定**：`isPaidResource` = `downloadType != FREE` **或** `pointsNeeded > 0`，两个条件任一成立都算付费，需购买后才能下载。
- **上传者免购买**：资源上传者本人下载不扣积分（`hasUserPurchased` 判断）。
- 积分流水与余额扣减由 PointsService 统一管理，资源模块只传 `SOURCE_RESOURCE_DOWNLOAD`（`resource_download`）来源标识。
