| 路径 | 职责 | 服务端口 |

## 业务与服务关系

```text
浏览器
  ├─ Web / Admin → Nginx → backend → liutech
  └─ Web / Admin → Nginx → ai      → liutech_ai
                                 ├─ backend：身份内省与公开业务资料
                                 └─ 模型 / TTS 供应商

backend：文章与评论事务 → 社区事件 → ai 后台执行 → backend 幂等发布
backend：用户永久删除 + 清理任务 → ai 永久清理会话与社区状态
```

## 分层与契约

主后端按 Controller → Service → Mapper 分层，用户业务失败交给统一异常处理。AI 服务保留现有 HTTP 响应和 SSE 事件契约；调用方按具体接口处理，不能假定所有成功响应都含 `data`。

两服务普通业务层使用构造器注入。主服务签发与解析 JWT，AI 经身份内省确认用户；内部令牌用于容器内通信。响应、错误码、缓存、认证和数据库写入规范统一见[跨服务规范](跨服务规范.md)，接口格式见[AI 接口参考](后端/AI服务/接口参考.md)。

Web 与 Admin 维持独立 Vite 根，网络层和四对镜像模块的边界统一见[网络封装](设计/网络封装/总览.md)。普通 JSON、上传、下载与 SSE 各自保留所需的传输协议。

## 数据与存储

主服务使用 `liutech`，AI 使用 `liutech_ai`，各自持有最小权限应用账户。新环境只维护一份[完整初始化 SQL](../SQL/sql.sql)，已有环境使用[版本迁移](../SQL/migrations/README.md)；应用启动检查结构，不执行 DDL。

图片与资源复用 `FileStorage`，支持本地磁盘与 COS。URL、相对路径、签名下载及引用清理的实际规则见[存储抽象](后端/图片管理/存储抽象.md)和[资源管理](后端/资源管理/总览.md)。TTS 配置、供应商调用与音频缓存属于 AI 服务。

主库永久删除与持久化清理任务同事务提交；任务调用 AI 永久清理入口，保留用户状态以阻止旧请求重建数据。用户主动清空记忆与永久删除使用不同语义，详见[数据库版本迁移](../SQL/migrations/README.md#清理任务)。
