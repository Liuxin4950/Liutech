# 数据库初始化与基础配置

> 新环境统一执行 [Docs/SQL/sql.sql](../../../SQL/sql.sql)。该文件同时包含两库的完整结构和可公开的基础数据；已有环境按[数据库版本迁移](../../../SQL/migrations/README.md)升级，不重放完整脚本。

## 结构与数据范围

当前完整快照包含主库 33 张表、AI 库 14 张表，结构覆盖主库 V4 / AI 库 V3；2026-10-18 更新初始化行为，未改变表结构。公开站点资料保留自 2026-10-06 云端 `53965f5` 的快照，不自动跟随线上后台更新。用户生命周期状态表保留结构；备份表与 Flyway 历史记录不进入新库。

| 数据 | 初始化行为 |
| --- | --- |
| 分类、标签、文章系列 | 保留公开基础目录，按名称去重，不沿用生产 ID；新库将历史拼写 `Fultter` 修正为 `Flutter`，不重命名已有业务目录 |
| 作者与关于页 | 云端公开的 `author.*`、`about.content`，已有值保留 |
| 欢迎公告 | 播种当前常驻公开公告，浏览数从零开始，同标题已存在则不重复插入 |
| 模型目录 | 仅模型表为空时播种：DeepSeek-V3.2 为唯一启用的默认模型，Qwen2.5-7B 初始停用；非空目录不新增、恢复或启用预置模型 |
| 语音配置 | SiliconFlow、CosyVoice2、MP3、44100 Hz；初始关闭，自定义音色 URI 与密钥按环境配置 |
| 社区互动 | `community_settings(id=1)` 全站默认关闭，接力开关 `bot_relay_enabled` 默认开启以保留升级前语义；`ai_community_worker(id=1)` 提供租约入口 |
| 账号、文章、评论、会话、任务、发布回执与记忆 | 不复制生产数据，不创建固定密码管理员，不预置虚构互动 |

初始化不预置轮播记录，Web 使用已有默认横幅。上传文件、音乐和账户专属音色不随 SQL 复制，不能只复制数据库路径而省略对应文件。脚本按表依赖顺序执行，不关闭调用方的外键检查。

## 默认模型的唯一来源

运行默认模型来自 `ai_model_config`；管理台「模型配置」调用 [AiModelConfigService.setDefaultModel](../../../../LiuTech-AI/src/main/java/chat/liuxin/ai/service/AiModelConfigService.java) 在事务中清除旧默认并设置新默认，随后失效缓存。聊天、写作和评论角色共用 [AiModelPolicy](../../../../LiuTech-AI/src/main/java/chat/liuxin/ai/infra/security/AiModelPolicy.java)。只修改 YAML 不会替换数据库中的默认选择。

新模型目录的初始化基准：`deepseek-ai/DeepSeek-V3.2`，上下文窗口 `164000`、输出上限 `32768`、温度 `0.4`。这是保留的站点配置基准，不是供应商当前可用性、价格或限额承诺；使用前核对实际账户。输入预算和实际消耗见 [模型预算与安全](../../后端/AI服务/模型预算与安全.md)。

模型表非空时整份模型目录保持原状，即使只保留自定义模型、管理员已删除预置模型，或当前没有默认模型，也不会补入并启用 DeepSeek。重复执行不会重置管理员的启用状态、默认模型、参数、作者资料、公告状态、互动开关或执行器租约。若已有目录没有默认模型，应在管理台明确选择，不能靠重放初始化强行修复。

## 新环境启动顺序

1. 按 [.env.example](../../../../.env.example) 配置两库密码、内部令牌、JWT 与模型 API Key；跨服务边界见 [跨服务规范](../../跨服务规范.md)。密钥不写入 SQL。
2. 空库执行唯一完整 SQL；Docker MySQL 的初始化目录仅在数据卷首次创建时执行。应用数据库账号由数据库管理员显式创建，分别只授予各自库的 CRUD；Compose 不再自动创建应用账号。
3. 启动主后端和 AI 服务。通过正常注册创建真实账户，再按[首次管理员步骤](部署操作.md#首次管理员)显式提权，不复制生产登录账号或密码哈希。
4. 在「模型配置」核对默认 DeepSeek-V3.2；通过 `/ai/runtime` 确认实际默认，不用付费生成测试来代替配置核验。
5. 如需语音，在「语音服务」填好本账户音色并启用。评论角色在「评论角色」配置与预演后开启，流程见 [社区 AI](../../后端/社区AI/总览.md)。

第2步的账号是 `liutech_app` 与 `liutech_ai_app`，密码分别匹配 `.env` 的 `DB_APP_PASSWORD` 与 `DB_AI_APP_PASSWORD`。SQL 文件不会读取或展开环境变量，也不写固定应用密码；初始化完成并不表示应用账号已经存在。账号创建后只授予对应库的 `SELECT/INSERT/UPDATE/DELETE`，不授予 DDL、跨库或全局权限。已有账号先核验，不用初始化过程重置密码。配置匹配与容器内数据库入口见[部署操作](部署操作.md#凭据与实际账号的匹配)。

## 已有环境与验证

已有环境先备份两库，按当前完整 SQL 核对结构差异，使用 独立 Flyway Maven 工程 升级主库至 V4、AI 库至 V3 并 validate。迁移版本与执行顺序以[数据库版本迁移](../../../SQL/migrations/README.md)为准。完整脚本的 `CREATE TABLE IF NOT EXISTS` 不会为旧表补列。初始化种子保留已存在的数据，不应作为在线配置同步器使用。

主库 V2、AI 库 V3 为旧环境补齐社区表、评论作者约束、执行任务与公共记忆；已部署评论区 AI 的环境只补缺失结构并登记台账，不重置角色和互动配置。主库 V3 补齐验证码查找索引，保留既有过期清理索引；V4 新增默认开启的接力开关，保留原有配置值。启动结构检查覆盖生命周期与社区关键字段，避免缺迁移时带病运行。

2026-10-18 在独立 MySQL 8.0.46 临时实例完成 Docker 首次自动初始化，创建47张表；显式创建两个独立CRUD账号后，现有主后端和AI容器以prod配置通过启动结构检查、健康检查以及默认数据读取。模型生成、语音和邮件供应商未实际调用。

[SqlInitializationMysqlTest](../../../../LiuTech/src/test/java/chat/liuxin/liutech/service/SqlInitializationMysqlTest.java) 执行整份脚本，包括两库切换与种子数据：检查中文与emoji、无虚构业务数据、唯一默认、语音和社区默认暂停；修改作者、关于页、公告、模型、语音、互动与租约后重放，确认数据不重复且定制值保留；非空自定义模型目录不被补入预置模型；调用方的外键检查设置保持不变。原有迁移测试继续对照冻结旧结构与当前快照，主库V4/AI库V3一致；两服务全部1036项测试通过，无失败或跳过。测试创建随机临时库，不重置开发库和生产库。
