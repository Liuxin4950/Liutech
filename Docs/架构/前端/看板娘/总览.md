# 看板娘前端架构总览

> AI 看板娘是 LiuTech 前端的核心交互功能，涉及聊天、TTS 语音、Live2d 模型、会话管理。
> 本文档为模块入口，读完能定位到具体细分文档。

## 模块职责

看板娘负责：用户与 AI 的多轮对话、流式回复渲染、TTS 语音播报与口型同步、Live2d 模型表情动作驱动、会话历史管理。管理员写作助手与看板娘聊天分开：写作结果只进入预览，采纳后修改编辑器草稿，契约见[后台管理](../后台管理/总览.md#写作助手)。前端在 `Web/`，后端 AI 服务在 `LiuTech-AI/`（聊天/SSE/TTS 合成）。

`MainLayout` 异步加载 `Live2d` 和 `AiChat`。聊天框的外部尺寸与定位由宿主 `.ai-box > .ai-chat` 管理，避免子组件后加载的 `.chat-box` 默认布局覆盖定位；聊天框内部样式仍归 `AiChat` 所有。

## 数据流概览

```
用户输入
  └─ AiChatInput ─> AiChat ─> chatStore.sendMessage
                                    ├─ 确认当前身份并恢复对应用户分桶
                                    ├─ 捕获身份代次，过滤旧响应
                                    │
                                    ▼
                        AiStream.streamChat (SSE POST)
                                    │
              ┌─────────────────────┼─────────────────────┐
              ▼                     ▼                     ▼
        onChunk(data)        onEvent              onComplete
        追加流式消息          事件分发              完成流式
                          ┌──────┴──────┐
                          ▼             ▼
                    avatar-cue       audio
                    入 Cue 队列      入 TTS 队列
                          │             │
                          ▼             ▼
              useTtsPlayer watch    useTtsPlayer watch
              avatarCuePendingCount  ttsPendingCount
                          │             │
                          ▼             ▼
              applyNextAvatarCues   playNextTts
              ─> Live2d 表情        ─> Live2d 口型
```

**显示状态**（showModel/showChat/isExpanded）集中在 chatStore，MainLayout 和 AiChat 直接读写，不再经 props/emit 中转。

## 陷阱与约束

- **流式 Markdown 渲染不要用 rAF 节流**：会"一顿一顿"，保持 computed 同步渲染。性能优化从减少单次解析耗时入手
- **Live2d 隐藏时必须停 ticker**：`visible` prop 控制，否则 PIXI 60fps 空转
- **引导第二步必须消费 Live2d 的真实加载状态**：不能用固定延时假定模型已经可交互
- **chatStore 包装 chatTts 是接口适配**，不是假拆分，不要删除
- **ttsCancelCounter 是合理的响应式桥接**，不要改成回调 hook
- **TTS 与音乐共用 lipSync 单实例**：TTS 优先，恢复音乐前校验用户操作版本

- 私有会话恢复必须经当前 token 的真实用户 ID 确认；不能用持久化 `userInfo` 或 token 是否存在直接选历史，见[Markdown与会话](Markdown与会话.md#身份与持久化)。
- 写作 `field-update` 只生成待采纳建议，不能作为即时覆盖编辑器的信号，见[后台写作助手](../后台管理/总览.md#写作助手)。
