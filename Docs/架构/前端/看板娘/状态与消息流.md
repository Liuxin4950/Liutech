# 状态与消息流

> chatStore 是看板娘的状态中枢，集中管理消息、会话、TTS 队列、显示状态。
> 本文档描述状态字段、显示状态提升、消息发送流程、SSE 事件分发。

## chatStore 状态字段

### 消息与会话

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `messages` | `ChatMessage[]` | 聊天消息列表 |
| `conversationId` | `number \| null` | 当前会话 ID（游客为 null） |
| `mode` | `'stream' \| 'normal'` | 回复模式：SSE 实时 / 一次性完整 |
| `isLoading` | `boolean` | 正在发送 |
| `isStreaming` | `boolean` | 正在接收流式响应 |
| `aiThinking` | `boolean` | AI 思考中（未开始输出） |
| `errorMessage` | `string` | 错误提示 |

### 显示状态（提升自 MainLayout）

| 字段 | 类型 | 说明 |
| --- | --- |
| `showModel` | `boolean` | Live2d 模型是否可见 |
| `showChat` | `boolean` | 聊天框是否打开 |
| `isExpanded` | `boolean` | 是否展开为大窗 |

这三个状态原是 MainLayout 局部 ref，现已提升到 chatStore，MainLayout 和 AiChat 直接读写，消除 props/emit/CustomEvent 中转。

### 首次引导与模型加载状态

首次引导不进入 chatStore，由 [`useOnboarding.ts`](../../../../Web/src/composables/useOnboarding.ts) 管理独立状态机，避免把一次性 UI 流程混入长期聊天状态：

```
welcome
  └─ 用户接受 -> spotlight             高亮右下角 AI 入口
                    └─ 点击入口 -> model-tip
                                      ├─ Live2d load-start/error/ready 更新提示
                                      └─ ready 后点击模型 -> chat-tip
                                                               └─ 指向聊天输入区 -> done
```

`MainLayout.live2dStatus` 取值为 `idle | loading | ready | error`，只桥接 `Live2d` 事件给 `OnboardingGuide`；模型未 `ready` 时不执行 `toggleChat()`。引导版本存于 `liutech_onboarding_version`，步骤存于 `liutech_onboarding_step`。

### TTS 状态

| 字段 | 类型 | 说明 |
| --- | --- |
| `ttsEnabled` | `boolean` | 用户想不想开语音 |
| `ttsAvailable` | `boolean` | 后端探测的语音可用性 |
| `ttsAwaitingAudio` | `boolean` | 等待首个音频事件 |
| `ttsCancelCounter` | `number` | 新消息发送时递增，通知播放器停止旧播放 |
| `ttsPendingCount` | `number` | TTS 音频队列待播数（computed） |
| `avatarCuePendingCount` | `number` | Avatar Cue 队列待消费数（computed） |

### 模型信息

| 字段 | 类型 | 说明 |
| --- | --- |
| `defaultModel` | `string` | 默认模型名 |
| `currentModelInfo` | `{ modelName, displayName }` | 当前模型 |
| `isModelLoading` | `boolean` | 运行时加载中 |

## 显示状态控制方法

| 方法 | 说明 |
| --- | --- |
| `toggleChat()` | 点击 Live2d 模型：展开态忽略，否则切换聊天框；关闭时重置展开+显示模型 |
| `expandChat()` | 切换展开/折叠大窗；展开时同步显示模型 |
| `closeChat()` | 关闭聊天框，重置为初始态 |
| `toggleModelVisibility()` | 展开/折叠模型显示（仅展开态有效） |
| `toggleModel()` | 底部导航入口，300ms 防抖 toggle 模型 |
| `openChatExternal(detail?)` | 外部唤起（如文章页"问 AI"），打开+展开，可选带入 prompt |

## 消息生命周期

```
addUserMessage(content)          用户消息入列
addAiMessage(content, id, opts)  AI 消息入列（isStreaming/isThinking）
updateStreamingMessage(chunk)    追加流式内容到 isStreaming 消息
completeStreamingMessage()       标记流式完成
updateAiMessage(id, content)     更新指定消息（normal 模式）
addErrorMessage(error)           错误消息入列
```

临时消息 ID 用负数（`generateTempId` 递减），避免与后端返回的正数 ID 冲突。

## sendMessage 流程

```
sendMessage(content, context)
  ├─ ensureUserRoleLoaded()           确保用户信息已加载
  ├─ buildGuestTempMessages()         游客取最近 10 条作上下文
  ├─ addUserMessage(content)          用户消息入列
  ├─ mode === 'stream'
  │   └─ sendStreamMessage(request)   SSE 流式
  └─ mode === 'normal'
      └─ sendNormalMessage(request)   一次性请求
```

### sendStreamMessage

1. `ttsCancelCounter++` 通知播放器停止旧播放
2. 清空 TTS/Cue 队列
3. 创建空 AI 消息（isStreaming=true, isThinking=true）
4. 调 `AiStream.streamChat`，注册 onChunk/onEvent/onComplete/onError
5. 事件分发见下节

### sendNormalMessage

1. 创建 AI 消息（isThinking=true）
2. `Ai.chat(request)` 一次性请求
3. `updateAiMessage` 填入回复内容
4. 失败时移除空消息并抛错

## SSE 事件分发

[`aiStream.ts`](../../../../Web/src/services/aiStream.ts) 解析 SSE envelope（`contractVersion=1`），按 event 类型分发：

| 事件 | payload | chatStore 处理 |
| --- | --- | --- |
| `start` | `{ conversationId }` | 首事件，立即更新 conversationId（避免后续请求用旧 id） |
| `data` | `{ content }` | `updateStreamingMessage(content)` 追加流式内容 |
| `avatar-cue` | `{ seq, expression, motion, ... }` | `aiThinking=false`，`enqueueAvatarCue` 入表情队列 |
| `audio` | `{ seq, audioUrl, text }` | TTS 启用时 `enqueueTtsAudio` 入音频队列 |
| `audio-skip` | `{ seq, text, reason }` | `enqueueTtsAudio`（status=skipped）入队列 |
| `audio-complete` | `{}` | `ttsAwaitingAudio=false` |
| `article-results` | `{ items, reason }` | 设置 `aiMessage.articleResults` |
| `complete` | `{ conversationId }` | `completeStreamingMessage`，清理状态 |
| `error` | `{ code, message }` | 移除流式消息，`addErrorMessage` |
| `heartbeat` | - | 保活，透传不处理 |

**重连**：流异常中断（非用户取消、非服务端 error、非正常 complete）时按指数退避（1s/2s/4s/8s，上限 30s）重连，最多 4 次。重连携带 `conversationId` + `lastSeq` 供后端去重/续传。

## 持久化

| 场景 | 存储 | 键 |
| --- | --- | --- |
| 登录用户消息 | `localStorage` | `liutech-chat-history` |
| 游客消息 | `sessionStorage` | `liutech-chat-history-guest` |
| 模式偏好 | 同上 | `liutech-chat-mode` / `-guest` |
| TTS 开关 | 同上 | `liutech-chat-tts-enabled` / `-guest` |

- `saveToStorage` 防抖 500ms，避免频繁写入
- watch messages 用浅签名（`id:length:streaming:thinking:articles`）而非 deep，流式时不深度遍历
- 加载时清除 `isStreaming/isThinking`，防止流式中刷新保存的脏状态污染下次流式

## 陷阱与约束

- **conversationId 竞态**：`start` 事件和 `complete` 都更新 conversationId，用 `!conversationId.value` 守卫，先到先得
- **游客无 conversationId**：`isGuestSession()` 判断，游客不持久化 conversationId，用 `tempMessages` 传上下文
- **ttsCancelCounter 不要改回调**：是合理的响应式桥接，chatStore 单向通知播放器
- **引导步骤按用户动作推进**：`model-tip` 等真实 `ready`，不以固定延时或自动关闭代替模型状态
