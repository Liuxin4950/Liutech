# 后台管理架构总览

> Admin 的表格分页、选择状态、删除/恢复和写作辅助。页面提供业务 API，组合式函数维护列表、操作状态与写作采纳边界。

## 模块职责

`Admin/src/views/admin/` 的管理页使用 `useTablePage` 管理列表，使用 `useCrudActions` 管理软删除、恢复、彻底删除和撤销。HTTP 响应与错误提示规则见[网络封装总览](../../设计/网络封装/总览.md)，整体分层见[当前架构](../../../记录/当前架构.md)。

## 数据流概览

```text
管理页面选择 ID
  → useCrudActions 检查 loading，复制并去重 ID
  → 调用删除 API
  → 清空选择，等待 onRefresh 完成
  → 软删除显示限时撤销按钮
       → 繁忙时保留按钮，点击不消费入口
       → 开始撤销后禁用重复提交
       → 有 batchRestoreFn：调用一次批量 API
       → 无 batchRestoreFn：Promise.allSettled 等待每条 restoreFn
       → 按真实完成/失败数量提示，部分成功也刷新
```

单条删除、恢复、彻底删除和批量操作共享同一个 `loading`。`onRefresh` 支持异步回调，刷新完成后释放操作锁。每个撤销按钮只接受一次操作，恢复使用删除时的 ID 快照，不读取随后变化的页面选择。

直接批量恢复全部成功后清空选择；单条恢复 fallback 部分失败时保留选择，由列表刷新同步当前行状态。撤销旧操作时不清空用户之后的新选择。

## 列表请求与选择

`useTablePage.load` 用请求代次控制数据回填，只有最后一次请求能更新列表、总数和 loading；过时失败不补弹通用错误。删除后当前页超出新的页数时，回到最后一个有效页重新加载。

搜索、重置和翻页清空旧结果集的选择。刷新同一结果集时只保留仍在当前页的 ID，避免批量操作包含已经隐藏或删除的记录。该后台不提供跨页累计选择。

## 写作助手

写作入口随请求发送完整 `draft` 快照和本组件临时对话历史。`requestedFields` 限定标题、摘要、正文、分类、标签或仅检查；`appendTags` 表示追加标签。工具结果与文章引用进入活动时间线，不能证明原稿已经修改。

```text
点击生成
  → useWritingReview.begin() 深拷贝请求前草稿
  → writingStream + 本轮 AbortSignal
      → data：显示生成内容
      → field-update：filterFieldUpdate 后 stage，聚合到 pending
      → error / 断流 / 取消：fail，预览不可采纳
      → complete：complete，标记完整成功
  → 用户检查预览，点击“应用本轮修改”
      → 当前草稿签名仍等于请求前快照
      → apply 只 emit 一次聚合字段和 original 快照
      → 父编辑器净化 HTML、更新草稿、记录整轮撤销
```

[`useWritingReview`](../../../../Web/src/services/writingReview.ts) 的采纳条件为 `succeeded && hasChanges && !applied && !conflict`。签名包含文章 ID、标题、摘要、正文、分类、标签、状态和图片字段。发送后继续编辑或切换文章会产生冲突；需要按当前原稿重新生成，不能用旧结果直接覆盖。HTML边界由同一镜像模块的 `sanitizeWritingPreview` / `sanitizeWritingHtml` 维护。预览隐藏全部图片和媒体，保留安全排版；链接只在明确点击后打开。采纳保留原稿已有图片地址与完整音视频/iframe/SVG/公式节点白名单，剔除脚本、事件、新外部资源和资源CSS，安全的字体、颜色、对齐、表格样式保留。若模型省略原稿媒体，预览明确提示数量，不猜位置自动重插。父编辑器复用净化入口，正常文章阅读不受该策略影响。

`null`/缺失字段不修改原值，明确的 `summary=""` 或 `tagIds=[]` 用于清空。追加标签模式对现有 ID 与新 ID 去重合并；预览明确展示清空操作。不存在的分类/标签是待确认创建建议，应用本轮结果不自动创建数据库记录。

父编辑器保存这轮请求前的完整草稿快照；“撤销本轮修改”恢复快照中的字段，原有逐字段撤销读取同一基线，不能被生成中的中间稿替换。当前仅保留最近一次采纳轮次的撤销，不是跨轮持久化版本库。

两个写作组件在“停止生成”和卸载时 abort。传输层的终态规则见[SSE 流式与心跳机制](../看板娘/SSE流式与心跳机制.md#成功断流与截断)，镜像约束见[网络封装](../../设计/网络封装/总览.md)。

每次管理端打开新建或编辑窗口都重建助手会话并清撤销/建议，禁止A文章的结果撤回到B文章。整轮撤销只恢复实际AI改动字段，保留随后手改封面、状态和未改字段；分类/标签撤销同步清理建议。

写作助手不提供保存或发布指令；“应用本轮修改”只更新前端草稿。实际保存/发布仍使用文章编辑器的业务按钮和主后端文章接口。写作暂存、长文原稿保护、冲突、明确清空与撤销回归见[writingReview.test.ts](../../../../Web/src/__tests__/writingReview.test.ts)，界面采纳/停止/卸载见[writingAssistant.test.ts](../../../../Web/src/__tests__/writingAssistant.test.ts)。

## 细分文档

当前模块规模较小，分页与操作状态在本总览维护，暂不拆分。

## 陷阱与约束

- `loading` 的入口检查负责防止重复写请求，页面可绑定该状态展示加载效果。
- 单条恢复 fallback 不能将 `.catch(() => null)` 当成成功；`Promise.allSettled` 的 fulfilled/rejected 数量分别用于恢复数与失败数。
- 现有批量 API 不返回逐项结果。成功提示不声称具体恢复/删除数量，不根据请求 ID 数量推断实际影响行数。
- 部分管理接口以 `code=200/data=false` 返回未完成的写操作。`useCrudActions` 在写操作边界将其视为失败；HTTP 客户端仍允许合法查询返回 `false`。
- 业务失败由 HTTP 拦截器提示，`isBusiness` 错误不重复显示通用失败原因；部分成功的提示只报告批量结果。
- 硬删除模式与 `undoWindowMs = 0` 不展示撤销按钮。
- Admin 的测试命令为 `cd Web && npm test -- --config ../Admin/vitest.config.mts`，先安装 Web 和 Admin 的已有依赖；测试配置不修改 Web 的默认测试范围。

- 收到 `field-update` 不能立即写表单；只在完整成功、原稿无冲突且用户明确采纳后写入。
