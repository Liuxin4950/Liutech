# 后台管理架构总览

> Admin 的表格分页、选择状态、删除/恢复和写作辅助。页面提供业务 API，组合式函数维护列表、操作状态与写作采纳边界。

## 模块职责

`Admin/src/views/admin/` 的管理页使用 `useTablePage` 管理列表，使用 `useCrudActions` 管理软删除、恢复、彻底删除和撤销，删除/恢复之外的领域批量动作（如用户批量启停）使用 `useBatchAction` 统一空选择提示、操作锁与刷新。HTTP 响应与错误提示规则见[网络封装总览](../../设计/网络封装/总览.md)，整体分层见[当前架构](../../总览.md)。

## 数据流概览

```text
管理页面选择 ID
  → useCrudActions 检查 loading，复制并去重 ID
  → 调用删除 API
  → 清空选择，等待 onRefresh 完成
  → 软删除显示限时撤销按钮
       → 繁忙时保留按钮，点击不消费入口
       → 开始撤销后禁用重复提交
       → 有 batchRestoreFn：调用一次批量 API
       → 无 batchRestoreFn：Promise.allSettled 等待每条 restoreFn
       → 按真实完成/失败数量提示，部分成功也刷新
```

单条删除、恢复、彻底删除和批量操作共享同一个 `loading`。`onRefresh` 支持异步回调，刷新完成后释放操作锁。每个撤销按钮只接受一次操作，恢复使用删除时的 ID 快照，不读取随后变化的页面选择。

直接批量恢复全部成功后清空选择；单条恢复 fallback 部分失败时保留选择，由列表刷新同步当前行状态。撤销旧操作时不清空用户之后的新选择。

## 列表请求与选择

`useTablePage.load` 用请求代次控制数据回填，只有最后一次请求能更新列表、总数和 loading；过时失败不补弹通用错误。删除后当前页超出新的页数时，回到最后一个有效页重新加载。

搜索、重置和翻页清空旧结果集的选择。刷新同一结果集时只保留仍在当前页的 ID，避免批量操作包含已经隐藏或删除的记录。该后台不提供跨页累计选择。

## 登录与首页

登录页在桌面分为品牌介绍与独立表单卡片，窄屏保留表单；登录验证和管理员权限仍由现有用户服务处理。首页按主要指标、次要统计、七日趋势/文章状态和文章/作者列表组织。排行榜使用相同的行间距、序号、摘要和右侧数值，不再用彩色技术栈标签作为运营信息。

统计来自 `DashboardService` 返回的数据；最近更新显示上次成功加载时间。首次加载失败展示重试，刷新失败保留旧数据并标出错误。文章/用户卡片的变化比较标注为近三天较前三天、不含今日；文章浏览分布不作为时间环比。没有趋势或文章数据时显示空状态。

## 评论与资源详情

评论列表显示父评论作者、内容和删除标记，点击详情打开同文章关系抽屉。抽屉完整加载数据后才呈现关系，当前评论有定位与高亮；点击任意节点显示完整正文和父评论正文。树可以折叠，每页显示 30 个已展开节点，深层缩进及路径适度压缩；全部节点仍保留在关系索引中。循环、缺失父节点和跨文章连接保留内容并标出异常。接口、快照和软删口径见[管理端评论关系](../../后端/文章生命周期/总览.md#管理端评论关系)。

资源列表显示关联文章摘要，详情按最新接口响应展示资源信息及完整关联文章清单。已发布、草稿和已删除文章分别标注；操作进入后台文章编辑或回收站，避免把隐藏文章链接到公开详情。关联查询口径见[资源管理](../../后端/资源管理/总览.md#管理端资源与文章引用)。

## 音乐素材与试听

音乐编辑使用 multipart `PUT /admin/music/{id}`，`fullAudio` 与 `vocalAudio` 均可选；不选文件保留原音轨。封面先经统一图片上传，再以 `coverUrl` 更新引用；上传未完成时不能提交，迟到的上传结果不能覆盖另一轮编辑。

列表可切换完整音频和人声音频试听。打开编辑、保存、关闭编辑、页面停用或卸载时停止相关音频；`KeepAlive` 停用也停止弹窗内的原生音频。状态或关键词筛选生效时禁用排序，重置筛选后才按完整歌单 ID 顺序提交。音轨含义、可听输出和存储补偿见[音乐播放与素材生命周期](../看板娘/总览.md#音乐播放与素材生命周期)。

轮播图排序与音乐使用同一「完整 ID 列表批量重写」协议（`PUT /admin/carousels/sort?ids=...`，后端按显示顺序重写 sort_order，DESC 语义下显示第 i 位写入 size-1-i）；筛选生效时同样禁用排序按钮。协议与后端约束见[跨服务规范](../../跨服务规范.md)管理端分页与排序接口约定。两个页面均一次加载完整列表（音乐后端本就返回全量数组；轮播管理页单页取 500 条并关闭每页大小切换），dataSource 必须保持全集，否则后端完整性校验会拒绝排序请求。

## 操作记录与汇总

操作记录列表和顶部总量/成功/失败/今日汇总使用同一组操作人、操作类型、目标、时间和结果筛选；汇总查询失败不使用当前分页条数冒充全量。日期与“今日”按 `Asia/Shanghai` 解释，显示优先使用 `createdAtEpochMs`。

操作人保留写入时名称和 `operatorId`，同时显示当前账号名称及管理员、普通用户、停用、已删除或身份未留存状态。已删除账号的旧名字不会被改写成当前管理员，历史漏记也不会自动补回。真实采集范围和故障边界见[统一操作审计](../../跨服务规范.md#31-统一操作审计)。

## 写作助手

Web/Admin 两个助手共用镜像 `writingSession.ts`，只注入页面草稿、流式封装和应用回调。统一协议、活动阶段和补丁规则见[写作事件与局部修改](../../后端/AI服务/写作事件与局部修改.md)。界面提供局部修改/整篇重写模式，已有正文默认局部；局部建议仅展示改动段落前后对照，整文建议展示全文预览。

```text
点击生成 → review.begin 保存完整原稿签名
  → started/activity/delta/proposal：真实进度、可见回复、暂存建议
  → failed/断流/取消/坏帧：不可采纳
  → completed：原稿仍一致时允许明确采纳
点击应用 → 父编辑器再次验证原稿及补丁 → 原子更新字段 → 记录本轮撤销
```

采纳条件为完整成功、存在修改、未应用且原稿无冲突。签名包含文章ID、标题、正文、摘要、分类、标签、状态和图片；生成中用户编辑、切换文章、停止或卸载都会隔离旧结果。局部补丁仅净化替换片段，未修改正文和媒体保持原字符串；预览隐藏媒体、链接需明确点击。完整文章仍使用原稿媒体白名单净化，缺失媒体显示数量，不猜位置重新插入。

缺失/null字段保持原值，`summary=""/tagIds=[]`明确清空；追加标签去重合并。新分类/标签是待确认建议，应用不自动创建。确认创建后两端展示实际读取列表、创建、刷新确认和结果；防重复请求，批量失败保留失败项，换文章/撤销/卸载使旧回调失效。分类创建成功只绑定有效ID，文章仍待保存。

历史最多7轮（14条），仅保存简短结论或修改摘要；工具-only成功也记录，避免持续对话超出请求上限。每次管理端打开新建/编辑窗口重建助手会话并清撤销及建议。整轮撤销只恢复本轮实际改动字段，保留其后手改的封面、状态和未改字段；撤销分类/标签字段不会删除已创建的分类/标签记录。

“应用本轮修改”只更新编辑器草稿。实际保存/发布仍使用业务按钮。回归包括[writingReview.test.ts](../../../../Web/src/__tests__/writingReview.test.ts)、[writingAssistant.test.ts](../../../../Web/src/__tests__/writingAssistant.test.ts)、[writingTaxonomy.test.ts](../../../../Web/src/__tests__/writingTaxonomy.test.ts)。

## 全量选项与列表排序

分类、标签等全量下拉及系列排序复用 [pagination.ts](../../../../Admin/src/services/pagination.ts) 的 `loadAllPages`，默认每页 200 条并逐页拼接；失败继续抛给调用方，不以已加载的部分数据伪装完整结果。纯响应类型统一放在 [types.ts](../../../../Admin/src/services/types.ts)，`api.ts` 保持兼容导出。

## 筛选与资料编辑布局

分类管理让名称输入与动作区合计占满 24 栅格：名称靠左，删除状态开关、搜索和重置靠右。积分流水与签到筛选将搜索/重置放在完整一行右端，导出、列设置和手动调整放入独立右对齐工具栏；按钮文字保持单行，窄屏表格使用横向滚动。布局变化不调整积分计算或筛选参数。

系列、标签、轮播图和留言使用可换行的 `filter-toolbar`：筛选字段靠左，`filter-actions` 通过自动左边距对齐容器右端，窄屏按整组换行。

语音页保留「引擎与音色」「已保存配置与试听」两区；检测时间来自现有 `checkedAt`，状态条取消日期元素继承的顶部间距，按相同垂直中心对齐，并允许窄屏换行。检测、保存与试听的状态边界见[语音服务](../../后端/AI服务/TTS与认证边界.md)。

关于页编辑器按作者资料、页面描述、个人介绍分组；头像预览、上传按钮和地址字段分开排列，上传期间禁止保存及重新加载。默认头像打包在 Admin 自己的资源目录，详细字段和发布边界见[关于页](../关于页/总览.md#管理端编辑)。

## 评论角色操作区

执行详情与预演结果提供“本轮加载的上下文”：按触发、直接前文、更早对话、附近讨论、文章、知识、公共记忆分组，显示实际节选正文、作者与回复关系、来源编号和字符范围；可展开完整消息并按原顺序复制输入。运行详情按需加载，切换记录或关闭窗口后丢弃迟到响应，失败可重试；同一记录的列表刷新只同步状态，保留已经读取的历史输入快照。旧记录未保存正文时明确提示，候选资料数量与实际加入输入分开显示；组装完成、模型请求开始和正式发表分开判断。存储与接口口径见[社区 AI](../../后端/社区AI/总览.md#知识记忆与可追踪性)。

参与规则使用独立的 AI 自动接力开关，兼容默认和关闭后的任务边界见[社区 AI](../../后端/社区AI/总览.md#触发限额与暂停)。执行详情展示模型决策或参与规则拦截的来源，沿用原有用量与任务状态。

页面标题为“AI 评论控制台”，既有页面内按运行概览、角色配置、资料与预演、任务与执行、实际对话、记忆及参与规则分区。运行概览集中展示统计，任务队列保留顶部快捷入口。角色配置、知识、预演、评论对话与记忆使用“操作角色”；运行概览、任务队列与执行记录使用独立的“查询角色”，切换查询不改变编辑对象。配置尚未读取成功时禁用写操作，不把初始化默认值当成已保存配置提交。

角色卡片的头像、描述及兴趣位于同一原生选择按钮内，键盘可选，并用 `aria-pressed` 表示当前选择；编辑、启停和右侧下一步操作同步到该角色，切换角色重置评论分页。长描述及兴趣限制显示行数；悬浮完整文本保留换行、允许长词折行，并限制宽度和可滚动高度，完整资料也可在编辑界面查看。参与积极度显示为 0–100 的候选权重，不表示发言概率。

运行概览可按所有角色或单角色查询，包含正式/预演用量、两阶段队列、任务状态与按角色汇总。模型决策、规则拦截和执行/发布失败分别展示；统计范围及供应商用量完整性以[社区 AI 管理端入口](../../后端/社区AI/总览.md#管理端入口)为准。任务筛选独立于角色编辑上下文，操作列固定在表格右侧。

队列合并主服务尚未接收的事件与 AI 服务任务，按 `eventId` 去重交接窗口；待处理及失败任务完整展示，当前文章直接用 `postId` 向服务端查询。当前任务状态优先采用有效执行器快照，避免刚取消的任务继续计入待处理。角色待处理总数包含该角色的待接收事件和 AI 任务，两类分别标出；执行器的全局队列与查询角色统计不混合。两服务分别读取，AI 暂时不可用时仍可查看和取消主服务的待接收事件，并明确提示查询不完整。页面可见时相关队列每 5 秒刷新，隐藏、停用或卸载时停止。

```text
运行概览的待处理 / 停止失败
  → 任务队列筛选 → 任务详情
  → 本任务已载入的执行记录 → 本轮结果与历史输入
  → 已发表回执 → 实际评论与对话
```

任务详情只列当前已经载入的关联执行，没有记录时明确说明查询范围不足，不推测历史生成内容。预演与历史预演始终标明不会发布；选择评论表示提供讨论线索，实际目标按执行决策展示，真人直接追问约束见[社区 AI](../../后端/社区AI/总览.md#触发限额与暂停)。取消、重试、邀请和补评各有提交中的入口保护；全站暂停时不重新排队需要生成或发表的失败任务，提示先核对参与规则；已发表任务以及 `postprocess/complete` 的纯恢复仍允许。暂停后的后台处理语义及发布仲裁规则见[社区 AI](../../后端/社区AI/总览.md)。

任务页顶部展示自动评论执行器的真实心跳、当前角色与文章、模型、执行阶段和耗时，可直接查看或取消当前任务。执行器状态独立每 5 秒刷新；阶段及倒计时按本次响应之后经过的时间每秒更新。服务器健康不代替调度心跳；状态读取失败或超过刷新窗口时保留上次事实并明确标注无法确认，不继续冒充正在执行。阶段无进展与模型截止由服务端报告，不自动创建重复任务或释放租约。

待接收事件用紧凑分页表格显示，任务表优先展示角色、文章、进度、等待原因和操作；累计生成尝试与本次模型调用轮数在详情区分，字段口径见[社区 AI 协议与状态](../../后端/社区AI/总览.md#协议与状态)。计划时间使用数据库返回的 `availableAtEpochMs`，剩余时间使用 SQL 计算的 `dueSeconds/leaseRemainingSeconds`，避免 Java、数据库及浏览器时区互相猜测。开关等条件结束的 `SKIPPED` 标为“已结束，未发表”，不把未执行模型的任务误称为模型沉默。

评论列表及对话详情提供撤回操作，确认框明确说明同时隐藏回复（包含真人回复）。撤回后重新查询实际评论状态，历史运行与模型用量保留。文章开关按钮根据已读取状态禁用重复设置，开启文章互动本身不创建邀请。

后台正文、导航和 Ant Design 组件统一跟随 `--lt-font-family` 系统字体栈，表单控件继承字体，代码区域保留等宽 token。

后台壳层在宽度不超过 767px 时使用独立抽屉导航，切换页面或关闭抽屉后释放全部内容宽度；手机开关不覆盖桌面侧栏折叠偏好。

## 细分文档

当前模块规模较小，分页与操作状态在本总览维护，暂不拆分。

## 陷阱与约束

- `loading` 的入口检查负责防止重复写请求，页面可绑定该状态展示加载效果。
- 单条恢复 fallback 不能将 `.catch(() => null)` 当成成功；`Promise.allSettled` 的 fulfilled/rejected 数量分别用于恢复数与失败数。
- 现有批量 API 不返回逐项结果。成功提示不声称具体恢复/删除数量，不根据请求 ID 数量推断实际影响行数。
- 部分管理接口以 `code=200/data=false` 返回未完成的写操作。`useCrudActions` 在写操作边界将其视为失败；HTTP 客户端仍允许合法查询返回 `false`。
- 业务失败由 HTTP 拦截器提示，`isBusiness` 错误不重复显示通用失败原因；部分成功的提示只报告批量结果。
- 硬删除模式与 `undoWindowMs = 0` 不展示撤销按钮。
- Admin 的测试命令为 `cd Web && npm test -- --config ../Admin/vitest.config.mts`，先安装 Web 和 Admin 的已有依赖；测试配置不修改 Web 的默认测试范围。

- 收到 `proposal` 不能立即写表单；只在完整成功、原稿无冲突且用户明确采纳后写入。
